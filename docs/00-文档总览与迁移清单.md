## 3. 迁移文档中需要注意的上下文差异

迁移文档成文于 mydatama 数据中台语境，在 mydbd 中按下述口径理解：

1. **模块定位升级**：TRAJ 在 mydatama 中是"第 7 个演示增强模块"；在 mydbd 中是**核心主业务域**，并扩展实时监控与基于驾驶员视频的风险分析（research/03 是业务蓝图）。
2. **职责边界打开**：MOD-TRAJ-001 §1.1 标注"不负责真实协议解析/实时流/视频流"，这是 mydatama MVP 约束；mydbd 规划迭代接入 **JT/T 808-2019**（定位/事件）与 **JT/T 1078-2016**（视频），见 SYS-DBD-001 路线图。
3. **数据库 schema**：mydbd 使用独立的 PostgreSQL 实例，schema 为 `traj`（轨迹域）与 `mon`（监控分析域），物理表结构与迁移 DDL 完全一致。
4. **文档内对 IAM/GOV/SCR 模块的引用**：mydbd 当前骨架用内置演示账号登录，权限/资产/大屏为后续迭代，引用处仅作背景理解。

## 4. 版本与文档管理规则

- 语义化版本：MAJOR.MINOR.PATCH；代码版本见根目录 [VERSION](../VERSION)，与 git tag 一致。
- 文档随代码变更同步更新；每份设计文档保留"修订记录"。
- 新增设计文档编号规则：`SYS-DBD-NNN`（系统级）、`MOD-DBD-NNN`（模块级）、`API-DBD-NNN`（接口级）、`UC-DBD-NNN`（用例级）、`DDL-DBD-NNN`（数据库级）。
