车辆详情聚合面板（F16）

功能编号 F16 · 实时监控域 · 第一波 · 关联文档 MOD-MON-003（模块技术设计） · 状态：已上线

1. 背景与目标

调度坐席在实时监控地图上看车时，经常需要"盯某一辆车看仔细"：这辆车是谁的、装了什么终端、今天跑过哪些路线、最近有没有报警。过去这些信息分散在主数据档案页、轨迹查询页、报警列表页三个地方，来回切换、反复输车牌，效率很低。

F16 把它收拢成一屏：在地图上点一下车辆图标，右侧滑出详情抽屉，车辆档案、终端与司机、实时位置、当日轨迹缩略图、最新报警和今日计数一次呈现，并提供跳转到档案/报警/回放页面的入口。

一句话定位：F16 是"围绕一辆车的只读信息聚合视图"，不做任何编辑和处置——编辑回 MDM 档案页，处置去 F17 报警中心。

就地查看，或点链接去对应页面
→
关闭
地图恢复全览，继续观察态势
  • 面板是共享组件：实时监控页（F16 本次接入）与 F15 监控大屏点选车辆时弹出的是同一个面板，体验一致。
  • 面板宽度桌面 560px；窄屏（如小窗口、平板竖屏）自动变为全屏抽屉，保证内容始终完整可见。
  • 再次点击其他车辆，面板内容直接切换；重复点击同一辆车不会重复加载。
  • 底部提供「刷新」按钮：面板停留期间报警计数不自动累加（避免与报警弹窗重复打扰），想看最新数字点一下刷新即可。

3. 面板里有什么

区块内容说明
头部车牌 + 号牌颜色 + 在线状态 + 实时位置卡（速度/方向/定位时间）位置卡随实时推送每秒刷新
车辆档案车型、品牌、VIN、运营类型、所属组织、车主、联系电话、道路运输证号、备注只读；右上"前往车辆档案"可跳转编辑
终端与司机当前绑定终端（识别码/型号/SIM/协议/视频通道数）；主班 + 副班司机（姓名/性别/电话/准驾车型）只展示"当前有效"的绑定
当日轨迹小地图上的当日轨迹线（起点绿、终点红、当前位置蓝点）+ 里程点数统计当日最多抽稀展示 500 个点，原始点数如实标注
最新报警最近 5 条终端报警（类型/时间/处理状态）+ 今日报警数、今日风险事件数两张计数卡"查看全部报警"跳转 F17 报警中心并按车牌过滤
底部操作「轨迹回放」跳转回放页；「视频调阅」本期为占位按钮视频调阅点击提示"建设中，将随 F25（第三波）上线"

无终端绑定的车辆：档案照常显示，位置与轨迹区显示"未绑定终端，暂无定位数据"占位，不报错。

4. 实时位置刷新

  • 面板打开时先显示服务端快照位置；此后只要实时推送通道存活，位置卡每秒跟随最新定位刷新（速度、方向、定位时间、小地图蓝点同步移动）。
  • 推送断线时自动降级为 5 秒轮询，刷新频率变慢但不中断；网络恢复后自动回到每秒。
  • "在线"判定口径与大屏一致：最近一次定位在 5 分钟以内。

5. 数据口径与边界

  • 当日 = 服务器本地自然日 00:00 至当前时刻；轨迹与报警/风险计数都按这个窗口。
  • 轨迹与最新位置按终端识别码查定位表；报警按车牌查终端报警表；风险计数按车牌查当日风险事件。
  • 一次点选只发一个聚合请求即返回全部区块（数据量小、无多次加载闪烁），点选到出图目标 300 毫秒内。
  • 面板为纯只读：不修改任何档案、不确认/解除报警、不发起视频请求。

6. 角色与权限

角色能否查看某辆车的面板
系统管理员✔ 全部车辆
安全管理员 / 调度坐席 / 车队队长✔ 数据范围内的车辆（与实时监控页可见车辆一致）
无 monitor:view 权限的账号✘ 看不到实时监控页，也就没有面板入口

数据范围沿用平台"部门数据范围"规则：车辆属于哪个组织，就只对管理该组织的账号可见。点选越权车辆时前端直接提示"无权查看该车辆或车辆未建档"；即便绕过界面直接调接口，服务端同样拒绝（403）。

7. 与其他功能的关系

  • F14 实时推送：面板位置刷新复用其全量点位消息，零改动、不新增订阅。
  • F15 监控大屏：同一面板组件，大屏侧接入属其自身范围。
  • F17 报警中心："查看全部报警"跳转其页面并自动按车牌过滤；面板内嵌的最近 5 条与 F17 列表字段口径一致。
  • F11 轨迹回放："轨迹回放"按钮携带终端识别码跳转回放页。
  • MDM 主数据："前往车辆档案"跳转档案页并带入车牌关键词；面板只读，编辑仍在档案页完成。
  • F25 视频调阅（第三波）：本期仅保留入口按钮，届时接入实时视频与审批流。

8. 边界与后续演进

  • 本期不做：视频实时调阅（占位）、单车定向推送订阅、面板内报警处置、轨迹完整交互回放、历史多日轨迹对比。
  • 演进方向：F25 上线后"视频调阅"按钮变为真实入口（有视频通道的终端可用）；如坐席反馈需要面板内快速确认报警，再评审与 F17 处置契约的复用方式。
