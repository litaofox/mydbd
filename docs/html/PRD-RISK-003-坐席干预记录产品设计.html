坐席干预记录（F21）

文档编号：PRD-RISK-003　|　所属功能：F21（第一波）　|　版本：v1.0　|　日期：2026-10-02　|　状态：已上线

上游依赖：F20 处置工单流转（工单状态机与闭环结果）　|　下游：F23 风险趋势与画像（干预统计维度）

1. 背景与目标

F20 上线后，风险事件可流转为工单并闭环，闭环时选择处置结果（电话提醒/教育/处罚等）。但闭环结果只记录最终一次动作，坐席在处置过程中对司机执行的多次干预（先电话未接、再电话接通口头教育、最后通知停运）没有留痕，导致：

  • 无法回答"这个工单坐席到底做了什么"，复盘困难；
  • 无法统计"感知—预警—干预—闭环"全链路转化，安全运营效果不可量化；
  • 同一司机被多次干预但无累计视图，无法识别屡教不改对象。

目标：建立干预动作留痕机制，支持按工单/事件记录每次干预的动作类型、结果与备注，并产出"感知→预警→干预→闭环"漏斗与闭环率指标。

2. 干预动作模型

每次干预为一条独立记录，核心字段：

字段说明
order_id关联工单（必填，干预从工单详情发起）
event_id / plate_no / identity_code冗余事件与车辆/终端标识，便于独立统计
action_type动作类型：PHONE_REMIND 电话提醒 / EDUCATION 安全教育 / STOP 停运通知 / PENALTY 处罚 / OTHER 其他
action_result动作结果：SUCCESS 成功 / FAILED 失败 / NO_ANSWER 未接通 / PENDING 待跟进
operator_id / operator_name操作坐席
remark干预说明（如教育内容、电话沟通要点），≤500 字
create_date干预时间

2.1 动作类型与工单闭环结果的关系

F20 工单闭环结果（close_result）是最终定性，干预记录是过程明细。一个工单可有 0~N 条干预记录；闭环时若选择了 close_result，系统自动补记一条对应动作类型的干预记录（action_result=SUCCESS），避免坐席重复录入。

close_result自动生成的 action_type
PHONE_REMIND 电话提醒PHONE_REMIND
EDUCATION 安全教育EDUCATION
REPORT_PENALTY 通报处罚PENALTY
TRAFFIC_VIOLATION 交通违法PENALTY
FALSE_ALARM 误报不生成干预记录

3. 与工单/事件的关系

  • 工单为主：干预记录挂在工单下（order_id 必填），继承工单的 event_id/plate_no/identity_code。
  • 事件视图：可按 event_id 反查该事件所有干预记录（一事件一单，故等价于工单干预记录）。
  • 删除：干预记录不支持物理删除（审计留痕），只能追加；工单逻辑删（valid_mark=0）时干预记录保留。

4. 感知—预警—干预—闭环 漏斗

按时间范围（默认今日）统计安全运营全链路转化：

E
感知：风险事件数
→
O
预警：生成工单数
→
I
干预：有干预的工单数
→
C
闭环：已闭环工单数
  • 干预率 = 有干预的工单数 / 工单数（I/O）
  • 闭环率 = 已闭环工单数 / 工单数（C/O）
  • 干预成功率 = action_result=SUCCESS 的干预数 / 干预总数

统计口径：均按 create_date 落在时间范围内统计；"有干预的工单"指该工单存在至少 1 条 intervention 记录。

5. 页面与交互

5.1 工单详情抽屉（OrderDetailDrawer）增强

在原有"流转时间线"下方新增干预记录区块：

  • 列表：时间、动作类型（标签）、结果（成功/失败/未接）、坐席、备注；
  • 新增按钮（risk:order:handle）：弹窗选动作类型、结果、备注，保存后即时刷新；
  • 闭环工单自动补记的干预记录标记 系统。

5.2 风险预警分析页（RiskEvents）统计增强

在页面顶部统计条新增"今日漏斗"卡片：事件 / 工单 / 干预 / 闭环 四项数字 + 干预率、闭环率百分比。

5.3 （可选）独立干预记录列表

本期不做独立菜单页；干预记录通过工单详情维护，统计通过风险页查看。

6. 权限与审计

  • 新增干预记录需 risk:order:handle（与工单处置同权限）；
  • 查看干预记录需 risk:order:view；
  • 新增干预操作写入审计日志（@AuditLog action=HANDLE, objectType=INTERVENTION）。

7. 验收标准

  1. 工单详情可新增干预记录，列表正确显示动作类型、结果、坐席、时间。
  2. 工单闭环（非误报）时自动生成一条对应类型的干预记录，标记系统来源。
  3. 风险页漏斗统计：事件数、工单数、干预工单数、闭环数与数据库一致；干预率、闭环率计算正确。
  4. 干预记录不可删除，仅可追加。
  5. 无 risk:order:handle 权限的用户看不到"新增干预"按钮。
