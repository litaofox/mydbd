终端报警中心（F17）

功能编号 F17 · 实时监控域 · 第一波 · 关联文档 MOD-MON-004（模块技术设计）

1. 背景与目标

车载终端（JT/T 808 设备）在运行中会直接上报硬件级报警：超速、疲劳驾驶、围栏越界、紧急求助、设备故障。过去这些报警在平台里只是一个只读的空列表——能看到，但不能筛选、不能处置、没有闭环。

F17 把它升级为报警中心：独立页面集中展示全部终端报警，支持按车牌、类型、状态、时间筛选；新报警通过实时推送秒级到达；坐席可以"确认 → 解除"完成处置闭环，每一步都留有审计痕迹。

一句话定位：F17 管"终端硬件报上来的事实"，F18~F21 管"平台研判出来的风险"，两条线各自闭环、互不混淆。

2. 报警从哪来：数据口径

报警数据落在既有的 traj.traj_warn_info 表（不新建表）。报警类型以平台字典表 base_warn_type 为唯一权威：

类型等级典型场景
超速报警红（高）终端判定车速持续超过设定阈值
疲劳驾驶红（高）连续驾驶超时、终端疲劳提醒触发
围栏越界橙（中）车辆驶入/驶出设定电子围栏
紧急求助红（高）司机按下终端紧急按钮
设备故障灰（低）GNSS/终端硬件异常

现状提示：当前演示环境终端尚未接入，表内数据由模拟/SQL 构造产生。列表为空属预期，不是缺陷；接入波次启动后由终端实时上报。

3. 报警中心页面

入口：菜单"实时监控 → 终端报警中心"（路由 /alarms）。页面自上而下分四块：

  • 统计条：窗口期内总数、待处理、已确认、已解除四个数字，30 秒自动刷新，新报警推送到达时即时累加。
  • 筛选栏：车牌模糊输入、报警类型下拉、处置状态、时间范围（默认今日）。
  • 报警表格：车牌、类型（按等级红/橙/灰着色）、报警起止时间、速度、持续标志、状态标签、处置人、更新时间、操作列。按报警开始时间倒序，分页浏览。
  • 详情抽屉：点击"详情"滑出，展示完整字段、起止坐标小地图（起终点连线）、处置信息，以及关联风险——同车牌报警前后 30 分钟内平台研判出的风险事件，方便坐席交叉印证，并可一键跳转风险预警页人工研判。

4. 处置闭环

待处理
终端上报默认状态
→
已确认
坐席知晓并跟进中
→
已解除
登记结论，闭环
  • 确认：一键操作，记录处置人与时间，表示"已看到、正在处理"。
  • 解除：必须选择结论——属实 / 误报 / 未知，可附不超过 200 字的说明（如"已电话提醒司机降速"）。
  • 明显误报或已自愈的报警允许跳过确认直接解除。
  • 解除是终态，不可重开：报警是硬件上报的事实记录，处置错了通过审计日志追溯纠正，不做状态回退。
  • 两名坐席同时操作同一条报警时，只有一人成功，另一人会收到"状态已变更，请刷新后重试"的提示——不会出现覆盖打架。

每次确认/解除都会写入操作审计（模块 MONITOR、动作 HANDLE、对象 ALARM），安全主管可在审计页完整回放。

5. 实时推送与统计

  • 复用 F14 实时推送通道：新报警产生后约 1 秒内，打开着报警中心的坐席会收到提示（车牌 + 类型），列表首行自动插入新报警，无需手动刷新。
  • 统计口径按"报警开始时间"落在所选窗口内计算；对外提供 page / latest / stats 三个只读契约，供 F15 监控大屏的"报警态势卡"和 F16 坐席面板直接消费。
  • 处置状态的变化本期不做全站推送，其他坐席靠 30 秒统计刷新与筛选感知。

队长角色进入页面只能看列表与详情，处置按钮自动隐藏；即便直接调用接口也会被服务端拒绝（双层校验）。

7. 与其他功能的关系

  • F14 实时推送：报警增量复用其 ALARM 消息，零改动。
  • F15 大屏 / F16 面板：只读消费本模块统计与最新报警契约。
  • F18~F21 风险闭环：两套体系互不转换——终端报警不会自动变成风险工单，风险工单也不改写报警状态；仅在详情页做"同车牌 ±30 分钟"的只读关联展示。
  • F34 审计：处置动作全量留痕。
  • F35 字典：新增"报警处置状态"字典项，供全局统一文案。

8. 边界与后续演进

  • 本期不做：列表导出、报警转工单、处置状态全站秒级推送、JT/T 808 原始 32 位报警标志位解析（终端侧已解析为离散类型）。
  • 演进方向：终端接入波次补齐真实数据源；如需状态秒级同步，扩展推送协议后再实施；如业务要求"报警升级工单"，届时单独评审资源与契约。
