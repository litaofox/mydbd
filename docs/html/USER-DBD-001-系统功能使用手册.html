系统功能使用手册

文档编号：USER-DBD-001 ｜ 版本：v1.0 ｜ 日期：2026-10-03 ｜ 适用：第一波 18 项功能（F14~F23、F28~F35）已全部上线

读者：调度坐席、安全管理员、车队队长、系统管理员等业务用户。技术细节请查阅各功能的 PRD（产品设计）与 MOD（模块设计）文档。

1. 平台总览与快速上手

本平台面向"两客一危"等营运车辆的北斗监控与安全风险处置：车辆通过北斗终端上报位置与报警，平台实时展示、自动识别风险、驱动"预警 → 工单 → 干预 → 闭环"的处置流程，并沉淀驾驶评分与风险画像供管理决策。

主数据管理（车辆/终端/司机/组织）

1.1 登录与账号

  • 打开系统地址后进入登录页，输入用户名与密码登录；登录状态失效后会自动回到登录页，重新登录即可继续。
  • 演示环境内置四类角色：超级管理员（全部功能）、安全管理员（系统管理+规则配置）、调度监控员（监控与处置，限本部门数据）、企业车队长（本企业档案维护与监控）。
  • 新账号由超级管理员在"系统管理 → 用户管理"中创建并分配角色。

1.2 界面结构

  • 左侧边栏：功能菜单按"实时监控 / 主数据管理 / 系统管理"分组，只显示你有权访问的菜单。
  • 顶栏：当前页面标题、消息铃铛（未读数）、推送通道状态、退出登录。
  • 监控总览大屏是独立全屏页面，不带侧边栏，适合投墙值守。

建议的上手顺序：先在"主数据管理"把组织架构、车辆、终端、驾驶员录齐并绑定，再看监控与处置——数据归属、通知对象、评分统计都依赖这些基础档案。

2. 实时监控域

回答"此刻车队在发生什么"：车辆位置、报警动态、整体态势一屏掌握。

F14 实时消息推送已上线 · 无需操作

功能概述

平台与浏览器之间保持一条实时通道：车辆位置每秒刷新，新报警、新风险事件即时弹出提示，无需手动刷新页面。

核心价值

从"5 秒刷一次"变成"秒级感知"，值守人员第一时间看到异常，缩短响应时间。

操作流程

全自动，无需任何操作。打开"实时导航监控""终端报警中心""监控总览大屏"等页面即自动建立连接；顶栏显示当前通道状态。

注意事项

  • 网络波动时通道会自动重连；重连期间页面降级为 5 秒轮询，顶栏标签变为"降级轮询"，数据仍持续更新，恢复后自动切回。
  • 演示环境下所有在线用户收到同一份推送；数据可见范围仍按各人权限在页面层控制。

F15 监控总览大屏已上线

功能概述

一块 1920/4K 自适应的全屏驾驶舱：中央是实时车辆地图与近 24 小时风险热力，四周环绕在线率、今日里程、报警态势、最新报警滚动、工单积压、车队/区域分布等统计分区。

核心价值

挂在值守室墙上的"总仪表盘"——不翻页、不筛选，抬眼即知全网状态；报警突增、工单积压一眼可见。

操作流程

侧边栏 实时监控 → 监控总览大屏
→
看态势
位置每秒刷新，统计每 30 秒校正
→
查单车
点地图车辆图标弹详情
→
退出
右上"退出大屏"返回监控页

注意事项

  • 大屏是纯展示页面：处置操作（确认报警、建工单等）请回到对应业务页面完成。
  • "在线"口径为最近 5 分钟内有过定位的车辆，可在"系统管理 → 系统参数"中调整窗口。
  • 今日里程为里程表差值近似口径，逐点精确里程待后续版本升级。

F16 车辆详情聚合面板已上线

功能概述

在地图上点击任意车辆，右侧滑出详情抽屉：车辆档案、当前终端与驾驶员、当日轨迹缩略、最新报警，一屏聚合。

核心价值

回答"这辆车现在怎么样、谁在开、今天跑了哪"不用在多个页面之间来回切换。

操作流程

实时监控页或大屏上点车辆图标 → 查看抽屉各区块 → 点"轨迹回放""报警中心"等链接跳转到对应页面深入处理。

注意事项

  • 抽屉只读展示，编辑档案请到"主数据管理"对应页面。
  • 显示"未绑定"说明该车还没关联终端或驾驶员，请先完成绑定关系维护（见 F31）。
  • 无权查看的车辆会被拒绝访问。

F17 终端报警中心已上线

功能概述

终端上报报警（超速、疲劳、SOS 等）的集中处理页：新报警实时置顶滚动，支持按车牌/类型/等级/状态筛选，每条报警可查看详情并完成"确认 → 解除"处置闭环。

核心价值

报警不再"只看不处理"：每条报警都有明确状态（未处理/已确认/已解除）与处置留痕，杜绝漏处置。

操作流程

发现
列表置顶或弹窗提示新报警
→
核实
点开详情看类型、等级、位置
→
确认
认领报警，状态变为处理中
→
解除
处置完成后填写结论解除

注意事项

  • 报警类型自动翻译成中文名称与等级，无需记忆编码。
  • 两人同时处理同一条报警时，后提交者会收到"状态已变化"提示，刷新后按最新状态操作即可。
  • 确认与解除操作均写入审计日志。

3. 风控闭环域

回答"风险如何变成可管理的事"：规则识别 → 分级通知 → 工单处置 → 干预留痕 → 评分画像。

F18 风控规则引擎已上线

功能概述

平台按可配置的规则实时分析终端报警与轨迹数据，自动产出分级风险事件。内置 8 条常用规则（超速、疲劳驾驶、夜间行驶等），并支持电子围栏：车辆进出围栏自动生成事件。

核心价值

把海量原始数据变成"值得处理的风险"，规则可调、等级可控，减少人工盯屏。

操作流程

规则维护：侧边栏 系统管理 → 风控规则（查看/启停/编辑阈值）；围栏维护：系统管理 → 电子围栏（地图上绘制区域）；事件查看：实时监控 → 风险预警分析。

注意事项

  • 规则修改即时生效，影响之后新产生的事件，不追溯历史。
  • 围栏进出判定依赖车辆定位上报节奏，位置稀疏时判定会延后。
  • 演示环境数据来自模拟器与样例导入，规则命中量与真实车队规模会有差异。

F19 报警分级与多渠道通知已上线（站内）

功能概述

按风险等级把通知送到对的人：高风险事件即时弹窗+站内消息，处置进展定向推送给工单负责人。短信、语音、App 推送渠道已预留接口，接入后可一键启用。

核心价值

重要风险不淹没在列表里——该知道的人在事件发生当下就知道。

操作流程

接收：留意页面弹窗与顶栏铃铛；查阅：侧边栏 系统管理 → 消息中心（全部历史通知，已读/未读）。

注意事项

  • 当前版本通知渠道为站内消息+实时弹窗；外部渠道（短信/语音）需配置对接后启用。
  • 通知按角色与工单分派对象定向发送，未读消息在铃铛上有角标提醒。

F20 处置工单流转已上线

功能概述

每个风险事件自动生成一张处置工单，按"待处理 → 处理中 → 已闭环"状态机流转，支持分派处置人、处置时限（SLA）与超时提醒。

核心价值

风险处置责任到人、进度可视、结果可查——积压了多少、超期了没有，管理者一目了然。

操作流程

建单
风险事件产生时自动建单
→
分派
指定处置人与时限
→
处置
处理中可追加干预记录
→
闭环
填写结论（已处置/误报等）关单

注意事项

  • 入口：实时监控 → 处置工单；也可从风险事件页的"处置"按钮直达。
  • 闭环结论选"误报"的工单，其事件不计入驾驶评分，避免误伤司机。
  • 超过时限未闭环的工单会被标记逾期，可在列表筛选跟进。

F21 坐席干预记录已上线

功能概述

在工单下追加干预动作留痕：电话提醒、安全教育、停运整改等。工单闭环时系统自动补记一条干预，保证"感知 → 预警 → 干预 → 闭环"漏斗不断链。

核心价值

处置过程可复盘、可统计：干预率、闭环率成为衡量风控运营质量的硬指标。

操作流程

处置工单 → 打开工单详情 → "干预记录"页签 → 添加干预（选择方式、填写说明）。

注意事项

  • 干预记录只可追加、不可修改删除，确保留痕可信。
  • 干预统计维度会汇入 F23 风险画像供管理层查看。

F22 驾驶行为评分已上线

功能概述

基于急加减速、超速、疲劳等风险事件与轨迹特征，每天为驾驶员计算 0~100 的安全分与风险等级（优/良/中/差），并给出扣分明细。

核心价值

把安全表现量化成一个可比较的分数：评优、培训、保险定价（UBI）都有了数据依据。

操作流程

侧边栏 风险画像 → 驾驶评分：按日期/驾驶员/车队筛选，点开某条查看当日扣分明细与关联事件。

注意事项

  • 评分为每日批量计算，当日分数次日可见；数据越完整评分越准。
  • 被工单判定为"误报"的事件不扣分——请及时处置工单，保障司机权益。

F23 风险趋势与画像已上线

功能概述

按车辆、驾驶员、企业三个维度查看风险趋势曲线与画像卡片：事件走势、等级构成、高频类型、干预与闭环情况，并支持黑点路段热力展示。

核心价值

从"处理今天的事"升级到"看清长期的势"：重点人、重点车、重点路段浮出水面，管理动作有的放矢。

操作流程

侧边栏 风险画像 → 风险趋势与画像：选择维度（车/司机/企业）与时间范围 → 查看趋势图与画像明细 → 下钻到具体事件。

注意事项

  • 趋势结论依赖数据积累，上线初期样本较少，建议以周/月为单位观察。
  • 画像只读，不修改任何底层数据。

4. 主数据管理域

车辆、终端、驾驶员、组织是所有业务功能的"地基"。建议维护顺序：组织架构 → 车辆/终端/驾驶员档案 → 绑定关系。

F28 车辆档案已上线

功能概述

车辆台账的增删改查：车牌、车型、运输性质、所属企业/车队、注册城市等基础信息集中维护。

核心价值

监控、报警、工单、评分全部按"车"归集——档案不准，一切统计都失真。

操作流程

主数据管理 → 车辆档案：新增/编辑填写信息保存；支持按车牌、所属组织筛选；不用的车辆置为"失效"而非删除。

注意事项

  • 车牌号全局唯一，重复会被拒绝。
  • "失效"车辆不再参与在线率等统计，历史数据保留可查。

F29 终端档案已上线

功能概述

北斗终端设备台账：终端编号、设备型号、协议类型、SIM 卡、视频通道数与启用状态维护。

核心价值

知道每辆车上装的是什么设备、状态如何，为后续指令下发与视频调阅打好数据基础。

操作流程

主数据管理 → 终端档案：录入终端信息；通过绑定关系挂接到具体车辆（见 F31）。

注意事项

  • 终端编号唯一；更换终端时先解绑旧终端再绑新终端，保留历史绑定记录。

F30 驾驶员档案已上线

功能概述

驾驶员信息管理：姓名、从业资格证、驾驶证类别、联系电话、状态维护。

核心价值

风险要落到"人"才有管理抓手：评分、画像、干预通知都依赖准确的驾驶员档案。

操作流程

主数据管理 → 驾驶员档案：新增/编辑驾驶员，绑定到车辆后即可参与评分与画像统计。

注意事项

  • 手机号等联系方式仅平台授权人员可见，用于紧急联系。

F31 绑定关系管理已上线

功能概述

维护"车-终端""车-驾驶员"两类绑定：何时生效、何时解绑、历史换过哪些，全部留档可追溯。

核心价值

报警和轨迹能准确归属到车与人；换车、换司机、换设备后统计口径不断档。

操作流程

在车辆档案/终端档案/驾驶员档案页内的"绑定"入口操作：选择对象 → 绑定（设生效时间）/ 解绑（记录失效时间）。

注意事项

  • 同一终端/驾驶员同一时间只能绑定一辆车，重复绑定会被拒绝。
  • 解绑不影响历史数据归属——事件按发生当时的绑定关系归集。

F32 组织架构管理已上线

功能概述

运输企业/车队的多级组织树维护：新增、改名、调整层级、停用。

核心价值

组织树是数据权限的骨架——"车队长只看本企业、坐席只看本部门"靠它实现。

操作流程

主数据管理 → 组织架构：在树上选择节点新增下级；车辆档案中选择所属组织完成挂接。

注意事项

  • 节点下仍有车辆或下级组织时不能删除，请先迁移。
  • 调整组织层级会影响数据权限范围，建议由超级管理员操作。

5. 系统管理域

平台自身的"人、账、配置"三件事。

F33 用户与权限（IAM）已上线

功能概述

替代单一演示账号：用户管理（建号、停用、重置密码、分配角色）+ 角色管理（四个内置角色 + 自定义角色，勾选菜单/按钮权限与数据范围）。

核心价值

每个人一把账号、一份权限：该看的看得到，不该看的进不去，操作可追责到人。

操作流程

系统管理 → 用户管理：新建用户 → 设置初始密码 → 分配角色；系统管理 → 角色管理：调整角色的菜单权限与数据范围（全部/本企业/本部门及以下）。

注意事项

  • 四个内置角色不可删除，可在其基础上新增自定义角色。
  • 权限调整即时生效，用户下次操作即按新权限校验。
  • 重置密码等敏感操作会写入审计日志。

F34 操作审计日志已上线

功能概述

登录登出、增删改等关键操作自动留痕：谁、什么时间、从哪里、做了什么、结果如何，可按人员/操作类型/时间范围检索。

核心价值

事后定责与合规检查的第一手证据；异常操作可回溯。

操作流程

系统管理 → 操作审计：设置筛选条件查询，点开记录查看操作详情。

注意事项

  • 审计记录只读，任何人（含管理员）不可修改删除。
  • 密码等敏感字段在记录中自动脱敏。

F35 系统配置与通知中心已上线

功能概述

三个页面管全局：数据字典（报警类型、风险等级等枚举）、系统参数（在线窗口、工单时限等可调项）、消息中心（站内通知统一查阅）。

核心价值

业务口径不写死在代码里：管理员改个参数就能调整平台行为，无需发版。

操作流程

系统管理 → 数据字典 / 系统参数：编辑取值保存即生效；顶栏铃铛 → 消息中心：查看与标记已读全部通知。

注意事项

  • 内置字典项与系统参数不可删除，可修改取值。
  • 参数修改立即影响后续统计口径（如在线窗口分钟数），请谨慎调整并知会相关岗位。

6. 常见问题

问题解答
页面顶栏显示"降级轮询"是什么意思？实时推送通道暂时断开，页面自动改用 5 秒轮询，数据仍会更新；通道恢复后自动切回"实时推送"，无需刷新页面。
为什么我看不到某个菜单？菜单按权限显示。请联系超级管理员在"角色管理"中为你的角色勾选对应菜单，或为你分配包含该权限的角色。
大屏上的数字多久变一次？车辆位置每秒刷新；在线率、报警统计、工单积压等统计每 30 秒整批校正，新报警作为增量即时置顶。
报警处理时提示"状态已变化"？说明另一位同事刚刚已确认或解除了该报警。刷新列表查看最新状态即可，避免重复处置。
车辆详情显示"未绑定"？该车辆尚未关联终端或驾驶员。请到主数据管理完成绑定（F31），绑定后监控归属与统计立即生效。
今天的驾驶评分怎么还没有？评分为每日批量计算，当日行为次日出分；若数据缺失，请检查该车当日是否有定位上报与有效绑定。
误报警会影响司机评分吗？不会。将对应工单以"误报"结论闭环后，该事件不计入驾驶评分。
演示数据从哪里来？当前环境数据由样例导入与轨迹模拟器产生，用于功能演示与验证；接入真实终端（JT/T 808）在第二波规划中。
