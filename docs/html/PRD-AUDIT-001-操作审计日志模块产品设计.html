操作审计日志 · 产品设计说明书

功能编号：F34（系统管理域）｜文档版本：v1.0｜编写日期：2026-10-02｜配套技术文档：MOD-AUDIT-001

一句话说明：平台把所有关键操作自动"记账"且账本不可改，安全管理员可以按人、按时间、按功能查到每一笔操作的来龙去脉。

一、为什么做

1.1 业务背景

北斗导航数据业务平台承载车辆实时位置、驾驶风险预警、视频证据、处置工单等敏感数据，使用方包括企业调度员、安全管理员、平台运维等多种角色。行业监管（道路运输车辆动态监控管理办法、网络安全等级保护）对运营平台有明确要求：重要操作必须留痕、日志不可篡改、保存期限不少于 6 个月（事故相关证据更久）。随着平台从演示阶段走向多用户真实运营，"谁做了什么"必须可追溯。

1.2 现在的问题

痛点具体表现后果
操作无记录车辆/终端/司机被误删、绑定关系被换绑后，无法知道操作人、时间责任无法界定，纠纷只能"猜"
登录无追踪密码被冒用、有人暴力尝试登录，系统没有任何记录账号盗用发现不了、取证不了
敏感查询无管控后续上线视频调阅、数据导出后，谁在什么时间看了哪辆车，无据可查隐私泄露风险，合规检查不过
日志可被改动如果管理员能登录数据库直接改日志，留痕就失去意义"自己监督自己"，证据效力不足

1.3 做成后的价值

定责有据

  • 误操作、恶意操作可精确定位到人、时间、IP
  • 处置动作与业务对象串联

安全发现

  • 登录失败异常增多可被检索发现
  • 非常用 IP、非常时段操作可追溯

合规交付

  • 满足监管留痕与防篡改要求
  • 检查时可直接导出/展示日志

无感运行

  • 自动采集，业务人员零感知
  • 不增加任何业务操作步骤

三、谁在用、什么场景用

安全管理员（主要用户）
"这辆车的终端是谁换绑的？"
按车牌/车辆 ID 搜到对象相关的全部操作，定位操作人、时间、来源 IP，配合业务记录复盘。
安全管理员
"昨晚是不是有人在试密码？"
筛选动作=登录失败、时间=昨晚，查看尝试使用的用户名和来源 IP，发现暴力破解或共享账号滥用。
企业管理者
"月度安全例会上要看操作概况"
通过概览数字（总操作量、成功率、登录失败次数、高频操作人）了解平台使用与安全态势。
合规检查 / 外部审计
"请提供近三个月的管理员操作记录"
按时间段导出范围数据（导出能力本期以页面检索+详情呈现，导出文件在后续波次），并出示防篡改说明。
平台运维
"某接口被反馈操作失败，查现场"
通过结果=失败筛选，结合错误消息、耗时、请求摘要，还原故障现场（不替代技术日志，但是业务视角补充）。

四、一条审计记录讲了什么

每一条日志回答六个问题（5W1H 的产品化表达）：

问题记录内容产品化说明 / 示例
谁操作人账号admin；登录失败时记录"对方自称是谁"（输入的用户名），即使密码错误也留痕
什么时间操作发生时间精确到秒，按本地时区（Asia/Shanghai）展示
从哪来IP 地址、设备信息经门户转发的真实客户端 IP；浏览器/设备类型（User-Agent 摘要）
在哪个功能模块 + 动作如"主数据 / 车辆登记"、"认证 / 登录失败"、"工单 / 派单"（后续）
对什么对象对象类型 + ID车辆（京 A34567，ID 10086）、终端 TERM_003 等
结果怎样成功/失败、错误原因、耗时失败必须记原因，如"车牌+颜色已存在"；耗时用于发现慢操作

隐私保护：日志不是"什么都存"。密码、令牌、密钥一律脱敏显示为 \*\*\*；手机号仅保留前 3 后 4（如 138\*\*\*\*8000）；请求内容超长截断，避免把敏感大报文写入审计库。

五、功能总览

① 自动留痕

  • 登录成功/失败
  • 新增/修改/删除类操作全量
  • 敏感查询按开关记录

② 日志检索

  • 时间/用户/模块/动作/结果筛选
  • 关键字模糊搜索
  • 分页、详情抽屉

③ 安全概览

  • 操作总量与成功率
  • 登录失败次数
  • 动作分布/高频用户

④ 防篡改

  • 只追加、页面无编辑删除入口
  • 每行内容指纹
  • 为后续校验/归档预留

六、什么操作会被自动记录

采集不需要开发人员逐个接口"打招呼"，平台按统一规则自动执行；个别敏感查询用"显式标记"方式加入。

操作类型是否记录说明 / 典型示例
登录成功 / 登录失败记录失败同样记录，用于发现暴力破解
新增类（登记车辆、录入司机、建规则…）记录自动提取新建对象的 ID
修改类（编辑档案、换绑、改规则…）记录记录修改目标与请求摘要（不记对比快照*）
删除类（删除档案、解绑…）记录业务上是软删除也记录为删除动作
数据导出记录后续波次上线时打标记，记录导出条件
视频调阅、证据播放/下载记录随视频功能（F16/F25）上线，记录调阅对象
报警确认、派单、坐席干预记录随 F17/F20/F21 上线自动纳入
普通列表/详情查询默认不记录量级巨大且价值低；确需审计的查询由产品在需求中指定后开启
审计页自身的查询不记录避免"查日志产生日志"刷屏（访问审计页本身仍会随登录与会话留痕）

* 修改前后字段对比（数据变更快照）列入后续增强，本期记录"谁、在何时、提交了什么"，已能满足绝大多数定责场景。

交互规则

  • 默认条件：进入页面默认展示最近 7 天；单次查询时间跨度最大 90 天（防止一次拉取过大数据）；结束时间不填默认当前时刻。
  • 失败行高亮：结果列失败使用红色标签；动作标签按动作类型着色（登录失败=红、增删改=蓝、查询类=灰）。
  • 详情抽屉：点"详情"从右侧滑出，分区展示：基本信息（人/时间/结果）、请求信息（方法/URI/参数/脱敏请求体）、对象信息、终端信息（IP/设备）。请求体以格式化 JSON 展示。
  • 对象跳转（后续增强）：详情中的车辆/终端 ID 未来可点击跳到对应档案；本期先展示文本。

八、登录安全审计

登录是安全审计中最特殊的事件：失败的登录也要记，而且要记住"试图登录的用户名"和来源 IP——这是发现撞库、暴力破解、离职人员尝试登录的唯一数据来源。

场景记录内容页面呈现
密码正确登录动作=登录成功，用户=账号，IP/UA，耗时蓝色"登录成功"标签
密码错误/用户不存在动作=登录失败，用户=对方输入的用户名，失败原因，IP/UA红色"登录失败"标签，详情可见错误消息
令牌过期后操作接口返回 401，前端跳登录页；该次请求以匿名身份记录失败用于排查会话异常

九、出事了怎么查：典型追溯流程

场景：调度员反馈"京 A34567 车上的终端被换成了别的设备，不知道谁操作的"。安全管理员的操作路径：

按对象初筛
在关键字输入车辆 ID/车牌，或时间范围圈定事发当天，筛出相关操作
定位关键动作
在结果中找到"换绑终端/绑定终端"记录，确认精确时间
锁定操作人
详情中看到操作账号、来源 IP、设备信息
串联前后操作
按该用户+时间扩大检索，看其前后还做了什么（解绑、编辑等）
形成结论
依据不可篡改的日志记录出具处理意见，必要时截图/导出存档

十、防篡改与合规留存

  • 只追加账本：系统只提供日志的"写入"（系统自动）和"查看"（管理员）能力，没有任何修改、删除接口和页面按钮。
  • 内容指纹：每条日志落库时对核心内容计算一个 SHA-256 指纹。若有人绕过应用直接改数据库，未来的巡检任务重算指纹即可发现被改动的行。
  • 演进路线（本期之后）：① 指纹链（每条记录含上一条指纹，形成可整体校验的链条）；② 数据库账号只授 SELECT/INSERT 权限；③ 按保留期归档（普通 6 个月、涉事记录长期保全）到低成本存储；④ 向外部日志平台同步。

产品口径：本期重点解决"留痕全、查得到、改不了（应用层）"；正式等保测评所需的指纹链巡检与外部归档，在获得本期运营反馈后于后续迭代落地。

十一、业务规则汇总

规则说明
自动采集原则除显式标记的敏感查询外，不需要业务模块主动写日志；漏记属于平台缺陷
失败也记录业务被拦截（如同号重复、互斥冲突）、登录失败、权限不足都要记，且失败原因可见
审计不影响业务日志组件故障时业务操作照常成功，故障信号进入技术日志供运维发现
敏感信息脱敏密码/令牌/密钥打码，手机号部分隐藏，报文截断；不记录文件流
查询范围限制默认近 7 天，单次最大 90 天，防止大范围拖取日志
可见权限本期仅 admin 可见；F33 用户权限体系上线后按权限码 audit:view 控制
日志不可清理页面不提供删除；保留期/归档策略由后台运维任务统一执行（后续）

十三、业务验收标准

  1. 用正确/错误密码各登录一次，审计页分别出现"登录成功""登录失败"，失败记录能看到输入的用户名与 IP；
  2. 在车辆档案完成一次"登记 → 编辑 → 打开绑定管理换绑终端"，审计页能按时间顺序找到对应 3 类操作，详情中对象 ID 正确、请求体里看不到明文密码；
  3. 制造一次失败操作（如重复车牌），日志以"失败+原因"展示，红色标识明显；
  4. 普通列表翻页、查看详情不产生新日志；审计页自身的查询也不产生日志；
  5. 按用户、模块、动作、结果、关键字、时间范围筛选结果准确，默认近 7 天、跨度超过 90 天被友好提示；
  6. 页面上找不到任何编辑/删除日志的入口；
  7. 概览数字与明细数据一致；中文显示正常，时间为本地时间。
