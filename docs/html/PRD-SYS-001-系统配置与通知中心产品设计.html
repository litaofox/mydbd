1. 背景与目标

当前平台枚举值与策略参数分散写死在前后端常量中（车牌颜色、协议类型、设备类型、密码策略、SLA 阈值等），修改任何一项都需要改代码重新发布。F35 建立统一的配置中心，将字典与参数从代码中剥离，支持运营人员在后台维护，业务模块按需读取。

本期交付核心：数据字典 + 系统参数。站内消息通知中心与对象存储（MinIO）建表预留接口，完整 UI 与接入后续迭代。

2. 数据字典中心

统一管理平台所有枚举型字典（码表），前后端共享数据源。

2.1 字典结构

  • 字典类型（dict_type）：如 plate_color（车牌颜色）、protocol_type（协议类型）、risk_event_code（风险事件码）、close_result（闭环结果）等
  • 字典项（dict_item）：属于某类型的具体选项，含 label（显示名）、value（存储值）、sort（排序）、status（启用/停用）

2.2 内置字典（种子数据）

2.3 接口

  • 字典类型：分页、新增、编辑、删除（停用）、按 code 查类型及全部启用项
  • 字典项：按类型查、新增、编辑、删除（停用）、排序
  • 对外查询：GET /api/system/dict/{dictCode}/items 返回启用项列表，供业务模块和前端下拉渲染

前端提供 useDict(dictCode) composable 缓存字典项，替代现有 constants/dict.ts 中的硬编码常量。

3. 系统参数配置

管理平台运行时的可配置参数（key-value），替代当前写死的策略阈值。

3.1 参数结构

  • config_key：参数键（唯一），如 password.min_length、login.max_fail
  • config_value：参数值
  • value_type：STRING / INT / BOOL / JSON
  • is_system：内置参数（不可删除，可修改值）

3.2 内置参数（种子数据）

参数键默认值说明
password.min_length8密码最小长度
password.max_length20密码最大长度
login.max_fail5登录失败锁定次数
login.lock_minutes15锁定时长（分钟）
sla.grace_ratio0.2临期阈值比例

3.3 读取方式

后端提供 ConfigService.getValue(key, default) 与带类型的读取方法，业务模块按需调用；参数变更后立即生效（内存缓存 + 变更失效）。

子功能本期后续
站内消息通知中心建表 sys_message + 预留接口消息列表、已读/未读、F19 多渠道通知接入
对象存储（MinIO）建表 sys_file + 预留接口文件上传/下载、司机头像、视频片段存储

5. 非功能与范围

  • 权限：字典与参数的 view/edit 权限分离，仅管理员可维护
  • 缓存：字典项与参数值内存缓存，变更时主动失效
  • 审计：字典/参数的增删改操作留痕
  • 不做：字典多语言、参数版本回滚、MinIO 实际接入、站内消息完整 UI
