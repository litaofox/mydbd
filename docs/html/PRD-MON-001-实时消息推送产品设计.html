实时消息推送（F14）产品设计

对应模块设计：docs/design/mod/MOD-MON-001-实时消息推送模块设计.md ｜ 版本 v1.0 ｜ 2026-10-02

1. 背景与目标

当前监控大屏（/monitor）通过前端 setInterval(refresh, 5000) 每 5 秒轮询 /api/traj/latest 与 /api/monitor/overview，在途车辆位置、风险事件、终端报警均依赖 5 秒一次的全量拉取。存在三个问题：

  • 端到端延迟最高 5 秒+，不满足运营监控"秒级感知"的要求；
  • 轮询浪费带宽与 DB 连接：无更新时仍全量拉取，并发坐席放大数据库压力；
  • 风险/报警无即时提示：新风险事件要等下一轮轮询才能在列表刷新，坐席无法第一时间响应。

F14 目标：用 WebSocket 长连接替代轮询，实现位置 1 秒级、风险/报警 ≤3 秒的主动推送；保留轮询作为降级兜底，确保 WS 不可用时功能不中断。

2. 用户与场景

角色场景期望
调度坐席监控大屏值守，关注在途车辆位置与异常地图车辆位置平滑/低延迟更新，报警车辆立刻标红
风控坐席等待新风险事件触发工单风险事件产生后 3 秒内收到推送并弹窗提示
车队队长关注所属车辆终端报警终端报警实时进入列表，无需手动刷新

3. 推送内容

单一 WebSocket 通道复用三类消息，前端按 type 字段分发：

type含义数据频率
POINTS在途车辆最新位置全量List<GpsPoint>（plateNo/identityCode/lng/lat/speed/direction/alarmFlag）每 1 秒
RISK新增风险事件RiskEvent 摘要（id/eventCode/plateNo/riskLevel/eventTime/lng/lat）增量，扫描到即推
ALARM新增终端报警WarnInfo 摘要（id/plateNo/typeId/startWarnTime/startLng/startLat）增量，扫描到即推

位置消息采用"全量快照"而非增量：在途车辆数量有限（百级），全量 JSON 体积可控，前端直接替换数组重绘 marker，逻辑简单且无丢点风险。风险/报警采用"按 create_date 时间窗口增量"，避免重复推送。

4. 交互与降级

4.1 连接建立

前端进入监控页后建立 ws://host/ws/realtime?token=JWT，服务端在握手阶段校验 token 有效性与用户状态，无效则关闭连接（1008）。

4.2 消息处理

  • 收到 POINTS → 替换地图 marker 数组与车辆列表，更新总览"在途车辆"；
  • 收到 RISK → 前端风险计数 +1，顶部 toast 提示（车牌+风险类型），若打开风险事件页则刷新列表；
  • 收到 ALARM → 终端报警计数 +1，toast 提示。

4.3 心跳与重连

服务端不主动发心跳（由 1 秒的 POINTS 充当心跳）。前端检测到连接关闭：

  1. 指数退避重连：1s → 2s → 4s → 8s → 16s → 30s（封顶），恢复后回到 1s；
  2. 重连期间 降级回 5 秒轮询（复用原有 refresh 逻辑），保证数据不中断；
  3. WS 重连成功后停止轮询，恢复推送模式。

降级是硬性要求：任何 WS 异常（网络、代理、鉴权失败）都不能让监控页停摆，必须自动回落轮询。

5. 非功能指标

指标目标
位置端到端延迟≤ 1.5 秒（CEP/模拟器入库 → 前端渲染）
风险/报警端到端延迟≤ 3 秒
单连接内存SessionRegistry 单会话 < 64KB
并发会话演示环境 ≥ 50 并发稳定
失败降级WS 断开后 ≤ 5 秒自动回退轮询

6. 范围与不做

本期范围：监控大屏（Monitor.vue）的位置/风险/报警三类推送 + 轮询降级。其他页面（工单、规则等）暂不接入 WS，仍走轮询或手动刷新。

不做：STOMP 协议、消息持久化与离线投递、用户级消息定向（本期所有登录用户收到相同推送，数据范围由既有权限控制在前端过滤）、多实例广播（单机部署，SessionRegistry 内存态）。
