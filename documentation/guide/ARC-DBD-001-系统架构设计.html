ARC-DBD-001 系统架构设计

文档编号 ARC-DBD-001|版本 v1.2.0|发布日期 2026-10-06|事实基准 2026-10-06 源代码

关联文档：SYS-DBD-001 项目总体设计　DDL-DBD-001 数据库设计　DEP-DBD-001 部署与运维手册　API-DBD-001 平台接口手册

1 架构总览

系统采用"单库 + 双后端服务 + 单页前端 + 门户反代"的分层架构。Java 平台承担交易型业务（权限、档案、工单、查询、推送），Python 处理服务承担数据接入、模拟器与规则引擎旁路计算，两者共享 PostgreSQL/PostGIS 数据库并经 HTTP 协作；前端为 Vue3 SPA，由 nginx 托管静态资源并按前缀反代后端。

v1.1 增补（2026-10-06，GATEWAY-PLAN-001 一期）：数据接入面新增 Kafka 消息通道——Python 服务新增 app/gateway/ 子包（consumer/mock_producer/terminal_resolver/mappers/media_store/runner），以 GATEWAY_MODE=simulator|mock|gateway 三模式切换：simulator 走既有 HTTP/模拟器链路；mock/gateway 模式经 kafka-python2 消费外部 vps 车载网关的 6 类 topic（GPS/报警/附件/心跳/下线/指令），写轨迹点、刷新在线态、旁路触发 CEP 与工单、转存报警附件。Java 侧新增网关状态代理与附件鉴权中转（module-monitor 的 gateway 包 + 2 个 Controller），前端新增 /system/gateway 状态页。基础设施新增可选 Kafka 容器（apache/kafka:3.9.0 KRaft，compose profile dev-infra，仅 mock 本地仿真启动；生产直连外部集群）。"Java 管交易、Python 管数据接入与算法旁路"的边界不变。详见 GATEWAY-PLAN-001 第 10 章 与 DEP-DBD-001 §6.4。

终端层
北斗视频智能终端：1Hz 定位 · DSM/ADAS 边缘识别 · 事件抓拍（现状以模拟器/HTTP 推送等价演示） 坐席浏览器 / 大屏 / 内嵌 Electron
接入层
现状：HTTP 接入（/api/ingest，X-Service-Token）· 进程内模拟器 · nginx :8090 反代 规划：JT/T 808-2019 TCP 网关（Netty）· JT/T 1078 视频通道
数据层
PostgreSQL 16 + PostGIS 3.4：schema traj（轨迹/主数据/IAM）· mon（监控/风险/工单/评分） 卷 pg-data · 初始化 17 个 SQL
业务服务层
platform-app（Spring Boot 3.2 / JDK17）：platform-common + 9 个业务模块 + platform-boot processing-app（FastAPI / Python 3.12）：ingest · simulator · dataset · cep_engine · 占位识别
推送与展现层
WebSocket /ws/realtime（POINTS · RISK · ALARM · NOTIFY） Vue3 SPA：Element Plus · Pinia · Leaflet · ECharts portal-nginx 静态托管 + 前缀路由

分层之间无消息中间件：当前版本不引入 Kafka/Redis，服务协作仅靠 HTTP 调用与共享库表。这是试点阶段刻意保持的最小依赖形态；消息总线、流处理与网关集群在蓝图中属于第二波规划。

3 后端模块清单与职责

父 POM（backend-java/pom.xml，Spring Boot 3.2.10 / JDK 17 / MyBatis-Plus 3.5.7 / jjwt 0.12.6）聚合 11 个 Maven 模块：1 个公共库（platform-common）、9 个业务模块、1 个启动模块（platform-boot）。业务模块的编译依赖保持有向无环：

  • module-notify 依赖 module-system（接收人按菜单查询等）；
  • module-monitor 依赖 module-trajectory（复用轨迹点域模型与查询）与 module-notify（实现其 RealtimePusher SPI）；
  • module-risk 依赖 module-notify（建单/升级通知）；
  • 其余业务模块仅依赖 platform-common；所有模块由 platform-boot 统一聚合打 fat jar。

4 Python 处理服务（processing-app）

处理服务是独立 FastAPI 应用（app/main.py，uvicorn 启动于 8000 端口），与 Java 服务不共享代码，协作契约只有三样：共享数据库表、HTTP 接口、服务令牌。

4.1 routes（HTTP 边界）

路由模块端点鉴权职责
routes.healthGET /health无容器健康检查，返回 {"status":"UP"}
routes.simulatorPOST /api/simulator/start · /stop；GET /status无（演示网络边界内开放，代码注释已标注正式版需登录态）控制进程内轨迹模拟器启停与状态
routes.ingestPOST /api/ingest/trajX-Service-Token终端/第三方批量推送定位点（5000 点/批分片入库），随后旁路触发 CEP 评估；引擎异常不阻断入库
routes.ingestPOST /api/ingest/load-sample无导入 samples 下样例 CSV 与当日司机事件 JSON；按设备+时间范围清理后重导（幂等）
routes.dataset/api/ingest/dataset/load · /clear · /status无后台线程生成/清空标准测试数据集（standard / dense 两档），保留 IAM/字典/配置/审计
routes.analysisPOST /api/analysis/videoX-Service-Token视频分析演示链路：占位"识别"信号候选 → CEP 按启用规则分级/去重/落事件，回写视频分析任务状态

4.2 services（领域逻辑）

  • cep_engine.py：F18 风控规则引擎。加载启用中的规则/围栏（TTL 缓存 risk_cache_sec=30，配置热生效），对定位点批与 DSM/ADAS 信号做匹配、风险定级、冷却窗口去重，写 mon.risk_event，并在同事务补建处置工单；
  • risk_engine.py：识别环节的骨架占位，只产出"信号码 + 置信度"候选（DSM_FATIGUE/DISTRACTION、ADAS_FCW/LDW），模块文档字符串明确"边缘识别 + 按需调阅，平台不做全量视频分析"；
  • simulator.py：进程内模拟器，按车辆绑定与城市生成实时定位点并写库；
  • dataset_gen.py：标准/稠密测试数据集生成（四省十车队、车辆/终端/司机/绑定/轨迹/事件）；
  • db.py：基于 psycopg2 的原生 SQL 访问层；config.py 用 pydantic-settings 从环境变量注入配置；security.py 校验 X-Service-Token 请求头。

4.3 与 Java 服务的契约

共享数据库（主契约）
Python 直接读写 traj/mon schema 的既定表（traj_gps_point、mon.risk_event、video_analysis、风险规则/围栏/工单表等）。表结构由 17 个初始化 SQL 定义，是两侧共同的事实源；任一侧改表必须同步另一侧 SQL。
HTTP + 服务令牌
前端经 nginx 把 /api/ingest、/api/simulator、/api/analysis/ 转发到 Python；机器调用以 X-Service-Token 鉴权（令牌值与 Java 侧共用 SERVICE_TOKEN 环境变量）。Java 当前不反向 HTTP 调用 Python。

前端为 Vue 3.4 + TypeScript 5.4 + Vite 5 的单页应用，构建产物 frontend/dist 直接由 portal-nginx 只读托管。依赖（package.json）：Element Plus 2.7 与图标库、Pinia 2.1、vue-router 4.3、Leaflet 1.9（地图）、ECharts 5.5（图表）、axios 1.7（HTTP）、dayjs、qrcode（MFA 绑定）。

6 模块交互关系

交互方式场景与实际类名
HTTP 同步 浏览器 → nginx：/api/analysis/score/、/api/analysis/profile/ 以更长前缀优先匹配到 Java（ScoreController/ProfileController），/api/analysis/ 到 Python；/api/simulator/、/api/ingest/ 到 Python；其余 /api/ 全部到 Java。响应统一 Result<T>{code,message,data}（GlobalExceptionHandler 兜底翻译异常）
共享库表 Python 写 traj_gps_point / mon.risk_event / mon.video_analysis / risk_work_order 等；Java 侧 TrajectoryService、DashboardMapper、RiskEventMapper、RiskOrderMapper 等只读消费。Java 模块间同样存在受控的跨域读库（如大屏 DashboardMapper 按 deptScope 查车辆车牌集合）。跨服务/跨域写操作以"同一事务内补建"保证一致性（Python CEP 落事件时同事务建工单）
WebSocket 推送 端点 /ws/realtime（RealtimeWebSocketConfig）。AuthHandshakeInterceptor 握手鉴权并写 uid；RealtimePushScheduler 每秒经 SessionRegistry 推送：POINTS（全量位置快照）、RISK/ALARM（id 游标增量）；通知走 RealtimePusher.sendToUsers（SPI 在 module-notify，实现类是 monitor 的 SessionRegistry）推 NOTIFY。所有消息经 WsScopeResolver 按用户范围过滤
Spring ApplicationEvent AuditFilter 在请求完成后 publishEvent(AuditEvent)；module-audit 的 AuditLogListener 以 @EventListener + @Async("auditExecutor") 单线程顺序消费落库，失败仅记 error，不影响业务。注意：通知派发不走事件总线，RiskOrderScheduler 直接调用 NotifyService.dispatchAsync（@Async("notifyExecutor")）
SPI 接口反转依赖 module-notify 定义 RealtimePusher 接口，由 module-monitor 实现，使 notify 不必反向依赖 monitor，避免循环依赖；platform-common 定义 AuthRealm 接口，由 module-iam 的 DbAuthRealm 实现
启动期引导 ApplicationRunner 顺序执行：DataInitializer（@Order(10)，确保 admin 存在）→ ProvinceTestUserInitializer（@Order(20)，四省 8 个测试用户）；均幂等

7 端到端数据流

7.1 主线一：定位点 ingest → 入库 → 增量推送 → 地图/大屏

产生点
终端 HTTP 推送 / 模拟器 / 样例导入；每点含 identityCode、plateNo、经纬度、速度、方向、报警标志、gpsTime
分片入库
processing-app 每 5000 点一批写 traj.traj_gps_point（PostGIS geometry + GIST）
CEP 旁路
cep_engine 同批评估超速/围栏等规则；异常被吞掉，绝不阻断入库主链路
游标/快照准备
Java 侧 TrajectoryService 查各终端最新点；RealtimePushScheduler 启动时把游标初始化为当前最大 id，不回放历史
握手鉴权
浏览器连 /ws/realtime，AuthHandshakeInterceptor 校验令牌写入 uid；新连接立即收一帧范围过滤后的 POINTS
秒级推送
每 1s：全量位置快照 POINTS；风险/报警按 id 游标增量（每 tick 最多 50 条）
逐会话过滤
WsScopeResolver 把 deptScope 换算为可见车牌集合（null 全量/空集不可见），SessionRegistry 过滤后下发
前端渲染
useRealtime 收消息 → Monitor 地图车辆标绘/HeatLayer 热力；Dashboard 大屏 30s 轮询聚合摘要（在线/里程/工单/区域）

7.2 主线二：预警信号 → 规则引擎 → 风险事件 → 通知/工单 → 干预闭环

边缘信号
终端 DSM/ADAS 识别命中，上报信号码+置信度+抓拍（现状 /api/analysis/video 由占位 risk_engine 产生候选）
规则评估
cep_engine 读 30s TTL 缓存的启用规则/围栏，定级并做冷却去重；不落事件的情形同步回写视频任务摘要
事件+工单落库
写 mon.risk_event；满足建单条件时同事务补建 risk_work_order 与 SLA，起始时限开始计算
实时触达
下一推送 tick 风险事件增量推地图/报警滚动；RiskOrderScheduler 每 60s 用 id 游标扫新工单，dispatchAsync 向在线坐席定向弹 NOTIFY
认领处置
坐席在工单中心按权限认领、分派；状态待处理→处理中，操作经 @AuditLog 留痕
干预取证
电话提醒/安全教育/停运等干预写 RiskIntervention；必要时按需调阅事件片段（边缘触发+按需调阅）
超时升级
RiskOrderScheduler 每分钟物化 overdue/escalated 并补系统升级日志
闭环沉淀
工单闭环；事件与干预进入 T+1 安全分（每日 01:00）与风险画像/黑点统计，反哺规则与运营

8 横切机制

8.1 JWT 鉴权链

  • JwtUtil（jjwt 0.12.6，HS 对称密钥来自 JWT_HMAC_SECRET）签发两类令牌：access（8h，purpose=access，uid claim）与 mfa（5min，仅可换二次验证）；签发算法 2026-10-06 起显式固定 HS256（此前仅传 Key 时 JJWT 按密钥长度自选，50 字节密钥实际签发 HS384），Java 解析侧接受同族 HMAC；
  • 跨服务验签：浏览器可直达的 processing 接口（经 nginx /api/simulator/、/api/ingest/ 转发）由 app/security.py 用 PyJWT 以同一把密钥独立验签，算法白名单 HS256/HS384/HS512（兼容存量 HS384 令牌）；服务间数据面（/api/ingest/traj、/api/gateway/*、/api/analysis/*）则走 X-Service-Token，与用户 JWT 两套体系；
  • AuditFilter 注册 order=0 包在最外层（鉴权短路也能记匿名失败访问）；JwtAuthFilter 注册 order=1、仅拦 /api/*，白名单 /api/auth/login、/api/auth/mfa/verify；
  • 过滤器校验令牌与 purpose，经 PermissionCache.getOrLoad（TTL 120s）调 DbAuthRealm 装载 UserInfo 写入 ThreadLocal，请求结束清理；/health、/actuator/health 不经过滤器。

8.2 功能权限：@RequiresPerm + PermAspect

切面基于已装载的权限码集合判定，不查库、不依赖 IAM 模块；支持方法级优先、类级兜底与 AND/OR（Logical）组合；超管直通，失败抛 BizException(403)。前端以 v-perm 指令做同口径的按钮隐藏（隐藏不是安全边界）。

8.3 数据范围注入

DataScopeService.compute 在登录装载阶段把用户多角色解析为 deptScope（null/空集/部门集合）；各业务 Service 执行查询前取当前用户范围并换算为可见车牌或部门集合传入 Mapper，空集合立即短路返回空页/0 计数。规则全文见 SYS-DBD-001 §8。

8.4 审计：切面 + 过滤器 + 异步监听器

AuditFilter 缓存请求/响应体，按"登录必记、GET 仅注解记、写操作全记"组装 AuditEvent（含 traceId、耗时、IP、UA、脱敏后报文——password/token/secret 打码、手机前 3 后 4）；AuditAspect 用 SpEL 解析 @AuditLog(objectId="#id") 补充对象 ID；事件经 ApplicationEventPublisher 发布，AuditLogListener 用独立 auditExecutor 单线程异步落库。audit.enabled=false 可整体关闭。

8.5 全局异常与响应结构

GlobalExceptionHandler（@RestControllerAdvice）把 BizException、参数校验异常、DuplicateKeyException、未知异常统一翻译为 Result 结构；业务异常保留业务码与信息，未知异常返回 500 与固定提示，堆栈只进日志。

8.6 持久化设施

  • MybatisPlusConfig 注册 PaginationInnerInterceptor（PostgreSQL 方言）；未设置全局 maxLimit，单页上限由各 Service 自行钳制（如报警/评分页 size 钳制 1~100、滚动列表 limit 1~50、档案页缺省 10 最大 100）；
  • MybatisMetaObjectHandler 插入时自动填 creator/create_date/updater/update_date，更新时填 updater/update_date；操作人取 UserContext，无上下文回落 system；
  • 连接池 HikariCP maximum-pool-size=10；下划线↔驼峰自动映射；Jackson 全局时区 Asia/Shanghai、日期格式 yyyy-MM-dd HH:mm:ss。

8.7 定时任务调度器

@EnableScheduling 只标注在启动类 PlatformApplication 一处；各调度器只写 @Scheduled，不得重复开启调度。ScoreScheduler 源码注释亦明确此约束——重复标注不会多跑任务但属于配置错误，排查"定时任务不执行"时先确认启动类注解未被移动。
