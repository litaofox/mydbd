1.1 命名与设计规范（从 SQL 归纳）

  • 主键：业务表一律 id bigserial PRIMARY KEY；关系表用复合主键（如 sys_user_role(user_id, role_id)）；mon.risk_fence_state 以 (identity_code, fence_id) 为复合主键；mon.risk_order_sla 以 risk_level 为主键；traj.sys_audit_log.id 为 bigint（应用层雪花 ID，非自增）；traj.base_warn_type.id 为 integer（字典显式编码）。
  • 索引前缀：普通索引 idx_，唯一索引 uk_；内联唯一约束也用 uk_ 前缀（如 CONSTRAINT uk_risk_order_event UNIQUE (event_id)）。
  • 部分唯一索引：大量唯一索引带 WHERE valid_mark = 1，保证软删后编码可复用；04 脚本还用条件部分唯一索引实现绑定互斥（一车一有效终端、一终端一车、一车一主班司机）。
  • 软删除：多数业务表带 valid_mark smallint NOT NULL DEFAULT 1（1=有效 0=删除）；菜单表 sys_menu 例外——版本种子化维护，不做软删。审计日志表不继承该组公共字段。
  • 审计列：业务表普遍带 creator / create_date / updater / update_date 四列；sys_audit_log 为只追加表，只保留 create_time，不提供 updater/update_date/valid_mark。
  • 注释方式：表级用 COMMENT ON TABLE，关键列用 COMMENT ON COLUMN 或行内 -- 注释；本文字段说明优先取 SQL 注释，无注释者按字段名与类型推断并标注"（推断）"。
  • 幂等可重入：所有脚本使用 CREATE TABLE/INDEX IF NOT EXISTS、ON CONFLICT DO NOTHING、ALTER TABLE ... ADD COLUMN IF NOT EXISTS，可重复执行；种子插入后普遍用 setval 对齐自增序列。
  • 外键策略：全库仅 traj.sys_dict_item.dict_type_id 声明了物理外键（REFERENCES traj.sys_dict_type(id) ON DELETE CASCADE），其余表间关系均为应用层维护的逻辑外键。
  • 空间数据：轨迹点 location geometry(Point, 4326)、电子围栏 polygon_geom geometry(Polygon, 4326)，均配 GiST 空间索引。
