1. 文档说明

目的。面向平台侧研发与架构决策，系统梳理 vps 车载网关的功能、全部对外接口（终端 TCP 协议接口、平台 HTTP 接口、Kafka 数据通道、流媒体接口）及其依据的 JT/T 808、JT/T 809、JT/T 1076、JT/T 1077、JT/T 1078 与主动安全智能防控（苏标）系列标准。

方法。以网关源码（Java 多模块工程）逐模块静态分析为准，消息 ID、字段、端口、Topic、DTO 均取自代码；标准协议以标准原文 PDF/DOC 为参照，二者交叉印证。

取证边界（务必知悉）：

① JT/T 808-2019、JT/T 809-2019、JT/T 1077-2016、JT/T 1078-2016 的 PDF 为扫描影像或字体内码（CID）不可提取文本，未逐字 OCR；其条款摘要依据标准公开目录、可提取的 2011/2016 版本以及网关代码实现交叉验证。

② 主动安全智能防控三份 .doc 已成功提取原文文本，确认其为江苏省地方标准 DB32/T 2019 征求/发布稿（《道路运输车辆主动安全智能防控系统技术规范》第 1/2/3 部分），本报告引用了其条款原文。

2. 系统总览

2.1 定位与能力边界

vps 是一个车载终端接入与协议转换网关，南向对接车载终端（行车记录仪/车载视频终端/主动安全智能防控终端），北向通过 Kafka 消息总线和少量同步 HTTP 接口对接业务平台。能力覆盖：

  • JT/T 808 终端通信：注册、鉴权、心跳、定位（含批量/补报）、报警、多媒体、拍照、文本下发、终端参数/控制等；
  • JT/T 1078 车载视频：实时音视频、历史回放、对讲/监听/广播、资源列表查询、云台控制（信令编解码齐备），并内置 RTP 收流与 WebSocket-FLV 转发；
  • 苏标主动安全：ADAS/DSM/胎压/盲区/激烈驾驶报警附加项解析、报警附件（图片/音频/视频/文本）独立文件上传服务；
  • 平台对接：定位、报警、附件、心跳、上下线、原始报文等事件以 JSON 投递 Kafka；音视频与拍照等主动指令以同步 HTTP 下发并等待终端应答。

不包含：JT/T 809 上级平台联网（代码中无 809 服务端/客户端实现）、平台业务 UI、持久化的轨迹/报警分析业务库（仅提供 StarRocks 建表参考 DDL）。

3. 核心业务流程

3.1 注册 / 鉴权 / 心跳

  1. 终端 TCP 连接 10808，发送 0x0100 终端注册；网关查 MySQL vps_base_truck 白名单（手机号），回 0x8100 注册应答，鉴权码（authCode）取手机号；
  2. 终端发 0x0102 终端鉴权，网关比较鉴权码与手机号，一致即视为接入成功；
  3. 终端周期性发 0x0002 心跳（无消息体），网关回 0x8001 通用应答，并向 jt808_heartbeat_topic 投递事件；
  4. 连接断开时网关产生离线事件（jt808_offline_topic，type=1）。注意：代码中没有“上线”事件发出（见第 7 章）。

3.2 定位上报

  1. 终端周期上报 0x0200 位置信息汇报（报警标志、状态、经纬度、高程、速度、方向、时间 + 附加项）；
  2. 网关解码（经纬度已 ÷10⁶ 转为“度”），组装 PositionInfo（头 GpsHead + 体 GpsInfo），以 truckId 为 key 发 jt808_gps_topic；
  3. 0x0704 定位批量上传、补报位置（delay 标志）、图片关联点（0x0801 触发，gpsType=11）、主动安全点（gpsType=12）同样汇入该 Topic。

单位注意：对外 JSON 中 speed 单位为 m/h（米每小时，即 1/100 km/h），数值=协议原始值×100；mileage 单位为米，=附加项 0x01 原始值×100。下游落库前必须换算。

  • 文件命名：<文件类型>_<通道号>_<报警类型>_<序号>_<报警编号>.<后缀>，如前向碰撞为 6401；类型 00 图/01 音/02 音视频/03 文本；
  • 元数据仅保存在 Caffeine 内存（30 分钟），文件服务重启会丢失传输进度。

3.4 立即拍照

  1. 平台调 POST /api/command/{phone}/cameraShot → 网关下发 0x8801 摄像头立即拍摄命令（通道、张数/0xFFFF 录像、间隔、分辨率、质量、亮度/对比度/饱和度/色度、存储标志）；
  2. 终端回 0x0805 拍摄应答，随后以 0x0801 多媒体数据上传回传照片；
  3. 网关落 MySQL vps_gps_photo，文件写本地盘，并向 jt808_gps_topic 发一条 gpsType=11 的图片关联定位点。该接口支持 timeout=0 的异步模式（不等待 0x0805）。

3.5 实时音视频传输

  1. 平台调 POST /api/command/{phone}/realtimeVideoReq（逻辑通道号、数据类型 0 音视频/1 视频/2 对讲/3 监听/4 广播/5 透传、码流类型默认 1 子码流）→ 网关下发 0x9101 实时音视频传输请求；
  2. 终端按 1078 以 RTP over TCP 连接 10780 推流；
  3. HTTP 应答的 extend 中返回浏览器播放地址：ws://<视频主机>:20780/live?tag={手机号}-{通道}&uuid={会话ID}&audio=1；
  4. 浏览器用 flv.js 等播放 FLV over WebSocket；停止：GET /api/command/{phone}/stopRealTimeVideo → 0x9102（controlCode=0）。

视频支持 H264（负载类型 98）与 H265（负载类型 99，以私有扩展写入 FLV，前端需支持增强 FLV 的播放器）；音频支持 G.711a/G.711u/G.726/ADPCMA/AAC，浏览器侧统一转 AAC。

3.6 历史录像回放

  1. 平台调 POST /api/command/{phone}/historyVideoReq（通道、音视频资源类型、码流类型、存储类型、回放方式、快进快退倍数、起止时间 yyyy-MM-dd HH:mm:ss）→ 下发 0x9201 远程录像回放请求；
  2. 终端向 10781 推回放流，浏览器从 20781 拉 FLV；
  3. 停止/暂停/拖动由 0x9202 回放控制完成（停止 playControl=2）。

资源检索：POST /api/command/{phone}/queryMediaItems → 0x9205 查询资源列表，同步等待终端 0x1205 资源列表（默认 10 秒）。

3.7 对讲 / 监听 / 广播

对讲/监听复用 0x9101（dataType=2/3），终端音频连 10782，浏览器侧 20782。浏览器上行对讲为 PCM、640 字节/帧，由 vps-video 转码后送终端。停止对讲 GET /api/command/{phone}/stopTalk（0x9102 controlCode=4）。

3.8 终端上下线

在线态由连接生命周期维护：连接断开 → jt808_offline_topic（OfflineInfo：truckId、时间、type=1 离线）。上线不发消息，下游若需上线时刻需以鉴权成功（jt808_command_topic 中的 0102）或首条心跳/定位近似。

4. 接口清单

网关共有 5 类接口面：① 终端 TCP 信令（10808）；② 附件 TCP（10818）；③ 视频 RTP/WS；④ 平台 HTTP REST（18001/18009）；⑤ Kafka 数据通道。平台系统对接的核心契约是第 ④、⑤ 两类。

4. 1 终端侧 TCP 信令（JT/T 808，端口 10808）

4.1.1 帧格式与链路规则

项实现规则
帧界0x7E 标识位分隔
转义0x7E↔0x7D 0x02，0x7D↔0x7D 0x01（先转义后校验/反转义后校验）
校验消息头+消息体逐字节异或（XOR）；配置 jt808.checkCode=true，校验失败仅记录日志、不丢包（见第 7 章）
分包消息头分包位 + 消息总包数/包序号；网关内存重组，支持 2013（终端手机号 BCD[6]）与 2019（BCD[10]）自适应
应答所有需应答消息回 0x8001 通用应答；平台下行指令的终端应答用于 HTTP 同步返回

6.2 JT/T 808-2011 / 2019

标准范围：规定卫星定位系统车载终端与监管/监控平台之间的通信协议与数据格式，包括通信连接、消息处理、报文格式、编码（含 BCD 时间、经纬度 1/10⁶、位图等）、加密机制及数十类终端/平台消息（注册鉴权、心跳、定位、报警、多媒体、电话、区域路线、行驶记录仪等）。

2019 版相对 2011/2013 的主要演进（结合代码）：终端手机号由 BCD[6] 扩展到 BCD[10]；新增查询服务器时间（0x0004/0x8004）、链路检测（0x8204）、查询区域或路线数据（0x8608/0x0608）；删除事件报告/提问/信息点播（0x0301/0302/0303、0x8301~8304）等老旧消息；参数体系调整。网关对 2013/2019 帧头长度做自适应处理。

与实现对应：10808 端口、0x7E 分帧/转义/XOR 校验、注册鉴权心跳、0x0200 定位与附加项、多媒体 0x08xx/0x88xx、文本 0x8300 等均为该标准落地（消息清单见 4.1.2）。

6.3 JT/T 809-2011 / 2019

标准范围：规定平台与平台之间（企业平台↔政府/上级平台）的数据交换协议：基于 TCP 的主从连接、登录/连接保持/校时、车辆动态信息交换（定位、北斗/GNSS 数据）、报警、电子运单、车辆单向/双向值守、查岗、下发指令等业务类型与子业务类型编码。

关键结论：vps 代码中没有 JT/T 809 的服务端或客户端实现（无 809 链路、登录握手、业务类型编解码）。WarnInfo 的 fromSource=11（JT809）只是为多来源预留的枚举。苏标第 3 部分第 5 章在 809 框架上扩展了“主动安全报警附件目录请求/应答”（子业务 0x9404/0x1404，上级平台可凭文件 URL 以 FTP 下载附件），vps 亦未实现该平台间交换。若 mydbd 需向政府监管平台联网，属另行建设范围。

6.4 JT/T 1076 / 1077-2016

  • JT/T 1076-2016 车载视频终端技术要求：规定终端的组成、功能（视音频采集/编码/存储/传输、通道划分 0–37 与特殊通道、报警联动、参数配置）、性能与安装。1078 的“逻辑通道号”即引用 1076 的通道表；苏标将 64/65 分配给驾驶辅助与驾驶员监测摄像头。
  • JT/T 1077-2016 车载视频平台技术要求：规定平台的功能（实时监控、历史回放、录像存储、报警、设备管理、用户与权限等）与性能指标，是平台侧建设依据。vps 只承担接入与媒体转发，不含 1077 描述的平台业务功能（由上层业务平台实现）。

6.5 JT/T 1078-2016

标准范围：在 JT/T 808 信令通道之上扩展车载视频通信：实时音视频传输请求/控制（9101/9102）、状态通知（9105）、远程录像回放（9201/9202）、资源列表查询（9205/1205）、文件上传（9206/1206/9207）、云台控制（9301–9306）、终端音视频属性（1003）、乘客流量（1005）；规定 RTP 负载封装、音视频参数（H.264/H.265、音频编码）与逻辑通道号规则。

与实现对应：vps-video 实现终端 RTP over TCP 收流（10780/10781/10782）并向浏览器转 FLV over WebSocket（20780/20781/20782）；信令经 18001 REST 触发（9101/9102/9201/9202/9205）。两点超出标准的工程化扩展：①浏览器侧 FLV/H265 封装为私有增强（标准面向终端 RTP，不管浏览器）；②对讲浏览器上行 PCM 640B/帧为自定义约定。

7. 实现备注与局限（对接前必须知悉）

  1. 无上线事件：只有离线 Topic；上线需用鉴权成功/首条心跳近似，或改造新增。
  2. 校验失败不丢包：XOR 校验失败仅记日志后继续处理，弱网/异常终端可能送入脏数据。
  3. 白名单强耦合：车辆必须先在 vps_base_truck 登记（手机号），否则注册即拒；truckId 为网关内 Integer 主键，下游需建立 truckId↔本平台车辆/终端标识的映射。
  4. 附件存储仅本地盘：无 MinIO/OSS 抽象（storeType 固定 “local”），文件服务 URL 指向其自身 18009；多实例/容器化需解决卷共享与 URL 可达性。
  5. 附件进度仅内存：Caffeine 30 分钟，文件服务重启丢失传输上下文。
  6. 未启用项：jt808_media_topic（GpsMedia）为死代码；clearSession 无调用方；9206/9207 无入口；0x0900 上行透传无业务消费；大量 8103/8500/86xx/87xx/93xx 仅编解码。
  7. 视频流无鉴权：WS URL 持有者可拉流，需外层补令牌/时效与网络隔离。
  8. 同步指令的时延假设：REST 指令默认 5 秒同步等终端应答，终端离线/弱网会直接失败，调用方需有超时与重试策略。
  9. 单位与坐标系：speed 为 m/h、mileage 为米，下游须换算；坐标为终端原始卫星坐标（通常 WGS-84/北斗），参考 StarRocks 表另列高德(gc)/百度(bd)坐标，说明坐标纠偏由下游负责。
  10. 安全配置：数据库口令明文存放于配置文件，部署需外置并收敛分发范围。
