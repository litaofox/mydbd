系统功能使用手册

文档编号：USER-DBD-001|版本：v1.0.0|更新日期：2026-10-05

本手册面向调度坐席、安全管理员、车队队长、系统管理员等业务用户，介绍北斗导航数据业务平台每个页面"是干什么的、谁来用、怎么操作、要注意什么"。全部操作步骤均以 2026-10-05 的线上系统为准。功能清单与建设规划见 FUNC-DBD-001 功能清单与建设规划。

阅读建议：第一次使用请先看完第一章「5 分钟快速上手」并跟着操作一遍；日常工作中可直接从左侧目录跳转到对应功能。

一、5 分钟快速上手

本平台面向营运车辆的北斗监控与安全风险处置：车辆位置与报警实时上图，平台自动识别风险并驱动"预警 → 工单 → 干预 → 闭环"，同时沉淀驾驶评分与风险画像。演示/培训环境可用内置样例数据在 5 分钟内走完全流程。

① 登录平台
打开系统地址，用 admin/admin123 或四省测试账号登录，需要时输入二次验证码
② 加载样例数据
系统管理 → 系统参数，点"加载标准测试集"，并打开模拟器开关
③ 看实时监控
打开"实时导航监控"或"监控总览大屏"，车辆位置秒级刷新
④ 查报警
打开"终端报警中心"，点开报警详情核实并确认、解除
⑤ 办工单
打开"处置工单"，认领、分派、记录干预并闭环
演示/培训环境
样例数据从哪里来？
系统管理 → 系统参数页面顶部的"测试数据与模拟器"卡片：可一键加载 4 公司 / 10 车队 / 500 车的标准测试集，打开模拟器后约每 15 秒产生新的轨迹与报警。
所有用户
看到的数据为什么"是昨天的"？
样例数据的定位时间（数据时基）可能滞后当前墙钟十几小时，这是正常现象。平台的"在线"判定以最新定位时间为基准，而不是你电脑上的当前时间。
所有用户
菜单为什么和同事不一样？
左侧菜单与按钮均按角色权限与数据范围显示，只能看到自己有权访问的功能和归属范围内的车辆。

二、登录与账号

2.1 这个页面能做什么

登录页是进入平台的唯一入口，支持账号密码登录、登录二次验证（MFA），并在页面下方提供测试账号一键填充，方便演示与培训。

2.2 谁会用

所有用户。新账号由超级管理员在"用户管理"中创建。

2.3 操作步骤

  1. 浏览器打开平台地址，进入登录页（登录页已默认填好 admin / admin123）。
  2. 输入或在下方"测试账号"区点击账号自动填充用户名与密码，点击登录。
  3. 若账号开启了二次验证，页面出现验证码输入框，打开身份验证器 App 获取 6 位动态码，填入后点确认完成登录。
  4. 登录成功后进入实时导航监控页；登录态失效时会自动跳回登录页，重新登录即可继续。

2.5 注意事项

  • 连续输错密码可能导致账号被锁定，需联系管理员在"用户管理"中解锁。
  • 测试账号仅供演示与联调使用，正式环境请修改默认密码并按人建号。
  • 登录、登录失败、MFA 验证等动作都会记入操作审计。

三、实时监控

实时监控域回答"此刻车队在发生什么"：车辆在哪、是否在线、报了什么警，一屏掌握。

3.1 监控总览大屏

用途：投墙值守的全屏驾驶舱，中央是实时车辆地图与风险热力，四周是在线率、今日里程、工单积压、报警态势、最新报警滚动条、车队/区域 TOP8、风险飘条等分区。

谁会用：调度监控员、安全管理员、值班领导。

进入大屏
侧边栏 实时监控 → 监控总览大屏（独立全屏页，无侧边栏）
看态势
车辆位置每秒刷新，统计分区每 30 秒校正
点单车
点击地图车辆图标查看简要信息
全屏 / 退出
右上按钮切换全屏；点"退出大屏"返回系统
🖥️
菜单路径：实时监控 → 监控总览大屏（路由 /dashboard）
1920/4K 自适应；在线率统计窗口为最近 5 分钟有定位的车辆。

注意事项：

  • 大屏是纯展示页面，确认报警、办工单等处置操作请回到对应业务页面。
  • "今日里程"为里程表差值的近似口径，逐点精确里程在后续版本提供。
  • 在线率以"最近 5 分钟有定位点"判定；样例数据时基滞后时，大屏按数据时基而非墙钟展示。

3.2 实时导航监控

用途：日常值守主工作台：Leaflet 地图上实时显示全部可见车辆，支持搜索、筛选、跟踪、查看车辆详情，并通过 WebSocket 秒级刷新位置与弹窗提示新报警。

谁会用：调度监控员（主要使用者）、车队长、安全管理员。

操作步骤

  1. 侧边栏 实时监控 → 实时导航监控进入，地图自动加载归属范围内的车辆。
  2. 左上角车辆树中用搜索框按车牌查找；用筛选条件（组织、在线状态等）缩小范围；点"展示设置"选择树上显示的字段。
  3. 顶部"在线判定窗口"下拉可切换 10 / 30 / 60 / 1440 分钟（默认 10 分钟）：最新定位时间距"平台数据时基"在窗口内的车辆计为在线。
  4. 点击顶部状态统计格（在线/离线/报警等数量）可勾选只看某一类车辆。
  5. 左键点地图车辆图标弹出信息气泡：显示车牌、速度、方向、定位时间，气泡内提供"轨迹回放""车辆详情"等按钮，"视频/对讲/拍照"为预留按钮（暂不可用）。
  6. 右键点车辆弹出菜单：车辆详情、开始跟踪等；跟踪状态下地图会跟随该车辆移动。
  7. 右上"地点搜索"可按地名定位地图视角。
🖥️
菜单路径：实时监控 → 实时导航监控（路由 /monitor，登录后默认首页）
左侧车辆树 + 顶部筛选/统计 + 中央地图 + 车辆气泡。

重要口径：在线/离线以平台数据时基（全局最新一个定位点的时间）为参照，不是本机墙钟。当样例数据滞后墙钟十几小时时，车辆不会因此全部显示离线；不要用"现在几点"去判断在离线。

注意事项：

  • 位置每秒自动推送，无需手动刷新；网络波动时自动重连。
  • 树上和地图上只出现你数据范围内的车辆；范围外的车牌即使知道车牌也搜不到。
  • "视频""对讲""拍照"按钮为 JT/T 1078 对接预留，当前点击仅提示功能预留。

3.3 历史轨迹回放

用途：选定车辆和时间段，在地图上回放历史行驶轨迹，支持多倍速与时间轴拖动，用于核实行驶路线、停留点与报警时的现场情况。

谁会用：调度监控员、安全管理员、车队长。

操作步骤

  1. 侧边栏 实时监控 → 历史轨迹回放。
  2. 在车辆选择框中输入车牌搜索并选中车辆（列表同时显示终端标识 identityCode，避免同车牌混淆）。
  3. 选择开始时间与结束时间，点击查询，地图绘制轨迹并列出轨迹点。
  4. 用播放控件开始回放：速度支持 1 / 2 / 4 / 8 倍速；拖动时间轴滑块可快速定位到任意时刻。
🖥️
菜单路径：实时监控 → 历史轨迹回放（路由 /playback）
顶部选车 + 起止时间 + 查询；底部播放控制条。

注意事项：

  • 从其他页面跳转时可携带车牌、终端标识与日期参数，页面会自动发起查询。
  • 时间范围过大、轨迹点过多时加载变慢，建议单次查询不超过数小时。
  • 只能回放归属范围内车辆的轨迹，越权查询无结果。

3.4 终端报警中心

用途：终端上报报警（超速、疲劳、紧急求助、设备故障等）的集中处理台：四张 KPI 卡概览态势，列表实时更新，每条报警可查看详情（含小地图与前后 30 分钟关联风险），并完成"确认 → 解除"闭环。

谁会用：调度监控员（一线处置）、安全管理员（督办）。

操作步骤

  1. 侧边栏 实时监控 → 终端报警中心。
  2. 页面默认查询今日 00:00 ~ 23:59 的报警；点"重置"也会回到今日窗口。需要查历史报警时手动改时间范围。
  3. 用顶部筛选（车牌、报警类型、等级、状态、时间）过滤列表；新报警实时置顶。
  4. 点击任意一行打开详情抽屉：查看报警位置小地图、车辆信息，以及报警时刻前后各 30 分钟内的关联风险事件。
  5. 核实后点确认，报警状态变为处理中，表示已有人接手。
  6. 处置完成后点解除：选择解除结论——属实（00）/ 误报（01）/ 未知（02），可填写不超过 200 字的说明，提交后闭环。
  7. 详情抽屉中的"监控""轨迹"快捷按钮可直接跳到实时监控或该时段轨迹回放。
🖥️
菜单路径：实时监控 → 终端报警中心（路由 /alarms）
四张 KPI 卡 + 筛选条 + 报警列表 + 右侧详情抽屉。

默认只显示今日（按墙钟自然日）报警。演示数据时基若不在今天，列表会是空的，属正常现象——把开始时间改到样例数据日期（如 2026-10-03）即可看到数据。

注意事项：

  • 两人同时处理同一条报警时，后提交者会收到状态变化提示，刷新后按最新状态操作即可。
  • 确认与解除操作均写入审计日志，请勿随意点选。
  • 报警类型名称与等级由数据字典翻译；若出现"类型 + 数字编码"，说明该类型尚未维护字典，请联系管理员。

四、风险预警与处置

本域回答"风险如何变成一件被管到底的事"：规则引擎产出风险事件 → 自动/手动建工单 → 分派与干预 → 闭环留痕。

4.1 风险预警分析

用途：平台风控规则引擎（CEP）与外部信号产出的全部风险事件的分析台：四张 KPI 卡加"感知 → 预警 → 干预 → 闭环"漏斗，支持多维度筛选，并可对未建工单的事件直接发起处置。

谁会用：调度监控员、安全管理员。

操作步骤

  1. 侧边栏 实时监控 → 风险预警分析。
  2. 通过顶部条件筛选：事件来源（DSM / ADAS / 国标报警 / 厂商上报 / 北斗等）、风险等级、处理状态、命中规则、车牌。
  3. 查看顶部四张 KPI 卡与漏斗各环节数量，判断事件在哪个环节积压。
  4. 列表中含视频分析任务相关事件（占位上报链路）；对需要处置的事件点去处理，系统创建处置工单并自动打开工单详情抽屉。
🖥️
菜单路径：实时监控 → 风险预警分析（路由 /risk）
KPI 卡 + 漏斗图 + 筛选条 + 事件列表。

注意事项：

  • 大部分风险事件在入库时已自动建工单，"去处理"主要用于未建单或需补单的事件。
  • 事件等级由规则配置决定；对判定有异议时，先在工单中处置，事后可由管理员调整规则。

4.2 处置工单

用途：风险事件的处置台账，按"待处理 → 处理中 → 已闭环"状态机流转，支持认领、分派、转派、SLA 时限与超时升级，并在工单内记录电话提醒、安全教育等干预动作。

谁会用：调度监控员（认领、处置、闭环）、安全管理员/主管（分派、转派、重开）、车队长（查看本企业工单）。

列表页操作

  1. 侧边栏 实时监控 → 处置工单。
  2. 顶部六张统计卡：待处理、处理中、超时、已升级、今日闭环、平均闭环分钟，点击卡片可快速过滤。
  3. 筛选条件支持：状态、时限档位（临期 / 已超时 / 已升级）、负责人、车牌、时间等。
  4. 右上角 SLA 配置按钮可调整处置时限；注意：新时限只对修改后新建的工单生效，存量工单时限不变。
  5. 对待处理工单点认领即成为负责人，状态转为处理中。
  6. 点击任意一行打开 780px 宽的工单详情抽屉。

工单详情抽屉操作

  1. 顶部状态条展示当前状态、剩余/超时时间与负责人。
  2. 查看事件快照（事件类型、等级、车牌、位置、时间）与处置信息。
  3. 在干预记录区点新增：选择干预方式——电话提醒 / 安全教育 / 停运 / 处罚 / 其他，填写干预结果后保存。干预记录只可追加，不可修改删除。
  4. 用工单操作按钮完成流转：认领 / 分派（指定负责人）/ 转派。
  5. 处置完成后点闭环：选择五种闭环结果之一，并填写 10 ~ 255 字的处置说明。
  6. 闭环后如发现处置不当，主管可执行重开，工单回到处理中。
  7. 底部流转时间线完整展示建单、分派、干预、闭环、重开的每个节点与操作人。
🖥️
菜单路径：实时监控 → 处置工单（路由 /risk/orders）
六张统计卡 + 筛选条 + 工单列表；点行打开右侧 780px 详情抽屉。

注意事项：

  • 超过 SLA 时限未闭环的工单自动标记超时并按策略升级，请优先处理"临期/已超时"工单。
  • 闭环说明少于 10 字或多于 255 字无法提交。
  • 工单关闭不代表事件消失：事件、工单、干预记录长期保留并汇入画像统计。

4.3 风控规则配置

用途：维护平台实时风控规则：超速、疲劳驾驶、信号类报警等，可启停规则、调整阈值与冷却秒数；规则决定了风险事件如何产生、等级如何判定。

谁会用：安全管理员、超级管理员（普通坐席只读或不可见）。

操作步骤

  1. 侧边栏 系统管理 → 风控规则。
  2. 按规则类型（SPEED 超速 / FATIGUE 疲劳 / SIGNAL 信号类等）浏览规则列表。
  3. 用行内启停开关临时停用/启用规则；编辑阈值参数与冷却秒数（同类事件在冷却期内不重复产生）。
  4. 需要纳入驾驶评分的事件码在"评分白名单"中维护，如 SPEED_GENERAL、SPEED_SEVERE、FATIGUE_DRIVE、DSM_FATIGUE、DSM_DISTRACTION、ADAS_FCW、ADAS_LDW、COMBO_FATIGUE_SPEED。
🖥️
菜单路径：系统管理 → 风控规则（路由 /system/rules）
规则类型筛选 + 规则列表 + 启停开关/编辑对话框。

注意事项：

  • 内置规则不可删除，只能停用或调整参数。
  • 修改即时生效，只影响之后新产生的事件，不追溯历史。
  • 调大冷却秒数会减少提醒量但可能漏报，调整请结合值守人力评估。

4.4 电子围栏

用途：在地图上画出圆形或多边形区域，车辆进入、离开或进出围栏时自动产生报警事件，用于禁区管理、场站到离管理。

谁会用：安全管理员、调度监控员。

操作步骤

  1. 侧边栏 系统管理 → 电子围栏，点新建围栏。
  2. 选择围栏形状：圆形（选中心点 + 半径）或多边形（在地图上依次点选顶点，至少 3 个顶点后闭合）。
  3. 填写名称，选择触发方向：进入 / 离开 / 进出均触发；选择报警等级与冷却时间。
  4. 保存后围栏立即生效；列表中可停用、编辑或删除围栏。
🖥️
菜单路径：系统管理 → 电子围栏（路由 /system/fences）
围栏列表 + 地图绘制对话框（基于 PostGIS 空间判定）。

注意事项：进出判定依赖定位上报频率，定位稀疏时触发时刻会有延后；围栏报警同样进入风险预警与工单链路。

五、主数据管理

组织、车辆、终端、驾驶员是所有业务的"地基"。建议维护顺序：组织架构 → 车辆/终端/驾驶员档案 → 绑定关系。数据归属、权限范围、通知对象、评分统计全部依赖这些档案。

5.1 组织架构

用途：维护运输企业与车队的多级组织树，它是数据权限的骨架——"车队长看本企业、坐席看本部门"都靠组织挂接实现。

谁会用：超级管理员、安全管理员。

操作步骤

  1. 侧边栏 主数据管理 → 组织架构。
  2. 左侧组织树选中一个节点，右侧展示该节点详情；点新增下级可建企业或车队两类节点。
  3. 编辑名称、联系人等信息后保存；调整层级在树上拖动或编辑上级节点。

注意事项：

  • 组织分企业 / 车队两类，车辆最终挂接在组织节点上。
  • 节点下仍有车辆或下级组织时不能删除，请先迁移车辆与子节点。
  • 数据可见范围一律以车辆归属组织为准，与车牌是哪个省份的无关（公司名下可挂任意外省车牌）。

5.2 车辆档案与绑定管理

用途：车辆台账的增删改查（车牌、车牌颜色、车型、运输性质、所属组织、注册城市等），并在车辆档案内集中维护"车-终端""车-主班/副班司机"的绑定关系与绑定历史。

谁会用：车队长（本企业档案）、安全管理员、超级管理员。

车辆档案操作

  1. 侧边栏 主数据管理 → 车辆档案。
  2. 按车牌、所属组织等条件筛选；点新增录入车辆信息并选择归属组织，保存。
  3. 对已有车辆可编辑、置失效；列表点行进入车辆详情。

绑定管理操作

  1. 在车辆详情中点绑定管理打开绑定弹窗。
  2. 分别维护三类关系：车 — 终端、车 — 主班司机、车 — 副班司机；选择对象后绑定，系统记录生效时间。
  3. 换设备/换司机时对原关系执行解绑，再绑定新对象；弹窗内可查看完整绑定历史。
🖥️
菜单路径：主数据管理 → 车辆档案（路由 /mdm/vehicles）→ 详情 → 绑定管理
车辆列表 + 详情抽屉 + 绑定管理弹窗（车-终端 / 车主班 / 车副班 / 绑定历史）。

注意事项：

  • 车牌号全局唯一，重复录入会被拒绝。
  • 同一终端、同一司机同一时间只能绑定一辆车，重复绑定会被拒绝。
  • 解绑不影响历史数据：历史报警与轨迹按事件发生当时的绑定关系归集。
  • "失效"车辆不再参与在线率等统计，历史数据保留可查。

5.3 终端档案

用途：北斗终端设备台账：终端编号（identityCode）、设备型号、协议类型、SIM 账号、视频通道数、启用状态等，是终端接入与后续指令下发的基础。

谁会用：安全管理员、运维人员、超级管理员。

操作步骤

  1. 侧边栏 主数据管理 → 终端档案。
  2. 点新增录入终端编号、型号、协议类型（JT808 / JT1078 / 其他）、SIM 账号等信息保存。
  3. 更换终端时先在车辆档案中解绑旧终端、绑定新终端；不再使用的终端置停用。

注意事项：终端编号全局唯一；终端与车辆是多对多的历史关系，当前是否在用车以绑定关系为准。

5.4 驾驶员档案

用途：驾驶员信息台账：姓名、驾驶证类别、从业资格证、联系电话、状态等。风险要落到"人"，评分、画像、干预通知都依赖司机档案。

谁会用：车队长、安全管理员。

操作步骤

  1. 侧边栏 主数据管理 → 驾驶员档案。
  2. 点新增填写司机信息保存；支持按姓名、所属组织筛选与编辑。
  3. 在车辆档案"绑定管理"中把司机绑定为主班或副班后，该司机即参与评分与画像统计。

注意事项：手机号等联系方式仅授权人员可见；司机不再上岗时置停用即可，历史评分保留。

六、分析决策

6.1 驾驶评分

用途：基于超速、疲劳、急加减速、分心等风险事件，为车辆/司机周期性计算 0~100 的安全分与 A~E 风险等级，支持手动重算与下钻查看 30 天趋势及扣分明细。

谁会用：安全管理员、车队长、企业管理层。

操作步骤

  1. 侧边栏 分析决策 → 驾驶评分。
  2. 顶部四张卡展示近 7 天均分等概览指标。
  3. 用日期、司机、车牌、等级筛选记录；点击重算可对指定时间范围发起异步重算（单次跨度最多 92 天），完成后刷新查看。
  4. 点击列表任意一行打开详情抽屉：查看该对象近 30 天评分趋势与特征扣分明细。
等级 A
≥ 90 分
等级 B
75 ~ 89 分
等级 C
60 ~ 74 分
等级 D
40 ~ 59 分
等级 E
< 40 分

评分口径（了解即可）：高风险事件扣 8 分、中风险扣 4 分、低风险扣 2 分；急加减速单次扣 0.5 分且次日封顶 5 分；为避免小样本失真，样本不足（少于 200 个定位点或 30 分钟行驶）的周期不出分。被工单以"误报"闭环的事件不扣分。

6.2 风险趋势与画像

用途：从"处理今天的事"升级到"看清长期的势"：按全网/企业/司机/车辆查看风险趋势，按车辆/司机/企业查看画像（处置漏斗、评分曲线、事件构成 Top6、工单 Top5）。

谁会用：安全管理员、企业管理层。

操作步骤

  1. 侧边栏 分析决策 → 风险趋势与画像。
  2. 选择时间范围：近 7 天 / 近 30 天 / 近 90 天 / 自定义。
  3. 趋势分析页签：选择维度（全网 / 企业 / 司机 / 车辆）与粒度（日 / 周 / 月）查看趋势曲线。
  4. 对象画像页签：选择对象类型（车辆 / 司机 / 企业）并指定具体对象，查看处置漏斗、评分曲线、事件构成 Top6、关联工单 Top5。
🖥️
菜单路径：分析决策 → 风险趋势与画像（路由 /analysis/profiles）
时间范围选择 + 两个页签（趋势分析 / 对象画像）。

注意事项：趋势结论依赖数据积累，上线初期样本少，建议以周/月为单位观察；画像为只读分析，不修改任何数据。

七、系统管理

7.1 用户管理

用途：管理登录账号：新建用户、编辑、分配角色、重置密码、解锁、停用/启用、修改登录口令。

谁会用：超级管理员（安全管理员可按授权管理部分账号）。

操作步骤

  1. 侧边栏 系统管理 → 用户管理。
  2. 点新增：填写用户名、姓名、初始密码，勾选所属组织与角色后保存。
  3. 对已有用户可：编辑资料、分配角色、重置密码、账号被锁时解锁、离职时停用、必要时修改登录口令。

注意事项：

  • admin 超级管理员为系统保护账号，不可删除、不可停用。
  • 重置密码、解锁等敏感操作均写入审计日志。
  • 建议一人一号，离职及时停用，不要多人共用账号。

7.2 角色管理

用途：维护角色及其菜单权限、按钮权限与数据范围。系统内置四个角色，也可新建自定义角色。

谁会用：超级管理员。

操作步骤

  1. 侧边栏 系统管理 → 角色管理。
  2. 新建角色或编辑现有角色：在权限树中勾选菜单与按钮权限。
  3. 设置数据范围：1 全部数据 / 按企业及下级 / 按部门树 / 仅本部门 / 5 自定义部门集合。
  4. 保存后，拥有该角色的用户下次操作即按新权限校验。

注意事项：内置角色（超级管理员、安全管理员、调度监控员、企业车队长）不可删除；数据范围默认强制、失败即拒绝（fail-closed），配置自定义范围时请确保至少勾选一个部门。

7.3 操作审计

用途：自动记录谁在什么时间、从哪个模块、做了什么动作、结果如何，是事后定责与合规检查的第一手证据。页面提供统计卡、多维检索与详情抽屉。

谁会用：超级管理员、安全管理员（只读）。

操作步骤

  1. 侧边栏 系统管理 → 操作审计。
  2. 顶部 4+1 张统计卡概览操作量；用日期、账号、模块、动作、结果、关键字组合筛选。
  3. 点击记录行打开详情抽屉，查看请求参数与结果信息。

注意事项：审计记录只读，任何人（含管理员）不可修改或删除；密码等敏感字段自动脱敏。

7.4 数据字典

用途：统一维护业务枚举（报警类型、车辆颜色、车牌颜色等），页面下拉与列表翻译都从字典取值，避免口径写死在代码里。

谁会用：系统管理员、安全管理员。

操作步骤

  1. 侧边栏 系统管理 → 数据字典。
  2. 页面为左右双栏：左侧选字典类型，右侧维护该类型下的字典项（值、名称、排序、启停）。
  3. 新增字典项保存后，相关页面的下拉与翻译立即生效。

注意事项：字典项在（类型 + 值）上有唯一约束，重复保存会被拒绝；停用字典项只会让它不再出现在新数据的可选项中，不影响历史展示。

7.5 系统参数与测试数据

用途：一页管两件事——顶部是"测试数据与模拟器"卡片（演示/培训/联调用），下方是系统参数键值表（在线窗口等全局可调项）。

谁会用：超级管理员、演示/培训人员；系统参数调整通常由管理员执行。

加载测试数据（5 分钟快速上手第 ② 步）

  1. 侧边栏 系统管理 → 系统参数，找到顶部"测试数据与模拟器"卡片。
  2. 点加载标准测试集：约 115 万轨迹点（30 秒一点，96 起风险事件，4 公司 / 10 车队 / 500 车），加载需 4~5 分钟，加载前会先清空现有业务数据。
  3. 需要更密数据时点加载稠密测试集：约 330 万点（15 秒一点，192 起事件），约需 12~15 分钟。
  4. 打开模拟器开关后，系统约每 15 秒产生实时轨迹、终端报警与风险事件；停止时点开关并确认即可（已产生数据保留）。
  5. 需要重置时点清空业务数据：清除公司/车队/车辆/终端/司机/轨迹/报警/事件/工单/干预/评分，但保留账号、角色、菜单与系统参数。

维护系统参数

  1. 在下方参数键值表中找到目标参数（如在线判定窗口分钟数），编辑取值保存。
  2. 参数修改立即影响后续口径，请谨慎调整并知会相关岗位。
🖥️
菜单路径：系统管理 → 系统参数（路由 /system/config）
页面顶部"测试数据与模拟器"卡 + 下方系统参数键值表。

加载标准测试集与清空业务数据都会改变现有业务数据，正式环境严禁操作；演示环境操作前也请确认数据不再需要。

7.6 消息中心

用途：站内通知统一查阅处：风险预警、工单分派、处置进展等消息在此汇集，顶栏铃铛显示未读数。

谁会用：所有用户（各自只收到与自己相关的消息）。

操作步骤

  1. 点顶栏铃铛，或侧边栏 系统管理 → 消息中心。
  2. 用"全部 / 未读"页签过滤；点全部已读一键清未读。
  3. 点击工单类消息行可直接打开对应工单（openOrder 跳转）；不需要的消息可单条删除。

注意事项：短信、语音、App 推送为预留通道，当前仅站内消息与实时弹窗生效；消息按角色与工单负责人定向发送。

8.2 数据权限两条硬规则

  1. 默认强制、失败即拒绝（fail-closed）：所有查询、推送、异步任务都按数据范围装载数据；权限解析失败时按"看不到"处理，不放开。
  2. 以车辆归属组织为准，不按车牌省份过滤：公司名下可以挂任意外省车牌，只要车辆归属组织在你的范围内，你就能看到它的位置、报警、工单与评分；车牌首字、省份代码仅作档案展示，绝不作为权限条件。

九、常见问题

问题解答
登录时要求输入"验证码/动态码"？该账号开启了登录二次验证（MFA）。打开绑定的身份验证器 App，把当前 6 位动态码填入即可；换设备后请联系管理员重置 MFA。
账号被锁定怎么办？多次密码错误会触发锁定。联系超级管理员在"系统管理 → 用户管理"中对你的账号执行解锁。
为什么我看不到某个菜单/按钮？菜单与按钮按角色权限显示。联系超级管理员在"角色管理"中为角色勾选对应权限，或为你分配其他角色。
明明知道车牌，为什么搜不到车？数据范围以车辆归属组织为准。该车不在你的数据范围内时，搜索、地图、接口均不可见，这是数据权限的正常表现，不是故障。
监控页车辆怎么全"离线"了？先确认顶部在线判定窗口；平台以"平台数据时基（最新定位时间）"而非墙钟判定在线。若模拟器已关闭或数据时基停滞，车辆会陆续转为离线——重新打开模拟器即可。
报警中心列表为什么是空的？列表默认只查"今日 00:00~23:59"（按墙钟）。样例数据日期不在今天时，请手动把开始/结束时间改到样例数据所在日期后再查询。
报警处理时提示"状态已变化"？另一位同事已先行确认或解除了该报警。刷新列表查看最新状态即可，避免重复处置。
工单闭环提交不了？闭环必须选择结果且说明在 10~255 字之间；请补充完整处置说明后再提交。
车辆详情显示"未绑定"？该车尚未关联终端或驾驶员。到"主数据管理 → 车辆档案 → 绑定管理"完成绑定后，监控归属与统计即生效。
今天的驾驶评分怎么还没有？评分按周期批量计算，且样本需达到 200 个定位点 / 30 分钟行驶门槛，样本不足不出分；需要时可在驾驶评分页发起"重算"（跨度最多 92 天）。
误报事件会影响司机评分吗？不会。对应报警在报警中心以"误报（01）"解除、或工单以误报闭环后，该事件不参与扣分。
监控气泡里的"视频/对讲/拍照"能点吗？这些是 JT/T 1078 视频对接的预留按钮，当前版本点击仅提示预留；实时视频能力在后续版本提供。
分析决策里的 19 个报表点不开数据？这些节点（13 项报表查询 + 6 项统计分析）已挂菜单占位，当前显示"功能建设中"，属于规划功能，详见 MOD-DBD-017。
加载测试集/清空数据点错了怎么办？加载标准测试集会先清空业务数据再灌入样例；清空操作需要二次确认。正式环境严禁使用这些按钮；一旦误操作，只能从数据库备份恢复。
