平台接口手册

编号 API-DBD-001|版本 v1.3.0|发布日期 2026-10-06|事实基准：2026-10-06 源代码

本手册覆盖平台全部对外 HTTP 端点与 WebSocket 实时通道：Java 平台 28 个 Controller 共 142 个端点、Python 处理服务 6 组共 17 个端点、WebSocket 1 个通道 4 类消息。每个端点的方法、路径、权限标识与参数均逐字取自控制器源码，分组标题下给出源码文件与类级 @RequestMapping 路径。阅读前请先看第 1 章通用约定。

1 通用约定

1.1 基址与 /api 前缀路由分工

Java 控制器的路径全部以 /api 开头（健康检查 /health 除外），应用本身没有配置 servlet context-path（见 platform-boot/src/main/resources/application.yml，仅设 server.port: 8080）。/api 前缀逐字写在每个控制器的 @RequestMapping 上。三端端口与分工如下（事实源 infra/nginx/portal.conf、docker-compose.yml）：

入口端口location 前缀（portal.conf 逐字）转发目标
门户 nginx8090/（Vue3 SPA 静态资源，try_files 回退 index.html）本地 /usr/share/nginx/html
门户 nginx8090/api/simulator/、/api/ingest/http://processing-app:8000
门户 nginx8090/api/analysis/score/、/api/analysis/profile/（更长前缀，优先匹配）http://platform-app:8080
门户 nginx8090/api/analysis/（其余）http://processing-app:8000
门户 nginx8090/api/gateway/（网关状态/媒体内部接口，X-Service-Token 鉴权，供服务间/运维直连；前端经 Java /api/monitor 中转）http://processing-app:8000
门户 nginx8090/ws/（HTTP/1.1 Upgrade 长连接，proxy_read_timeout 3600s）http://platform-app:8080
门户 nginx8090/api/（兜底）http://platform-app:8080
Java 平台直连8080Spring Boot 单体（platform-app），承载除上述 Python 前缀外的全部 /api/** 与 /ws/realtime
Python 服务直连8000FastAPI（processing-app），路由前缀 /api/simulator、/api/ingest、/api/analysis、/api/gateway（后两者服务令牌鉴权），另有裸路径 /health

本地开发时前端跑在 Vite 5173，frontend/vite.config.ts 的代理顺序与 nginx 一致：/api/simulator、/api/ingest、/api/analysis → localhost:8000，其余 /api → localhost:8080。

nginx client_max_body_size 220m；/api/simulator/、/api/ingest/、/api/analysis/ 的 proxy_read_timeout 为 300s，Java 与 /ws/ 分别为 120s / 3600s。

1.2 统一响应结构（Java）

Java 端除 /health 外全部返回 Result<T>（源码 platform-common/.../api/Result.java），实际字段只有三个：

{
  "code": 0,              // 0=成功；非 0 见 1.5 错误码表
  "message": "success",   // 成功固定 "success"；失败为具体原因
  "data": { }             // 业务数据；无返回数据时为 null
}

前端 frontend/src/api/http.ts 的 axios 响应拦截器按此解包：code===0 时直接把 data 作为 Promise 结果返回，code!==0 时弹 message 并 reject。前端请求不设 baseURL，全部使用相对路径（经 nginx / Vite 代理）。

Python 处理服务不使用 Result 包装，成功直接返回业务 JSON（如 {"inserted": 12}），失败由 FastAPI 返回 {"detail": "..."}（服务令牌失败为 HTTP 401，请求体校验失败为 HTTP 422）。

1.3 分页结构

分页接口的 data 为 PageData<T>（源码 platform-common/.../api/PageData.java），字段固定为：

{ "total": 123, "page": 1, "size": 10, "records": [ ... ] }
  • 请求参数统一命名为 page、size；page 从 1 开始。
  • 绝大多数接口默认 page=1、size=10；报警分页 GET /api/alarm/page 默认 size=20；GET /api/notify/messages 服务端把 size 截断为最大 100（Math.min(size, 100)）。

1.4 鉴权方式

方式一：登录 JWT（Bearer Token）

除两个白名单接口外，所有 /api/* 请求都被 JwtAuthFilter（注册于 WebConfig，urlPattern /api/*）拦截：

  • 请求头：Authorization: Bearer <token>（前端从 localStorage 的 mydbd-token 读取后附加）。
  • 登录接口：POST /api/auth/login，body {"username","password"}；成功返回 LoginVO：{mfaRequired, token, mfaToken, userId, username, realName}。
  • access 令牌由 JwtUtil 签发，算法显式固定 HS256（signWith(key, Jwts.SIG.HS256)，2026-10-06 前未指定算法时 JJWT 按密钥长度自选，50 字节密钥实际签发 HS384），claims 为 uid + purpose=access，有效期 8 小时，HMAC 密钥取 mydbd.jwt.secret（环境变量 JWT_HMAC_SECRET）。
  • processing-service 浏览器侧接口（/api/simulator/*、/api/ingest/dataset/*）由 app/security.py require_access 用 PyJWT 独立验签同一把 HMAC 密钥，算法白名单 HS256/HS384/HS512（兼容 2026-10-06 前签发的 HS384 存量令牌）；验签失败回 HTTP 401 {"detail":"登录已过期，请重新登录"}，前端拦截器收到 401 会清除令牌并硬跳 /login。
  • 开启 MFA 时登录只拿到 mfaToken（claim purpose=mfa，5 分钟有效），须再调 POST /api/auth/mfa/verify 换取 access 令牌。
  • 白名单（无令牌可访问）仅两个：/api/auth/login、/api/auth/mfa/verify。缺令牌、令牌过期、purpose 非 access、用户不存在/停用一律由过滤器直接回 HTTP 401，body 为 {"code":40101,...}。

功能权限由 @RequiresPerm 注解 + PermAspect 切面校验（源码 platform-common/.../security/）：可标注在类或方法上，方法注解优先；value 支持多权限码，logical 取 AND（默认）或 OR；超级管理员恒放行；不通过抛 40301。本手册表格中：

  • 写权限码（如 mdm:vehicle:edit）表示必须持有该码；
  • 仅登录表示控制器/方法上没有 @RequiresPerm，只要 JWT 通过即可访问；
  • 免鉴权表示不在 JWT 过滤器范围内或位于白名单。

方式二：服务令牌 X-Service-Token（仅 Python 端）

Python 端 app/security.py 校验请求头 X-Service-Token，与配置 settings.service_token（环境变量 SERVICE_TOKEN，默认 change-me-service-token）不等即返回 HTTP 401 {"detail":"服务令牌无效"}。实际挂载位置：

  • POST /api/ingest/traj：方法级依赖 Depends(verify_service_token)；
  • POST /api/analysis/video：路由级依赖，覆盖整个 /api/analysis 路由器。

模拟器控制（/api/simulator/**）、数据集（/api/ingest/dataset/**）与 POST /api/ingest/load-sample、/health 均未挂任何鉴权依赖（simulator.py 代码注释："演示环境开放控制（容器网络边界内）；正式版本需登录态/服务令牌"）。Java 端 application.yml 虽声明了 mydbd.service-token 配置项，但当前没有任何 Java 代码读取或校验它。

方式三：WebSocket 握手带 token

WebSocket 不能自定义请求头，token 放在连接 URL 的查询参数中：ws://<门户主机:8090>/ws/realtime?token=<access JWT>。AuthHandshakeInterceptor 解析 query 中的 token，校验签名且 purpose=access，通过后把 uid、username 写入会话属性；失败直接拒绝握手。详见第 4 章。

1.6 长整型 ID 的字符串序列化约定

数据库主键为 bigint（实体 Long，MyBatis-Plus IdType.AUTO）。为避免 JavaScript Number 精度丢失，项目在对外 VO上用 Jackson @JsonSerialize(using = ToStringSerializer.class) 把 Long id 序列化为字符串，LoginVO 注释明确"userId 为雪花大数，统一以字符串输出"，AlarmVO/VehiclePanelVO/DashboardSummaryVO 注释要求前端全链路按 string 处理。已覆盖的类型包括：LoginVO、UserListVO、UserDetailVO、UserProfile、RoleListVO、RoleDetailVO、OptionRoleVO、AlarmVO、AuditLogVO、SysAuditLog、VehiclePanelVO、DashboardSummaryVO、AssignableUserVO、DriverScore、RiskWorkOrder.id、RiskOrderLog 等。

该约定不是全局 Jackson 配置，逐字段标注，存在以下需要注意的例外（代码现状）：

  • MDM 新建接口 POST /api/mdm/vehicles|terminals|drivers|depts 的 data 直接返回 Long（数字）；IAM 用户/角色、风控规则/围栏新建返回 String。
  • 直接返回实体的接口（Vehicle、Terminal、Driver、Dept、RiskRule、RiskGeoFence、RiskEvent、WarnInfo、GpsPoint 等）其 id 仍以 JSON 数字输出；WebSocket 推送的 RISK/ALARM/POINTS 载荷同样是实体序列化，id 为数字（前端 useRealtime.ts 中即按 number 接收）。
  • 入参侧大 id 可用字符串传递（Spring 自动转为 Long）；评分重算的 driverId 设计为字符串并手动解析。

4 WebSocket 实时通道

源码目录：module-monitor/.../monitor/websocket/（RealtimeWebSocketConfig、AuthHandshakeInterceptor、RealtimeWebSocketHandler、RealtimePushScheduler、SessionRegistry、WsScopeResolver）；前端消费侧 frontend/src/composables/useRealtime.ts。

4.1 连接与握手鉴权

  • 端点路径：/ws/realtime（RealtimeWebSocketConfig 注册，setAllowedOriginPatterns("*")）。
  • 经门户连接：ws://<主机>:8090/ws/realtime?token=<JWT>（HTTPS 页面用 wss://）；直连 Java 为 ws://<主机>:8080/ws/realtime?token=...。nginx /ws/ 已配 Upgrade 头。
  • token 为登录获得的 access JWT（purpose=access）；握手拦截器只解析 URL query 中的 token 参数，缺失/解析失败/purpose 不符均拒绝握手；通过后把 uid、username 写入会话属性。MFA 中间令牌（purpose=mfa）不能用于握手。
  • 同一用户多标签页/多设备允许多会话（SessionRegistry 维护 uid → sessionId 集合）；会话注册为内存态，单机实现。

4.2 消息信封与推送类型

所有推送统一信封：{"type": "<类型>", "data": ...}。服务端共推送 4 类消息：

type方向/时机data 结构与字段
POINTS 服务端 → 客户端；连接建立后立即推一帧位置快照；之后调度器每 1 秒推一次全量最新点（@Scheduled(fixedDelay=1000, initialDelay=5000)） GpsPoint[]，每项字段：id, identityCode, plateNo, gpsTime, lng, lat, speed, direction, altitude, alarmFlag, mileage（id 为 JSON 数字；时间按全局 yyyy-MM-dd HH:mm:ss 输出）

4.3 客户端是否需要发消息

不需要。RealtimeWebSocketHandler.handleTextMessage 方法体为空注释（"单向推送，忽略客户端消息；可扩展为 ping/pong 或订阅控制"）。客户端只需建立连接并接收。前端 useRealtime.ts 的策略：连接失败指数退避重连（上限 30s），断连期间降级为每 5 秒轮询 GET /api/monitor/overview + GET /api/traj/latest，恢复后停止轮询。

4.4 按 deptScope 的数据范围过滤

三类广播消息（POINTS/RISK/ALARM）均通过 SessionRegistry.broadcastScoped 按每个会话各自的范围过滤后发送，DB 全量只查一次；过滤键为车牌（POINTS 取 GpsPoint.plateNo，RISK 取 RiskEvent.plateNo，ALARM 取 WarnInfo.plateNo）。范围由 WsScopeResolver.allowedPlates 依据握手中的 uid 解析：

  • allData=true（全数据用户/超管）：返回 null = 不限制，发送全量；
  • 有部门范围：把 deptScope 部门集合经 DashboardMapper.selectVehicleNosByDeptScope 换成可见车牌集合，仅发送集合内数据；
  • 空集合 = 不可见任何数据，fail-closed 跳过该会话；uid 属性缺失、用户不存在/停用同样按空集合处理（停止推送）。

WS 链路与 HTTP 链路共用 PermissionCache（TTL 120 秒兜底；用户/角色/授权写操作后主动 evict，权限调整实际立即收敛）。NOTIFY 不走范围过滤，本身按接收人 id 定向。

5 联调提示

以下各条均可在仓库代码中直接核实。

5.1 401 / 403 / 404 的语义区分

  • HTTP 401：只由 JwtAuthFilter 在缺 Authorization 头、令牌无效/过期、purpose 非 access、账号不存在/停用时返回，body 为 {"code":40101,"message":...,"data":null}（Content-Type 显式带 charset=UTF-8）。前端拦截器收到 401 会清除 token 并跳转 /login。
  • 业务码 40301 / 40401 / 40901 / 40001 等：HTTP 状态码是 200。BizException 经 GlobalExceptionHandler 翻译为 Result 且未设 @ResponseStatus；参数校验失败（40001）、唯一键冲突（40901）同为 HTTP 200。判断成败必须看 body 的 code，不能只看 HTTP 状态。
  • HTTP 500：未捕获异常，body code=50000。
  • 真正的路径 404（请求了不存在的 URL）：项目没有为"No handler"配置全局 JSON 处理，命中 Spring/Servlet 容器默认 404 页，不是 Result 结构；body 里的 40401 仅表示"业务资源不存在"。
  • Python 端服务令牌失败是真正的 HTTP 401（{"detail":"服务令牌无效"}）；请求体不符合类型注解时由 FastAPI 返回 HTTP 422；路由内主动抛的 400/404/409 同样为 {"detail":...}。

5.2 请求格式与参数命名

  • 带 @RequestBody 的接口要求 Content-Type: application/json；query 参数直接拼接在 URL，注意中文值做 URL 编码。
  • 分页参数固定 page（从 1 起）/ size，不要传 pageNum/pageSize/current。
  • 各接口时间格式不统一，按目标接口传：yyyy-MM-dd HH:mm:ss（轨迹 track、审计日志）、ISO 日期时间（工单 funnel，@DateTimeFormat(iso=DATE_TIME)）、yyyy-MM-dd'T'HH:mm:ss（画像 4 接口）、yyyy-MM-dd（评分）；报警 beginTime/endTime 与工单分页 beginTime/endTime 为字符串，由服务层解析。Jackson 全局输出格式 yyyy-MM-dd HH:mm:ss、时区 Asia/Shanghai。

5.3 长整型 ID 精度

  • 凡 VO 字段经 ToStringSerializer 输出的 id（登录 userId、用户/角色、报警、面板、大屏、审计、可分派人员、评分、工单等），前端一律按字符串存取与比较。
  • 直接返回实体的接口与 WebSocket 实体载荷中 id 仍是 JSON 数字；新建 MDM 档案返回数字 Long，新建 IAM/风控配置返回字符串——跨模块传 id 前先核对本手册表格。

5.4 路由前缀与跨域

  • 经门户联调时，/api/analysis/score/**、/api/analysis/profile/** 在 Java，其余 /api/analysis/**（如 /video）在 Python；新增 analysis 子路径若部署在 Java，必须在 portal.conf 中放在 /api/analysis/ 之前用更长前缀优先匹配。
  • /api/ingest/dataset/** 被 location /api/ingest/ 覆盖到 Python，无需额外配置。
  • Java 侧 CORS 对 /api/** 放开（allowedOriginPatterns("*") + allowCredentials(true)，方法 GET/POST/PUT/DELETE/OPTIONS，预检缓存 3600s）。
  • 请求体上限受 nginx client_max_body_size 220m 约束；长耗时接入/分析接口代理读超时 300s。

5.5 令牌与会话

  • access JWT 有效期 8 小时，无服务端吊销名单（退出登录仅写审计）；令牌泄露在过期前始终有效，靠密钥（JWT_HMAC_SECRET）保密。
  • WebSocket 必须用 access 令牌拼 query；令牌过期后连接不会被服务端主动断开，但重连需取新令牌。
  • 用户/角色/权限写操作会主动清 PermissionCache；其它情况下缓存最长 120 秒收敛。

5.6 脚本调用注意事项

  • 用 PowerShell 调接口时建议显式指定：Invoke-RestMethod -ContentType "charset=utf-8" 并把 body 用 [System.Text.Encoding]::UTF8 编码后发送，避免中文（车牌、备注、闭环说明）以非 UTF-8 字节入库导致乱码；查询串中的中文先 [uri]::EscapeDataString 编码。
  • 调用 Python 服务令牌接口示例头：X-Service-Token: <SERVICE_TOKEN>；令牌错误返回 HTTP 401，而不是 Java 风格的 200+错误码。
  • 模拟器、数据集、样例导入接口当前无鉴权，生产暴露前需自行在网关层收口或补登录态/服务令牌（代码注释已声明这一边界假设）。
