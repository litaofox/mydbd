MOD-DBD-006 终端报警中心

文档编号 MOD-DBD-006|版本 v1.0.0|发布日期 2026-10-05| 状态 已上线|功能编号 F17

事实基准：2026-10-05 源代码（backend-java module-monitor）与初始化 SQL（02-traj-tables.sql、13-alarm-center.sql）

主要代码锚点：AlarmController / AlarmService / WarnInfoMapper / RiskEventMapper.relatedRisks；AlarmQuery / ResolveRequest / AlarmVO / WarnInfo（module-monitor）；前端 views/alarm/AlarmCenter.vue（543 行）、api/alarm.ts

1 功能概述

1.1 模块定位与边界

终端报警中心（F17）是 traj.traj_warn_info 的全量查询与处置闭环工作台：坐席在这里按车牌/类型/状态/时间窗检索终端上报的报警（超速、疲劳驾驶、围栏越界、紧急求助、设备故障等），查看报警起止位置与关联风险事件，并执行"确认 → 解除"两级处置，解除时强制填写结论（属实/误报/未知）。

  • 列表与统计：分页列表（车牌模糊、类型、处置状态、时间段四条件）+ 顶部四张 KPI 卡（今日总数/待处理/已确认/已解除）+ 待处理滚动接口（供大屏与监控页消费）。
  • 详情：报警全字段 + 起止坐标小地图（高德瓦片）+ 同车牌 ±30 分钟关联风险事件前 5 条（跨 schema 直查 mon.risk_event）。
  • 处置闭环：状态机 0 待处理 → 1 已确认 → 2 已解除（允许 0 直接到 2）；条件更新并发冲突返回业务码 45001；处置人自动落当前用户姓名；全程审计留痕。
  • 数据权限：全部端点按当前用户 deptScope 换算的车牌集过滤；详情与处置对"不存在"与"越权"同一口径返回 40401，不泄露存在性。
  • 实时联动：复用 F14 的 WebSocket 通道（P07），新报警 1 秒内弹提示并按条件置顶列表。

一句话边界：本模块只管"终端报警"（traj_warn_info）的看与处。规则引擎产出的"风险事件"（mon.risk_event）在风控模块研判与工单流转；报警的实时推送在 MOD-DBD-005；报警数据的产生（模拟器/数据集/未来 808 网关）在 MOD-DBD-004 与终端接入域。本模块与监控域（/api/monitor/warnings）同读一张表，但职责不同：那里是"最近 100 条速览"，这里是全量分页与闭环。

1.3 术语与概念

术语含义
handle_status 状态机0 待处理 / 1 已确认 / 2 已解除；合法流转 0→1、0→2、1→2；历史 NULL 读取侧 COALESCE 归一为 0（13 号脚本已把存量置 0 并加列默认值 0）。
resultCode 解除结论解除时必填：00 属实 / 01 误报 / 02 未知；resultMsg 可选 ≤200 字。
45001本模块专用的状态冲突业务码（不复用通用 40901）：条件更新影响 0 行即"状态已被他人变更"，文案"报警状态已变更，请刷新后重试"。
grade_level 报警等级base_warn_type 上的着色字段：报警中心与 AlarmVO 注释按 1=红 / 2=橙 / 3=灰 使用；大屏右列图例的口径与之存在差异（见 17 节待核实）。
warn_continue_mark持续标志：0=停止（一次性报警）1=持续（报警仍在发生中）。
关联风险详情附带：同车牌、报警开始时间 ±30 分钟窗口内 mon.risk_event 的前 5 条（事件码/标题/等级/时间），用于判断"这条终端报警是否已被规则引擎升级为风险事件"。
存在性保护详情/确认/解除对"记录不存在"与"不在数据范围内"返回同一个 40401，避免借接口探测范围外报警是否存在。
handler 处置人当前用户 realName（空回退 username，再空回退 "system"），varchar(30) 截断防御；同时写入 updater。

3 操作流程

菜单路径：实时监控一级目录（sys_menu id=10）→ 终端报警中心（菜单 id=16，/alarms，权限点 alarm:view，图标 Bell，sort 9）。处置按钮为按钮级权限点 id=926（alarm:handle）。角色授权（13-alarm-center.sql）：管理员全量；安全管理员与调度监控员 查看+处置；企业车队长 仅查看。前端路由 meta.perm=alarm:view，操作列按钮 v-perm="'alarm:handle'"。

3.1 列表查询与筛选

进入页面
顶部四张 KPI 卡（今日总数/待处理/已确认/已解除）来自统计接口（缺省今日窗口）；列表默认带"今日 00:00~23:59"时间窗（前端默认值，非后端强制）。
组合筛选
车牌模糊 / 报警类型（下拉来自 types 接口）/ 处置状态（待处理/已确认/已解除）/ 起止时间（datetimerange，格式 yyyy-MM-dd'T'HH:mm:ss）；查询回第一页，重置恢复今日窗。
浏览列表
列：车牌、类型（按等级着色标签）、报警开始/结束、速度、持续标志、状态、处置人、更新时间、操作；分页 20/50/100（默认 20，后端钳制上限 100）。
URL 恢复筛选
支持从路由 query 恢复 plateNo/typeId/handleStatus/beginTime/endTime——大屏与面板的钻取链接即借此预置条件。

3.2 报警详情与位置地图

打开抽屉
行内"详情"调 /api/alarm/{id}（640px 抽屉）；接口失败时回退用行数据展示，不打断操作。
字段速览
两列描述列表：车牌/终端标识/类型/状态/起止时间/起止速度/持续标志/处置人/解除结论/更新时间/处置说明。
位置地图
起/终点任一有效即渲染 Leaflet 小地图（高德瓦片）：起点绿圆点、终点红圆点、两点间连线并自适应视野；坐标为 varchar 防御解析（非法或 0 视为缺失），全缺时显示"坐标缺失"。
关联风险
同车牌 ±30 分钟的 mon.risk_event 前 5 条（标题/等级标签/时间）；无数据显示提示；底部链接前往风险预警分析页人工研判。

3.3 确认与解除闭环

确认（0→1）
待处理行点"确认"（需 alarm:handle）：服务端条件更新成功返回最新记录替换行数据，KPI 重新拉取；若他人已抢先处置，返回 45001 并自动刷新列表。
解除（0/1→2）
点"解除"弹 440px 对话框：结论单选（属实 00/误报 01/未知 02，默认属实）+ 说明（可选，≤200 字带字数统计）。
提交与结果
成功后行内状态变"已解除"、显示处置人与结论；冲突同样 45001 关窗刷新；resultCode 非法或说明超长由后端 40001 拦截（前端单选与 maxlength 已先行约束）。
留痕
确认/解除均写操作审计（模块 MONITOR、动作 HANDLE、对象 ALARM+id）；handler 落当前用户姓名并同步 updater/update_date。

3.4 钻取联动与实时增量

  • 行内"监控"：跳 /monitor?plate={车牌}，在实时监控页定位该车当前位置。
  • 行内"轨迹"：跳 /playback 带 plateNo + identityCode + date（报警开始当天），回放页自动锁定当天 0~24 点。
  • 大屏钻取：态势卡"待处理"带今日窗 + handleStatus=0；滚动条条目带 plateNo——均由本页 route.query 恢复。
  • WS 增量：收到 ALARM 消息按 id 去重（缓存 200）后弹提示；当前"未设筛选"或"正在筛待处理"时，新行置顶、total 与今日总数 +1；其余筛选态只提示不插行（避免破坏当前结果集）。

7 核心实现逻辑

7.1 处置状态机与并发控制（45001）

状态机
0 待处理 → 1 已确认 → 2 已解除；允许 0 直接到 2（确认是可选项）。非法流转（如对已解除再操作）被条件更新天然拦截。
条件更新
markConfirmed：UPDATE ... WHERE id=#{id} AND COALESCE(handle_status,0)=0；markResolved：... AND COALESCE(handle_status,0) IN (0,1)。WHERE 子句自带"当前状态=期望原值"谓词。
冲突判定
UPDATE 返回影响行数：0 行即"他人已变更状态"（或记录刚被处理），抛 BizException(45001, "报警状态已变更，请刷新后重试")；本模块专用码，不复用通用 40901（代码注释注明 RES-DBD-001 §3.2）。
落名与留痕
handler=realName（空回退 username，再空 "system"，截 30 字符）；同步 updater + update_date=now()；成功后 selectDetail 返回最新记录给前端替换行。

解除参数校验在 Service 手写：resultCode ∉ {00,01,02} → 40001"resultCode 仅支持 00/01/02"；resultMsg 超 200 字 → 40001。先校验参数再 requireExists，避免无效请求触达数据库。

7.4 详情与关联风险（±30 分钟）

detail(id) 的执行顺序：selectDetail（LEFT JOIN 类型表单条）→ 不存在或 !canSee → 40401 → 有车牌且有 startWarnTime 时调 relatedRisks(plateNo, startWarnTime) 填充关联风险，否则置空列表。relatedRisks 直查 mon.risk_event：同车牌、event_time ∈ [报警开始 −30min, +30min]，event_time 倒序取前 5，返回 id/eventCode/title/riskLevel/eventTime 五列。该设计让坐席在一个抽屉里回答"这条终端报警是否已被 CEP 升级、升级成了什么等级"，而不必切换到风险页手工对时间。

7.5 前端页面与实时增量

  • 时间与默认值：timeRange 默认今日 00:00~23:59（前端 todayDefaultRange，墙钟）；value-format=YYYY-MM-DDTHH:mm:ss 与后端 LocalDateTime.parse 对齐；数据时基滞后墙钟时默认窗内可能无数据，改时间窗即可（项目避坑经验）。
  • KPI 口径：四卡数字 = stats.byStatus 按 handleStatus 匹配（总数取 stats.total），与列表筛选互不影响；处置成功后 loadStats 重拉，另有 30s 轮询兜底。
  • 详情地图：parseCoord 对 varchar 坐标做防御解析（空/非数字/0 均视为缺失）；单点 setView 13 级，两点连线并 fitBounds(pad 0.3)；抽屉关闭时销毁地图实例防泄漏。
  • WS 增量：seenIds 缓存 200 个 id 防重复插入；filtersInactive()（无车牌、无类型、无时间窗）或正在筛"待处理"时才 unshift 新行并 total+1、stats.total+1；其余筛选态只 ElMessage 提示。新行的 typeName/gradeLevel 从已加载的类型下拉映射补齐。
  • 冲突自恢复：confirm/resolve 捕获消息含"状态已变更"时自动关窗并 loadRows()，坐席看到的就是最新状态。
  • 权限双闸：菜单路由 meta.perm=alarm:view；确认/解除按钮 v-perm="'alarm:handle'"——车队长（role4）页面可用但看不到处置按钮，直调接口也会被后端 40301 拒绝。

12 技术选型依据

  1. 条件更新判影响行数做并发控制，而非乐观锁版本列或悲观锁：处置是"状态前进一格"的单字段变更，WHERE 自带原状态谓词即可把"读-改-写"合并成一条原子 UPDATE；0 行即冲突，无需给表加 version 列，也无需 SELECT ... FOR UPDATE 拉长事务。
  2. 专用冲突码 45001，而非复用 40901：40901 的语义是"唯一性/占用冲突"，前端按它做通用提示；45001 让报警页能精确匹配"状态已变更"并自动刷新列表（前端按消息内容匹配），语义与处理动作都更清晰。
  3. 不存在与越权同口径 40401：详情/处置若区分 40401 与 40301，攻击者可枚举 id 探测范围外记录是否存在；合并口径牺牲少量排错便利，换存在性保密（与监控域 handleRisk 对齐，SYS-DBD-001 §8 fail-closed）。
  4. 读取侧 COALESCE 归一 + 存量迁移双管齐下：历史 handle_status 允许 NULL，单纯改默认值管不住存量；13 号脚本 UPDATE 归一 + DEFAULT 0，SQL 里 COALESCE 兜底任何漏网与旧备份恢复场景。
  5. 解除校验在 Service 手写，而非 jakarta 注解：ResolveRequest 为极简 record，非法值文案需中文字段级定制（"resultCode 仅支持 00/01/02"）；手写校验顺序（先参数后存在性）也避免无效请求触库（代码注释注明该取舍）。
  6. 关联风险用 ±30min 窗口前 5 条，而非外键关联：终端报警与 CEP 风险事件是两条独立生产链路，无稳定外键；时间窗口 + 同车牌是业务上最可靠的关联口径，LIMIT 5 控制详情载荷。
  7. 统计三查询分离（total/byType/byStatus），而非一个大 GROUP BY：三组聚合维度不同，分开写各自走 idx_traj_warn_status_time，SQL 简单可读；窗口数据量下成本可忽略。
  8. 范围换算复用 DashboardMapper.selectVehicleNosByDeptScope：监控域已确立"deptScope→车牌集"的换算 SQL 与跨 schema 直查先例，报警中心复用同一方法，权限口径全模块一致（与 MonitorService 同款 currentPlates 实现）。
  9. WS 增量按筛选态条件置顶：用户已设筛选时强行插行会破坏其结果集语义；只在"无筛选"或"看待处理"时置顶，其余只提示——新数据可见性与列表稳定性兼顾。

15 边界行为与常见问题

列表为什么有时打开是空的？
前端默认带"今日 00:00~23:59"时间窗（墙钟）。演示数据时基滞后墙钟时今日无数据属正常；把时间窗改到数据所在日期，或用大屏钻取链接（自带时间窗）即可。
确认和解除有什么区别？必须两步都走吗？
确认=“我已看到并开始处理”（0→1），解除=“已办结”（→2）且必须填结论。可以不确认直接解除（0→2），确认是可选项。
两人同时处置同一条会怎样？
条件更新保证只有一人成功；另一人收到 45001"报警状态已变更，请刷新后重试"，前端自动刷新列表显示最新状态与处置人，不会产生重复结论。
已解除的报警还能再操作吗？
不能。操作列按钮按状态渲染（确认仅 0、解除仅 0/1）；直调接口也会被条件更新拦截返回 45001。
处置人字段显示谁？
当前登录人的真实姓名（realName），未填姓名时回退登录名 username，都没有时记 "system"；超长截 30 字符（varchar(30) 防御）。
为什么直填 id 查他省报警返回"报警不存在"？
存在性保护：范围外记录与不存在记录返回同一 40401，防止借响应差异探测他范围数据（fail-closed 口径）。
新报警为什么不总是插入列表第一行？
只有"未设任何筛选"或"正在筛待处理"时才置顶（此时新行一定属于当前结果集）；其余筛选态只弹提示，避免插入不满足当前条件的行。
详情里"坐标缺失"是什么原因？
起止坐标为 varchar 存储，前端防御解析：空、非数字或 0 均视为缺失（页面上也标注"坐标为终端上报原始值"）。两点都存在时小地图会连线并自适应视野。
关联风险为什么是空的？
三种情况：该车牌在报警开始 ±30 分钟内没有 CEP 事件；报警缺 startWarnTime（不查直接置空）；纯终端报警未被规则引擎升级——第三种正是"关联"要回答的问题。
类型下拉里的等级颜色和大屏图例为什么不一致？
已知口径差异：报警中心按 1=红/2=橙/3=灰，大屏右列按 3=高/2=中/1=低。已列待核实（17 节），统一前以报警中心口径为准。
limit/size 传超界值会怎样？
钳制而非报错：latest 的 limit 钳到 1~50，page 的 size 钳到 1~100、page 下限 1——调用方不需要先校验。
企业车队长为什么看不到确认/解除按钮？
role4 只有菜单 16（alarm:view）没有按钮 926（alarm:handle）；按钮 v-perm 隐藏，直调接口返回 40301。处置权在调度监控员与安全管理员。
