MOD-DBD-017 分析与报表

编号：MOD-DBD-017｜版本：v1.0.0｜日期：2026-10-05｜ 状态：部分具备｜覆盖功能项：F41～F59（19 项）｜ 代码锚点：17-analysis-menu.sql、ComingSoon.vue、ScoreList.vue、RiskProfile.vue、ScoreController、mon.driver_score
产品篇

1. 模块定位与整体状态

分析与报表模块面向企业管理者、安全管理人员与调度运营，提供车辆运行、驾驶行为、在线质量、油耗成本、周期安全、商机与数据质量等 19 个分析功能（F41～F59）。整体状态为部分具备：

  • 已上线：19 个菜单与占位路由（4 个角色全部授权）、驾驶评分（301 菜单，ScoreList.vue）、风险趋势与画像（302 菜单，RiskProfile.vue）。
  • 未实现：F41～F59 共 19 项报表/分析页均为 ComingSoon 占位，无后端统计逻辑；其中大量功能依赖尚未建成的数据底座（F12 派生统计、F02 在线状态、F05 CAN/OBD、F08 清洗、F36 质量）。
菜单结构
分析决策（300）下两组：报表查询（310，F41～F53 共 13 项）、统计分析（340，F54～F59 共 6 项）
授权角色
平台超级管理员、企业管理员、安全管理员、调度员（17-analysis-menu.sql 四角色全授权）
对标依据
FUNC-REF-001 功能参考（对标产品的节点、查询条件、结果列、业务场景）

5. 数据范围七条强制口径

以下七条为本模块所有功能必须遵守的数据权限规则（基于 UserInfo.deptScope：null=不限制，空集合=不可见任何数据）：

  1. 统一约束：全部报表受 deptScope 约束；null=不限制、空集合=直接返回空结果。
  2. 车辆锚点唯一：车辆类报表以 traj_vehicle.dept_id 为唯一锚点；GPS 数据经车牌/标识 JOIN 或 EXISTS 关联车辆，dept_id 为空的车辆对受限角色不可见。
  3. 司机经绑定映射：司机类报表（traj_driver 无 dept_id）经 F31 车-司机绑定关系（traj_vehicle_driver）映射到其驾驶车辆的 dept_id 并集。
  4. 企业先裁剪后聚合：企业聚合类报表先按范围裁剪企业行（自定义数据范围须补全组织祖先链），再在裁剪结果上聚合，禁止"全量聚合后过滤"。
  5. 异步导出快照：导出任务固化执行人当时的数据范围快照；生成的文件按执行人隔离，他人不可见、不可下载。
  6. 推送同样过滤：实时 WebSocket 推送必须按数据范围过滤后再下发；现状全量广播是已知缺口，相关实时报表（F51）上线前必须先关闭/修复全量广播。
  7. "用户"维度映射：对标产品的"用户"维度统一映射为"用户所属部门 → 该部门锚定的车辆集"，不引入独立用户-车辆关系。

6. 业务价值

  • 管理闭环：运行数据→周期安全评分→排名通报→整改，覆盖车、司机、企业三层。
  • 口径统一：所有里程/时长/报警/在线指标共享 F12/F02/F08 同一数据底座，报表之间不打架。
  • 权限可控：七条范围口径保证企业只能看自己的车与司机，支撑多租户式运营。
  • 渐进交付：菜单、授权、占位已全量上线，数据底座（F02/F05/F08/F12）每建成一个，对应报表即可激活。

8. 已上线：驾驶评分（mon.driver_score）

驾驶评分是本模块唯一真实在跑的统计模型，F57 已具备、F54/F55 可部分复用：

要点口径（ScoreConstants 代码实证）
快照表mon.driver_score：score_date、driver_id、identity_code、plate_no、dept_id、score numeric(5,1)、level char(1)、features jsonb、sample_points、event_count；唯一键 (score_date, driver_id)
事件白名单8 个事件码：SPEED_GENERAL、SPEED_SEVERE、FATIGUE_DRIVE、DSM_FATIGUE、DSM_DISTRACTION、ADAS_FCW、ADAS_LDW、COMBO_FATIGUE_SPEED
扣分三级事件 level3=8 分、level2=4 分、level1=2 分；急加减速每次 0.5 分、单日封顶 5 分
急加减速阈值加速度 2.5m/s²；参与计算的邻点时间差最大 30 秒
样本门槛≥200 个定位点且 ≥30 分钟才有当日评分（不足不出分）
等级A≥90、B≥75、C≥60、D≥40、E<40
重算上限 92 天；POST recalc 异步执行、AtomicBoolean 互斥（同一时刻只允许一个重算任务）；仅超管/安全管理员；@AuditLog 留痕
定时ScoreScheduler cron 0 0 1 * * ? 每日 01:00 跑 T+1 评分

8.1 评分算例（口径演示，数值为构造样例）

司机 A 当日：定位点 420 个（≥200）、驾驶时长 52 分钟（≥30 分钟）→ 出分
  严重超速 SPEED_SEVERE    ×1  level3  →  -8
  一般超速 SPEED_GENERAL   ×2  level2  →  -8
  分心驾驶 DSM_DISTRACTION ×1  level2  →  -4
  急加减速检出 14 次 ×0.5 = 7 分，单日封顶 5 分 → -5
  得分 = 100 - 8 - 8 - 4 - 5 = 75.0 → 等级 B（B≥75，边界含等号）

司机 B 当日：定位点 180 个（<200）或驾驶时长 25 分钟（<30）→ 当日不出分、不写快照
司机 C 当日：无白名单事件且样本达标 → 100 分，等级 A

8.3 定时与重算时序

  • ScoreScheduler 每日 01:00（cron 0 0 1 * * ?）跑 T+1：取前一日样本达标司机，按 ScoreConstants 口径 upsert 快照，唯一键 (score_date, driver_id)。
  • 手工 recalc：POST 后异步执行；AtomicBoolean 保证同一时刻全库只允许一个重算任务，重复提交直接拒绝；范围上限 92 天。
  • 权限：仅平台超级管理员、安全管理员可触发；@AuditLog 记录重算时间窗与操作人。
  • F54/F55/F57 的周月汇总只读取快照，不与定时/重算任务争抢写。

8.4 与对标产品评分的差异说明

  • 现状评分是司机日评分（白名单 8 码、100 分扣减制）；对标 F54 是车辆周期评分（按"百公里报警 × 规则级别权重"），两者数据源可共用、公式不可混用。
  • 现状无"标准统计 / 内部统计"规则属性，F54 上线前须在规则模型扩展该字段并回填（见待核实）。
  • 急加减速不是 808 报警码，而是平台按相邻点加速度（2.5m/s²、邻点时差 ≤30s）检出，仅影响评分、不产生 risk_event。

9.16 范围裁剪 SQL 骨架（13 项统一写法）

所有车辆类报表 SQL 必须以 traj_vehicle 为锚点先做范围裁剪，再 JOIN 统计；禁止先聚合后过滤。统一骨架：

-- deptScope == null  : 不拼接 scope 子句（平台超管，不限制）
-- deptScope == []    : Service 层直接返回空页，不进 SQL（fail-closed）
-- deptScope == [...] : 拼接以下锚点过滤
SELECT t.stat_date, v.plate_no, t.mileage_km
FROM traj.traj_daily_stat t
JOIN traj.traj_vehicle v ON v.id = t.vehicle_id
WHERE v.dept_id = ANY (:deptScope)           -- 唯一锚点：车辆归属组织
  AND t.stat_date BETWEEN :begin AND :end
  AND (:vehicleIds IS NULL OR t.vehicle_id = ANY (:vehicleIds));

-- 司机维度：经 F31 绑定并集映射，禁止直接用 traj_driver（该表无 dept_id）
SELECT ...
FROM traj.traj_daily_stat t
WHERE t.vehicle_id IN (
  SELECT vehicle_id FROM traj.traj_vehicle_driver
  WHERE driver_id = :driverId AND valid = TRUE);
  • 禁止用 province_code、车牌简称/首字作为过滤条件（外省车牌可挂本公司，归属在范围内即可见，该字段仅作档案展示）。
  • EXISTS 与 JOIN 二选一：仅需存在性判断时用 EXISTS，避免 JOIN 产生重复行后再 DISTINCT。
  • 企业维度先按 deptScope 裁剪企业车辆集合，再在结果集上聚合（口径④"先裁剪后聚合"）。

9.1 F41 轨迹报表

查询条件：车牌号 + 起止日期时间。对标结果列：序号、车牌、颜色、状态、速度、方向、里程、油量(L)、油量原始值、定位时间、上点时间（receive_time）、经度、纬度、位置描述、所属企业、补点标记。

设计级方案：来源 traj_gps_point JOIN traj_vehicle（dept_id、车牌颜色）；位置描述取 GeocodeController 逆地理（mydbd.amap.key）；双时间列直接暴露 gps_time/receive_time 以识别上点时延；油量列与补点标记依赖 MOD-014 18 号迁移（ext 油量、is_backfill）；导出为明细分页 Excel，数据量大时按时间段分片异步导出。

9.2 F42 里程报表

对标口径：按年、按周维度统计每车总里程。结果列：车牌、车牌颜色、所属企业、总里程。

10.1.1 评分算例（权重为示例值，详设固化）

车辆 X，周期内里程 1200 km：
  严重超速 2 次（级别权重 8）、一般超速 4 次（权重 4）、疲劳驾驶 1 次（权重 8）
  扣分 = Σ_type (次数_type ÷ 里程 × 100 × 权重_type)
       = (2×8 + 4×4 + 1×8) ÷ 1200 × 100 = 40 ÷ 1200 × 100 = 3.33
  周期评分 = 100 − 3.33 = 96.7
注：① 8 个白名单码之外的规则是否计入，由"标准统计/内部统计"属性决定；
    ② 已禁用的"标准统计"规则仍参与历史周期计算；
    ③ 权重具体取值需安全业务确认，不可直接照搬本算例。

10.6 F59 轨迹完整率

交付方式：异步计算（日期范围 ≤10 天、阈值参数过滤），结果经下载中心交付。

结果列：连续里程、轨迹里程、轨迹完整率、错误定位数、定位总数、错误占比、合格率、漂移总数。

10.6.1 连续里程判定口径（必须严格实现）

  • 相邻点距离 ≤2km 视为连续；
  • 连续出现 5 段 距离 >2km 且 ≤10km 的间隔，则从第 6 段起判为不连续；之后若出现一段 <2km，则计数归零重新开始；
  • 相邻点距离 >10km 直接判不连续。

10.6.2 错误点五规则 + 漂移

  1. 经纬度超出有效范围；
  2. 海拔不在 −200～6000 米；
  3. 速度 <0 或 >160km/h；
  4. 方向角不在 0～360 度；
  5. 定位时间晚于接收时间 20 小时以上；
  6. 漂移：连续点按距离÷时间等效速度 >160km/h。

指标公式：合格率=合格点数÷定位总数；轨迹完整率=连续里程÷轨迹总里程。判定函数与 F08 清洗共用同一套规则代码（MOD-DBD-015 原则②）。依赖：F08/F36 质量标记；异步导出框架（第 11 节）。

10.6.4 计算流程伪代码（异步任务按车分片）

for 每辆车（按 vehicle_id 分片并行，受 worker 并发度限制）:
  points = 按 gps_time 升序拉取窗口内定位点（只取必要列）
  totalDist = 0; continuousDist = 0
  badCount = 0; driftCount = 0
  mediumStreak = 0          // (2,10] 间隔的连续计数
  prev = null
  for p in points:
    if 命中错误五规则(经纬度/海拔/速度/方向/时钟):
      badCount++; continue          // 错误点不参与连续里程判定
    if prev != null:
      d = haversine(prev, p)
      totalDist += d
      if d <= 2:
        continuousDist += d; mediumStreak = 0       // ≤2km 连续并归零
      else if d <= 10:
        mediumStreak += 1
        if mediumStreak <= 5: continuousDist += d  // 前 5 段仍计连续
        // 第 6 段起不计入连续里程
      else:
        mediumStreak = 0             // >10km 直接不连续
      if 漂移(prev, p): driftCount++ // 距离÷时间等效速度 >160km/h
    prev = p
  合格率   = (总点数 − badCount − driftCount) ÷ 总点数
  完整率   = continuousDist ÷ totalDist
  连续里程 = continuousDist

说明：判定函数（五规则、漂移、连续里程）与 MOD-015 F08 清洗共用同一实现类，禁止报表侧另写一份；分片结果汇总后写导出文件，单片失败只重试该车，不重跑全任务。

11.1 export_task 表草案

CREATE TABLE mon.export_task (
  id             BIGINT PRIMARY KEY,
  task_no        VARCHAR(32) UNIQUE NOT NULL,  -- EX + yyyyMMdd + 序列
  func_code      VARCHAR(40) NOT NULL,         -- 如 track-integrity（F59）
  query_params   JSONB NOT NULL,               -- 查询条件快照
  scope_snapshot JSONB NOT NULL,               -- {"deptScope":[...],"scopeType":"..."}
  operator_id    BIGINT NOT NULL,
  status         VARCHAR(16) NOT NULL,         -- QUEUED/RUNNING/SUCCESS/FAILED
  file_path      VARCHAR(255),
  file_size      BIGINT,
  row_count      INT,
  error_msg      VARCHAR(1000),
  create_time    TIMESTAMP DEFAULT now(),
  start_time     TIMESTAMP,
  finish_time    TIMESTAMP,
  expire_time    TIMESTAMP                     -- create_time + 7 天
);

11.2 异步执行时序

提交
写 export_task（QUEUED），固化查询条件与 deptScope 快照
认领
worker 以 SELECT ... FOR UPDATE SKIP LOCKED 认领，置 RUNNING；多 worker 不抢同一任务
生成
按快照范围分页拉取，SXSSF 流式写 xlsx（含汇总页），避免内存堆积
交付
文件落存储并按 operator_id 隔离鉴权，置 SUCCESS，下载中心可见
清理
超过 expire_time 的文件与记录定时清理；提交/下载写 @AuditLog EXPORT

11.3 失败处理与权限

  • RUNNING 超时（规划 30 分钟）置 FAILED 并释放认领；FAILED 允许本人在下载中心重试（重新快照当前范围）。
  • 下载接口校验文件归属 operator_id 与当前登录用户一致；任何越权下载尝试记审计。
  • 并发配额：每用户同时 QUEUED/RUNNING 任务 ≤3，防止大批量导出拖垮库。

决策方案理由

13.1 报表激活检查表（每个占位菜单替换前必须全部满足）

  1. 数据来源已上线：依赖的底座（F02/F05/F08/F12 等）已有真实数据，不是临时造数。
  2. 口径已登记：指标取数来源写入 9.15 一致性矩阵，不与其他报表冲突。
  3. 范围已收口：Service 层 deptScope 裁剪经越权用例验证（改参数/空集合/跨企业三类）。
  4. 性能已达标：时间窗上限内 P95 ≤2 秒；大结果集走异步导出。
  5. 导出可控：同步/异步路径明确，文件名与汇总页符合 9.0 约定，EXPORT 审计可查。
  6. 占位替换：ComingSoon 路由替换为真实页面，菜单 code 与权限点不变。

  1. 19 个菜单按 17-analysis-menu.sql 对 4 个角色可见；占位页 code 与名称映射正确。

  11. 同步导出超 5000 行的请求被拒绝并引导走异步；异步任务并发配额、7 天清理、超时失败均有对应用例。
  12. F56 看板指标卡数值与 F51/F54/F55 对应报表数值逐项一致（同一聚合层，不另算）。
  13. F53/F58 新模型页面与导入功能均接入 deptScope；外部导入失败行有明确回执，不产生半量数据。
