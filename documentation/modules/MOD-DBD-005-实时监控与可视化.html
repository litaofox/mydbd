1 功能概述

1.1 模块定位与边界

实时监控与可视化模块回答三件事：车在哪里、状态如何、出了什么事。它以秒级节拍把轨迹接入模块（MOD-DBD-004）落库的定位点、终端报警（traj.traj_warn_info）与风险事件（mon.risk_event）推送到坐席浏览器，并提供两个工作台（坐席监控页、值班大屏）与一个车辆级聚合视图（详情面板）。

  • WebSocket 实时推送（P07）：端点 /ws/realtime，1 秒一拍推送三类消息——位置全量快照 POINTS、增量风险事件 RISK、增量终端报警 ALARM；所有消息按各会话用户的数据范围过滤（fail-closed）；断连自动降级为 5 秒 REST 轮询。
  • 实时导航监控（F14）：/monitor 页面，左栏组织车辆树 + 状态统计，中央高德瓦片地图实时车标，底部车辆明细表；气泡与右键菜单提供轨迹回放跳转、详情面板与预留终端指令入口。
  • 监控总览大屏（F15）：/dashboard 页面，面向值班室的整屏数据驾驶舱（v1.1.0 起去地图）——顶栏当前用户视角徽标、六卡 KPI 指标带、车队全景卡片矩阵、在线车速分布、车队/区域排行、报警态势与滚动条；30 秒一次聚合轮询 + 实时消息即时修正。
  • 车辆详情聚合面板（F16）：单一接口一次返回车辆档案、当前终端与在班司机、最新定位点、当日轨迹（抽稀 ≤500 点）、最新 5 条报警与当日计数；以共享抽屉组件在监控页与大屏复用。
  • 地理编码代理：高德逆地理与地点检索的服务端代理（Key 不下发前端），供监控气泡显示文字地址与地图地点搜索。

一句话边界：本模块只做"看"——定位点与报警/风险数据的生产与落库在 MOD-DBD-004 与风控模块；报警的确认/解除闭环在 MOD-DBD-006；风险事件的工单流转在风控工单模块；轨迹存储与历史回放在 MOD-DBD-004。本模块保留一个风险"轻量处置"入口（与工单处置同一权限码）。

1.3 术语与概念

术语含义
POINTS / RISK / ALARMWS 三类消息封套 {type, data} 的 type 值：位置全量快照 / 增量风险事件 / 增量终端报警。
id 游标增量推送记录 lastRiskId / lastAlarmId，每拍查 id > 游标 的记录；不丢不重，重启不回放（初始化为当前最大 id）。
范围签名broadcastScoped 内把会话可见车牌集合排序拼接成 key，同一次调用内相同范围的会话共享一份 JSON 序列化结果。
fail-closed任何环节拿不到有效范围（无 uid、用户停用、空范围）一律视为"不可见任何数据"，宁可不推也不错推。
refTime（数据时基）前端以"全局最新定位时间"作为在线判定参考点，而非浏览器墙钟；历史数据集演示时数据时基滞后墙钟十几小时仍能正确区分在线/离线。
在线窗口定位时间距参考点不超过 N 分钟视为在线。监控页前端可选 10/30/60/1440（默认 10）；大屏后端读 sys_config 键 monitor.online.window.minutes（缺省 5）。
LATERAL 优化最新点查询以终端表驱动，CROSS JOIN LATERAL 逐台走索引取最新一条，避免对 890 万行轨迹表做全量聚合。
GCJ-02平台点位坐标与高德瓦片底图同为火星坐标系，逆地理直接透传；若未来接入 WGS-84 原始 GPS 须在接入层统一转换（代码注释口径）。
轻量处置监控域对风险事件的单步处置（写处置状态+备注），与工单处置共用权限码 risk:order:handle；完整流转仍在工单模块。

2 典型场景

调度监控员
全网车辆一屏掌握
打开实时导航监控页：左栏组织树按车队勾选车辆，地图 1 秒一拍刷新车标位置与方向，底部统计格实时显示 在线/行驶/停车/离线/报警 数量；点统计格即勾选对应分组。
调度监控员
新风险与报警即时提示
值守期间终端上报报警或规则引擎产生风险事件，浏览器 1 秒内弹出 ElMessage 提示（车牌 + 事件码/类型 + 等级），无需刷新页面；每拍最多提示最近 3 条。
值班长
大屏值守与钻取
值班室投屏监控总览大屏：顶栏标注当前登录用户与数据范围，KPI 指标带速览全局，中央车队全景卡片矩阵逐队展示在线率，左列在线车速分布实时聚合，右列报警滚动条实时置顶；新风险以飘条提示 5 秒。点车队卡/待处理数字直接带条件跳到车辆档案/报警中心。
企业车队长
核查某辆车当前状况
在监控页点车标气泡"车辆详情"：抽屉一次展示档案、当前终端与在班司机、最新定位（速度/方向/时间）、当日轨迹曲线、最新 5 条报警与当日计数；可一键跳轨迹回放锁定当天。
调度监控员
气泡快速操作
点击车标弹出气泡：速度/方向/定位时间/坐标/文字地址（高德逆地理），按钮直达轨迹回放（自动锁定该车最新定位当天 0~24 点）与详情抽屉；视频/对讲/抓拍按钮标注"预留"。
省份受限用户
只见本范围数据
山东测试账号登录后：监控页只见本省车辆，WS 推送的 POINTS/RISK/ALARM 均已被服务端按会话过滤；大屏六块聚合只统计本省；直输他省车辆的面板地址返回 40301。

3 操作流程

菜单路径：实时监控一级目录（sys_menu id=10，图标 Monitor），下挂：实时导航监控（id=11，/monitor，权限点 monitor:view）、历史轨迹回放（id=12，/playback，playback:view，属 MOD-DBD-004）、监控总览大屏（id=15，/dashboard，monitor:dashboard:view，由 12-dashboard.sql 种子并授权 role 1~4 全员）。大屏路由为顶层独立路由（不进 MainLayout 侧栏框架），菜单点击后以整屏模式打开。

3.1 实时导航监控页

进入页面
首屏并行执行：REST 拉一次 overview + 最新点（pollOnce），同时建立 WS 连接；顶栏连接胶囊显示"实时连接 · 1s 推送"或"降级轮询 · 5s"。
组织树勾选
左侧树按"组织 → 车辆"两级展示（带车队统计后缀），首次进入自动全选；搜索框按车牌/终端号/SIM 过滤；漏斗图标按状态/颜色/车型筛选并自动勾选结果。
地图浏览
车标 1s 差分刷新（仅位置/状态/方向变化的标记重建）；点标气泡看详情，右键车标打开操作菜单；工具条支持地点搜索、标准/卫星底图切换、复位视野。
底部明细与跟踪
五个页签（全部/行驶中/停车/离线/报警）过滤明细表；行点击定位到该车；🎯 开启持续跟踪后地图自动跟随该车移动。

3.2 监控总览大屏

打开与自适应
进入 /dashboard 即整屏布局（KPI 指标带 + 左列在线率/车队排行/车速分布 + 中央车队全景卡片矩阵与实时报警 + 右列报警态势/区域分布/工单处置，无地图），根字号按 1920 基准 rem 流式缩放（clamp 12~32px），适配 1080P 与 4K。
30s 聚合轮询
每 30 秒拉一次 summary（六块）、overview 计数与报警统计，重绘环图与排行条；WS POINTS 驱动在线车速分布实时聚合（reactive Map 按 identityCode 合并），RISK 驱动飘条，ALARM 驱动滚动条置顶。
卡片钻取
各卡片标题栏"›"与关键数字可点击：有效车辆/车队卡→/mdm/vehicles（车队卡带 deptId），在线率→/monitor，里程→/playback，工单→/risk/orders（带状态条件），今日报警→/alarms（带今日时间窗），区域行→/risk（带 cityCode），滚动条条目→/alarms（带车牌）。
全屏与退出
顶栏"全屏"切换浏览器全屏；"退出大屏"跳转 /monitor 监控页；离开页面自动恢复根字号 16px，不污染常规页面。

3.3 车辆详情聚合面板

打开抽屉
监控页气泡"车辆详情"、右键菜单"车辆详情"、大屏风险飘条点击均可打开；无车辆档案 id（未建档或无权）时提示并拦截。
一次聚合加载
GET /api/monitor/vehicle-panel/{id} 一次返回六个区块：档案、当前终端、在班司机、最新点、当日轨迹、报警 Top5 与当日计数；越权返回 40301。
在线状态展示
抽屉头部的在线标签优先使用调用页传入的 online（监控页 refTime 口径），未传时用接口 latestPoint.online（后端墙钟 5 分钟口径）。
跳转联动
面板内可跳"前往车辆档案"、"查看全部报警"、"轨迹回放"（无绑定终端时禁用）。

3.4 风险事件列表与轻量处置

  • 监控域提供风险事件分页接口（/api/monitor/risks），筛选条件：事件来源 eventSource、风险等级 riskLevel、处置状态 handleStatus、规则 ruleId、车牌 plateNo（模糊）、注册地 cityCode（经车辆表换算车牌集合，供大屏区域柱钻取）。
  • 处置入口 POST /api/monitor/risks/{id}/handle，仅需备注 remark；权限点 risk:order:handle 与工单处置同码，并写操作审计（@AuditLog MONITOR/HANDLE/RISK_EVENT）。
  • 不存在与越权同一口径返回 40401，避免借处置接口探测事件存在性（与 AlarmService 对齐）。
  • 前端风险事件完整列表页在风控模块（/risk）；本模块接口同时服务监控页侧栏与大屏钻取。

  • 零刷新值守：位置、风险、报警全部服务端推送；监控页与 Chrome 标签页并存的多标签会话各自独立过滤、互不干扰。

技术篇

6 模块架构与组件

监控域后端集中在 module-monitor（4 个 Controller + 3 个 Service + WebSocket 六类），另复用 module-trajectory 的最新点查询；前端为 2 页 + 2 共享组件 + 1 个 WS composable。nginx 把 /ws/ 前缀以 Upgrade 方式反代到 platform-app:8080，/api/monitor、/api/terminal/geocode 走默认 /api/ 分支。

7 核心实现逻辑

7.1 WebSocket 链路与握手鉴权

建连
前端 new WebSocket("wss?://host/ws/realtime?token=...")；nginx location /ws/ 以 Upgrade 反代 platform-app:8080（proxy_read_timeout 3600s）。
握手拦截
AuthHandshakeInterceptor 从 query 取 token，JwtUtil.parse 验签并校验 purpose=access，把 uid（Number）与 username 写入会话 attributes；缺 token/验签失败/purpose 不符一律返回 false，握手被拒绝。
注册与首帧
RealtimeWebSocketHandler.afterConnectionEstablished：SessionRegistry.add 登记会话（并按 uid 归集多标签），随即 pushPointsOnce 推一次按该会话范围过滤的位置快照，避免首屏空等下一拍。
运行与释放
服务端单向推送，客户端消息被忽略（注释注明可扩展 ping/pong 或订阅控制）；连接关闭或传输异常即从注册中心移除，uid 下无会话时一并清理映射。

7.2 按会话数据范围过滤（fail-closed）

2026-10-05 数据权限改造后，WS 推送与 HTTP 查询同口径。核心是两个类的协作：

环节实现要点
范围解析WsScopeResolver.allowedPlates(session)attributes 无 uid → 空集合（异常 fail-closed）；permissionCache.getOrLoad 加载用户，停用/删除 → 空集合；allData() → null（不限制）；deptScope 空 → 空集合；否则 selectVehicleNosByDeptScope 换算车牌集
权限缓存PermissionCache（platform-common）与 HTTP 请求链路共用同一缓存（TTL 120s），角色/数据范围调整后两条链路在 120s 内同时收敛
过滤发送SessionRegistry.broadcastScopedDB 只查一次全量；逐会话取范围：null 共享一份序列化；空集合 continue 跳过；非空把范围排序拼成签名 key，computeIfAbsent 缓存"该范围的过滤结果 JSON"，同范围多会话不重复序列化
首帧过滤SessionRegistry.sendScoped单会话版本：空集合不发送；非空按车牌过滤后 sendTo
失败治理SessionRegistry.send会话已关闭直接除名；sendMessage 抛 IOException 记 warn 并移除会话，不影响其他会话

为什么过滤放在发送环节：位置快照是"每终端一条"的全量集合，所有会话共用同一份查询结果；如果每个会话各查一次数据库，N 个在线会话就是 N 次 LATERAL 查询。发送环节过滤 + 范围签名缓存序列化，把成本压到"1 次查询 + 每范围 1 次过滤与序列化"。

7.3 推送调度与 id 游标

启动初始化
@PostConstruct initCursor：分别查 risk_event / traj_warn_info 当前最大 id 作为游标起点——只推启动后的新增记录，避免重启时把全量历史回放给在线用户。
每拍三件事
@Scheduled(fixedDelay=1000, initialDelay=5000)：pushPoints（无会话直接返回）→ pushRisks → pushAlarms；单拍异常整体 catch 记 error，不影响下一拍。
位置快照
trajectoryService.listLatestPointsForPush() 取全量最新点，broadcastScoped("POINTS", ...) 按会话过滤。
增量事件
pushRisks/pushAlarms：LambdaQueryWrapper gt(游标) orderByAsc limit 50；取到则先把游标推进到本批最大 id，再 broadcastScoped("RISK"/"ALARM")；单拍超 50 条时下一拍继续追。

选择 id 游标而非"最近 2 秒时间窗口"的原因：调度抖动会让时间窗口丢消息或重复；id 单调递增天然有序，游标语义不丢不重（项目避坑经验固化）。

7.4 最新点查询的 LATERAL 优化

推送与大屏/下拉共用的"每终端最新点"查询在 GpsPointMapper.listLatestPoints（module-trajectory）：

  • 写法：以 traj_terminal（valid_mark=1）为驱动表，CROSS JOIN LATERAL 对每台终端沿 idx_traj_gps_point_identity_time 做 ORDER BY gps_time DESC LIMIT 1 索引探测。
  • 效果：原 DISTINCT ON 全量扫索引约 53s，改造后约 0.5s（500 终端）；同文件的 listActiveVehicles（在途车辆下拉）由约 19s 降至亚秒级（SQL 注释内实测口径）。
  • 范围参数：plates=null 不限制；空集合由调用方提前返回不入 SQL。推送链路传 null（全量查出后发送环节过滤），HTTP 链路（/api/traj/latest）传入当前用户可见车牌集（见 MOD-DBD-004）。

7.5 大屏六块聚合

区块SQL / 逻辑口径要点
① 在线率selectOnline：vehicle→有效绑定→terminal→相关子查询 max(gps_time)窗口内有定位记在线；onlineRate 四位小数（vehicleTotal=0 时 null，前端显"—"）；窗口分钟经 make_interval(mins => #{n}) 参数化
② 今日里程selectTodayMileage：当日按 identity_code 分组，Σ(max(mileage)−min(mileage))里程表差值近似口径（页面标注）；仅计 mileage 非空点
⑤ 工单积压selectWorkOrder：mon.risk_work_order 上 FILTER 聚合pending/processing/overdue（overdue=1 且未闭环）+ 近 7 日 closed/created；closeRate=closed7d/created7d（分母 0 时 null）；FILTER 必须紧跟聚合函数（项目避坑经验）
⑥ 车队 TOP8selectFleetStats：dept JOIN vehicle LEFT JOIN 绑定/终端 LEFT JOIN LATERAL 最新点按在线数降序再按总数，LIMIT 8；deptId 用 ToStringSerializer 输出（前端 string）
⑦ 区域 TOP8selectRegionVehicleCounts + selectRegionRiskCounts 两路查询 Java 合并按注册地 city_code 分组（空串归"未知"）；合并后按车辆数降序取前 8；city_code 库内存中文城市名，无城市字典表，直接回显 code 作为名称
⑩ 风险热力selectRiskHeat：近 24h risk_event 按 0.02°×0.02° 网格聚合count 降序封顶 500 格；格内取 max(risk_level) 供前端着色；v1.1.0 大屏去地图后前端暂不消费，接口保留向后兼容

范围裁剪：summary() 先取当前用户 deptScope——null 不限制；空集合直接返回 closedSummary（全零结构，含 serverTime 与窗口分钟），不进任何 SQL；非空则车辆类聚合按 dept_id IN、事件/工单类聚合先换算车牌集再 plate_no IN。

在线窗口配置：每次请求实时读 traj.sys_config 键 monitor.online.window.minutes；键缺失、非数字、≤0 或 >1440 一律回落缺省 5。该键不在种子脚本内（12-dashboard.sql 注释声明由运维在 F35 系统参数页按需新增）。

两处注释与行为的偏差（以代码行为为准）：① DashboardController 类注释仍写"无数据范围裁剪"，系 2026-10-05 数据权限改造前的旧文，Service 实际已实现逐块裁剪；② DashboardMapper.selectFleetStats 注释注明：MOD 原文限定 dept_type=2（车队），现库挂车部门均为 dept_type=1，严格过滤将恒空，实现按"全部有效部门"分组（实施记录已注明）。

7.6 车辆面板聚合与轨迹抽稀

入参与存在性
路径变量 vehicleId 为 String 手动 Long.parseLong（非法 → 40001，不依赖类型转换异常处理）；selectVehicle 查不到（不存在或已软删）→ 40401"车辆不存在"。
数据范围校验
checkDeptScope：allData 放行；scope 空集 → 40301；车辆 deptId 为 NULL 或不在 scope → 40301"无权查看该车辆"。
关联聚合
当前有效绑定终端（bind_time 最新一条）、在班司机（按 driver_type、bind_time 排序，主班在前）；无终端时 latestPoint=null、当日轨迹返回空结构。
当日轨迹抽稀
selectTodayPoints 升序取当日原始点（单车当日万级以内）；≤500 直接返回（sampled=false）；>500 按等间距步长取 500 个下标，首末点强制保留（sampled=true，totalPoints 带原始总数）。
报警与计数
selectLatestAlarms 按车牌取最新 5 条（JOIN base_warn_type 带类型名）；countTodayAlarms / countTodayRisks 当日计数。

在线判定双口径（现状）：后端 latestPoint.online 用墙钟 now().minusMinutes(5) 固定 5 分钟窗口；前端抽屉优先使用调用页传入的 online prop（监控页按 refTime 数据时基 + 所选窗口计算），prop 未传才回退后端口径。历史数据集演示时应由监控页传 prop，避免墙钟口径把全部车辆误判离线（项目避坑经验固化的统一口径）。

8 数据流程

端到端实时链路（以"终端上报一个定位点/报警到坐席看到"为例）：

数据落库
processing-service（模拟器/接入）写 traj_gps_point / traj_warn_info；风控规则引擎写 mon.risk_event（见 MOD-DBD-004 与风控模块）。
调度轮询
RealtimePushScheduler 每 1s：LATERAL 查全部最新点；按 id 游标查新增风险与报警（各 ≤50）。
逐会话过滤
broadcastScoped：WsScopeResolver 把会话 uid 换算成可见车牌集；null 共享序列化、空集跳过、非空按范围签名缓存。
浏览器接收
useRealtime 按 type 分发：监控页差分刷车标/统计（大屏则聚合车速分布与排行），RISK 弹提示 + 飘条，ALARM 弹提示 + 滚动条置顶。
断连兜底
WS 断开 → 5s REST 轮询（/api/monitor/overview + /api/traj/latest，均按 HTTP 链范围过滤）+ 指数退避重连；恢复后停轮询。

大屏聚合链路：浏览器每 30s GET /api/monitor/dashboard/summary → DashboardController（monitor:dashboard:view）→ DashboardService 读窗口配置 + deptScope 判定 → DashboardMapper 六组 @Select 聚合（跨 schema 直查）→ DashboardSummaryVO 一次返回；WS 增量消息在两次轮询之间即时修正车速分布与报警滚动条。

12 技术选型依据

  1. 服务端单向推送，而非双向订阅协议：消息主题固定三类、无订阅管理诉求；TextWebSocketHandler + 定时调度即可覆盖，客户端实现（useRealtime 130 行）保持轻量；双向能力以注释预留。
  2. 发送环节过滤 + 范围签名序列化缓存，而非每会话一次查询：N 个会话共享 1 次 LATERAL 查询；不限范围的会话共享同一份 JSON，同范围会话共享过滤结果，把每秒成本压到最低。
  3. id 游标而非时间窗口：调度抖动下时间窗会丢/重；id 单调有序，"gt 游标 + limit 50"不丢不重，重启以 max id 初始化避免回放历史（项目避坑经验）。
  4. 终端表驱动 + LATERAL 取最新点：对 890 万行轨迹大表，DISTINCT ON 全量扫索引约 53s；LATERAL 把探测次数降到终端数量级（约 0.5s），使 1s 推送节拍可行。
  5. 新连接首帧快照 pushPointsOnce：否则首屏要等下一拍（最坏 1s 空白）；首帧同样按该会话范围过滤，不绕过权限。
  6. 当日轨迹 Java 端等间隔抽稀，而非 SQL 抽稀或前端抽稀：单车当日点量万级以内，一次取出后 Java 等间距取 500 个下标，首末必留；SQL 保持简单索引扫描，前端拿到即可直接渲染。
  7. 前端在线判定用 refTime 数据时基，而非墙钟：演示用历史数据集的数据时基滞后墙钟十几小时，墙钟口径会把全部车辆误判离线；以"全局最新点 gpsTime"为参考则两种场景都正确（项目避坑经验固化的统一口径）。
  8. divIcon 签名脏检查，而非每秒全量 setIcon：500 标记每秒重建 DOM 会造成明显抖动；仅"状态|方向|车型"签名变化才重建图标，setLatLng/zIndexOffset 同样先比较再调用。
  9. rosterSig 结构签名，而非直接 watch 点数据：车辆树结构只在"车牌集合/归属/绑定/部门"变化时重建，每秒的点更新不冲掉树的搜索与展开状态。
  10. 高德 Key 服务端代理：Key 不出现在前端产物；GCJ-02 与底图同系直接透传；统一错误归一（50301 未配置/服务不可用，50000 上游失败）。
  11. WS 与 HTTP 共用 PermissionCache：权限数据一处加载两处使用，角色调整后两条链路在同一 TTL（120s）内收敛，不会出现"页面已受限但推送仍放行"的窗口。
  12. 大屏 30s 轮询 + WS 即时修正：聚合六块没必要秒级重算；轮询保底口径一致，RISK/ALARM/POINTS 消息在间隔期内即时修正视觉，成本与时效平衡。

15 边界行为与常见问题

为什么打开监控页先闪一次轮询数据？
useRealtime 挂载时并行执行 pollOnce（REST 拿 overview + 最新点）与 WS 建连，首屏不依赖 WS 握手时序；WS 连通后由推送接管，轮询停止。
WS 断开后页面会怎样？
顶栏胶囊变"降级轮询 · 5s"：每 5 秒轮询 overview + latest 保底；同时按 1s、2s、4s…（封顶 30s）退避重连，成功后自动切回"实时连接 · 1s 推送"。
历史数据集里车辆为什么曾全显示离线？现在怎么判在线？
早期按墙钟判定，历史数据时基滞后墙钟导致全离线；现统一用 refTime（全局最新定位时间）− 窗口（默认 10 分钟，可切 30/60/1440）判定，真实终端与历史数据集两种时基都正确。
受限用户会收到范围外的 WS 消息吗？
不会。broadcastScoped 逐会话过滤：范围为空集合的会话直接跳过；非空范围只收集合内车牌的消息；过滤在服务端发送环节完成，范围外数据不出平台进程。
重启后端会重演历史报警/风险推送吗？
不会。游标在启动时初始化为两张表的当前最大 id，只推启动后的新增记录。
大屏区域分布为什么城市名直接是中文或"未知"？
traj_vehicle.city_code 实际存中文城市名（如"上海市"），库内无城市字典表；空 code 归"未知"，其余直接回显该值作为名称（代码注释口径）。
详情抽屉的"在线"标签与面板接口的 online 字段为什么不总一致？
抽屉优先用调用页传入的 online（refTime 口径）；接口 latestPoint.online 是后端墙钟 5 分钟口径。历史数据集场景应以页面传入为准。
气泡里文字地址一直显示"地址解析中…"？
多半是 AMAP_KEY 未配置（接口返回 50301）；同一坐标会话内不会重复请求（geoFailed 记录），配置生效后需刷新页面重试。
为什么右键有时点不中车标？
Leaflet popup-pane 层级（700）高于 marker-pane（600），打开的气泡会遮挡下方车标右键命中；实现已对车标注册 contextmenu 处理并对地图 contextmenu 统一 preventDefault，自动化验证可对元素派发 MouseEvent('contextmenu')。
风险"处置"按钮和工单是什么关系？
监控域的 handle 是轻量闭环入口（写 handleStatus + 备注），与工单处置共用权限码 risk:order:handle 与同一审计动作；完整的派单/流转/逾期管理在风控工单模块。
同一人开两个标签页，推送会重复吗？
每个标签页是独立 WS 会话，各自独立接收（按各自范围过滤）；SessionRegistry 的 uidSessions 支持同用户多会话并存，F19 定向推送会送达该用户全部在线标签。
大屏钻取报警中心为什么列表有时为 0？
大屏按"今日"（墙钟）带 beginTime/endTime 钻取；若演示数据时基滞后墙钟，今日窗口内无记录属正常，改带数据所在日期的时间窗即可（项目避坑经验）。
