MOD-DBD-015 轨迹实时处理（规划）

编号：MOD-DBD-015｜版本：v1.0.0｜日期：2026-10-05｜ 状态：规划中｜覆盖功能项：F08～F12｜ 代码锚点：processing-service/app（routes/ingest.py、cep_engine、services/geocode）、02-traj-tables.sql
产品篇

1. 模块定位与功能范围

轨迹实时处理模块位于终端接入与业务消费之间：对网关送入的原始定位点依次完成清洗校验、坐标转换、地图匹配、轨迹压缩与行驶统计派生，向下游监控、风控、报表提供"干净、统一、轻量、可统计"的轨迹数据。

功能项名称核心职责
F08数据清洗与校验必填/范围/物理合理性校验，异常点、漂移点识别，脏数据隔离而非删除，质量指标产出
F09坐标体系转换WGS-84（终端原始）→ GCJ-02（平台展示）统一在接入层完成；分析侧保留 CGCS2000/WGS-84 口径
F10地图匹配吸附道路、赋道路 ID/限速/行政区，支持超速判定与区划统计
F11轨迹压缩在线道格拉斯-普克（DP）+ 死区过滤，降低存储与前端渲染压力 50%～80%
F12行驶统计实时派生实时里程、行驶时长、夜间行驶、区划停留、围栏进出，为 F42～F52 系列报表提供统一派生层
F08～F12 均为设计规划，2026-10-05 时点平台没有任何清洗、转换、压缩、统计环节，定位数据由 /api/ingest/traj 与 CSV 导入直插 traj_gps_point。

2. 术语与坐标系

术语含义
WGS-84GPS/北斗原始定位采用的地心坐标系；JT/T 808 终端上报坐标即 WGS-84（CGCS2000 与 WGS-84 在民用精度下基本一致，分析侧可互换口径使用）。
GCJ-02（火星坐标）国测局加偏坐标系；高德/腾讯底图使用。平台 Leaflet 底图为高德瓦片，点位必须为 GCJ-02 才能与道路对齐。
异常点违反必填、取值范围或物理可能性（如瞬时速度 >300km/h、瞬移）的定位点。
漂移点定位抖动产生的噪声点：前后点方向/速度矛盾、点偏离真实行驶轨迹，需滤波或丢弃。
脏数据隔离区不直接删除可疑点，而打质量标记/移入隔离表，供人工复核与回流（对齐 F36 数据质量）。
DP 压缩Douglas-Peucker 算法：用点到首尾连线的垂直距离递归抽稀，保留轨迹形状关键点。
死区过滤车辆静止/微动时，位移小于阈值（死区半径）的连续点只保留代表点，消除静止漂移簇。
派生统计以定位点流实时计算的里程、时长、停留、夜间、区划等二次数据，与原始点分层存储。

4. 目标处理流程

① 原始点到达
来自 MOD-014 网关（Kafka 消费）或现有 HTTP/CSV 通道，携带 gpsTime、WGS-84 经纬度、速度、方向、海拔、报警标志。
② F08 清洗校验
必填 → 范围 → 物理合理性（瞬时速度/瞬移/时钟偏差）→ 滤波判漂移；通过点放行，可疑点打标/隔离。
③ F09 坐标转换
WGS-84 → GCJ-02 后写展示列/location；原始坐标留 ext，供分析使用。
④ F10 地图匹配
道路吸附（PostGIS 路网最近边 + 方向约束），赋道路 ID、限速、行政区。
⑤ F11 在线压缩
死区过滤 + 流式 DP 判定关键点；原始点与压缩标记分层，回放默认用关键点序列。
⑥ F12 统计派生
按车辆维护有状态计算：增量里程、行驶/停车段切分、夜间标记、区划与围栏进出，写派生表/更新当日分片。
⑦ 下游分发
监控 WebSocket（范围过滤）、CEP 引擎、报表派生层、F36 质量统计各取所需。

6. 业务价值

  • 数据可信：异常与漂移不直接进入业务，监控不"见鬼"、超速有道路限速依据。
  • 坐标统一：一次转换、全平台一致，根除"WGS-84 点叠高德图偏移几百米"的系统性事故。
  • 降本提效：压缩降低存储与前端渲染成本；派生统计让 10+ 报表共享同一口径，避免每个报表各写一套里程算法。
  • 质量可运营：质量指标反推终端设备质量，形成"平台发现坏设备 → 运维更换 → 指标改善"闭环（F36）。
  • 可回溯：原始点、清洗标记、压缩标记分层保留，统计可按补传点（F04）回补重算。

  • routes/ingest.py：鉴权（X-Service-Token）→ 批量插点 → 旁路 cep_engine.evaluate_points；无校验、无转换。

  • 原始点不物理删除：清洗结果以 qc_status（OK/SUSPECT/REJECT）与 qc_reason 标记；REJECT 点不进业务统计但可查、可回流（对齐 F36 隔离区原则）。

9.1 五条设计原则

  1. 原始不可变：任何环节只追加标记、不改原始坐标与字段。
  2. 判定函数单一来源：F08 与 F59 共用错误/漂移规则代码，口径只维护一处。
  3. 坐标系显式化：每条数据必须带来源坐标系声明，无声明数据按异常隔离处理。
  4. 统计一处派生多处消费：里程/时长只在 F12 算一次，报表只读派生层。
  5. 可降级：匹配/逆地理等外部依赖故障时降级为无匹配直采，主链路不断。

10. F08 数据清洗与校验（设计规划）

本节为设计规划，尚未实现。

10.1 校验规则链（蓝图 §3.3 口径）

#规则判定口径处理
1必填校验时间、经纬度、速度缺失REJECT，reason=MISSING_FIELD
2陆域范围经纬度不在中国陆域合理范围（粗略包围盒 + PostGIS 国境校验备选）REJECT，reason=OUT_OF_RANGE
3瞬时速度速度 > 300 km/hSUSPECT/REJECT，reason=SPEED_IMPOSSIBLE
4瞬移检测与邻点距离 ÷ 时间差得到的等效速度物理不可能（超交通工具上限）SUSPECT，reason=TELEPORT
5定位无效标志0x0200 定位状态位为"未定位"SUSPECT，reason=GNSS_INVALID
6漂移检测Kalman 预测残差超限 / 速度方向约束矛盾（前后点方向与速度不自洽）SUSPECT，reason=DRIFT
7时钟偏差gpsTime 与平台时钟偏差 > 30 秒（实时点）保留点 + 告警 reason=CLOCK_SKEW

10.2 清洗策略

  • 硬错误（缺字段、越界、未定位）直接 REJECT 打标，不进派生统计；软错误（瞬移、漂移）先 SUSPECT，结合邻点窗口（前后各 1～3 点）二次确认。
  • Kalman 滤波用于平滑展示位置，不回改原始坐标；平滑结果只写展示/匹配辅助列。
  • 静止漂移簇（死区内抖动）不在 F08 删点，交由 F11 死区过滤统一处理。
  • 质量计数（接收/有效/异常/漂移/越界）按终端、按小时聚合，供 F36 五维指标与终端画像。

10.2.1 判定算例

样本邻点事实判定
A 点速度 350km/h前后点速度 40～50km/hSPEED_IMPOSSIBLE；单点先 SUSPECT，若终端连续多点超阈则 REJECT
B 点与前点相距 3.2km、时间差 10 秒（等效 1152km/h）后点回到前点附近 50 米TELEPORT，典型隧道口单跳漂移，SUSPECT 后由后点确认丢弃
停车点簇 200 点散布半径 25 米速度均≈0F08 不判异常；交 F11 死区压缩
C 点 gpsTime 比 receive_time 快 48 秒终端时钟快CLOCK_SKEW 告警，点保留参与统计（时间未倒挂）
D 点 gpsTime 晚于 receive_time 20 小时以上终端时钟错或报文重放对齐 F59 错误规则，REJECT 并计入错误定位数
连续三点方向 10°→170°→12°、速度连续中间点速度方向矛盾DRIFT SUSPECT，Kalman 平滑用于展示

10.3 衔接、依赖与验收

依赖
F01 数据通道（网关提供定位状态位与原始标志）；F36 消费质量统计
衔接现有
F59 轨迹完整率的"错误五规则 + 漂移规则"与本规则链共用一套判定函数，避免两处口径分叉
  1. 构造缺经纬度、越界点、350km/h 点、瞬移点、未定位点各 100 条，qc_reason 分类准确率 100%。
  2. 真实/仿真轨迹中人工标注的漂移点召回率 ≥95%，正常点误杀率 ≤0.1%（对齐蓝图异常点 <0.1% 目标）。
  3. REJECT 点不产生里程、不触发超速报警，但在隔离查询页可查且可人工回流。
  4. 时钟偏差 >30 秒的终端出现在质量告警列表。
  5. 清洗通过率、异常率按终端/小时聚合数值与样本 SQL 直算一致。

11. F09 坐标体系转换（设计规划）

本节为设计规划，尚未实现。当前无任何坐标转换代码，全部点位被直接当作 GCJ-02。

11.1 现状约束（代码确证）

  • GeocodeController 注释原文口径：平台点位与高德底图同为 GCJ-02，直接透传；未来接入 WGS-84 原始数据"应在数据接入层统一转换"。
  • 前端 Leaflet 全部使用高德 webrd0{s}.is.autonavi.com/appmaptile?style=8 瓦片（GCJ-02）。
  • 现有 CSV / 模拟器数据均按 GCJ-02 制造与使用；真实 808 终端为 WGS-84，不转换会出现数百米系统性偏移。

11.2 设计方案

  • 转换点放在数据接入层（app/gateway mappers.py 与 ingest 入口共用同一转换函数），任何来源（网关/HTTP/CSV）都显式声明坐标源（source_crs=WGS84|GCJ02），历史 CSV/simulator 标 GCJ02 不转。
  • GCJ-02 经纬度写 lng/lat 与 location(4326 承载 GCJ-02 数值，现状如此沿用)；WGS-84 原始值留 ext.raw_lng/raw_lat，分析类需要真实距离时以原始 CGCS2000/WGS-84 坐标在 PostGIS 地理坐标下计算。
  • 算法：国测局加偏算法（纯数学实现，无外部请求），结果与公开基准点比对误差控制在 1 米内；禁止用高德 HTTP 接口逐点转（QPS 与成本不可接受），逆地理仍走现有 AmapProperties。

11.2.1 坐标双套使用规则

用途使用坐标落点
前端地图展示、轨迹回放、围栏绘制GCJ-02lng/lat、location（现状沿用）
两点距离/里程、速度复核、地理计算WGS-84/CGCS2000ext.raw_lng/raw_lat → PostGIS geography 计算
地图匹配候选检索GCJ-02（路网同坐标系导入）路网表与点必须同一坐标系，严禁混用

11.2.2 边界情形

  • 境外点：不做加偏（算法在国境内有效），source_crs 保留 WGS84 并标记，展示降级。
  • 历史数据：不批量回灌转换（模拟器/CSV 已按 GCJ-02 制造）；仅对 gateway 模式启用后新入的真实终端点执行转换。
  • 重复导入：幂等键命中时跳过，避免重复转换造成漂移。
  • 高德 key 缺失：只影响逆地理（503），不影响坐标转换本身（纯本地算法）。

11.3 验收标准

  1. 选定 20 个覆盖全国的已知 WGS-84↔GCJ-02 基准点，转换结果与基准偏差 ≤2 米。
  2. 同一点标记 source_crs=GCJ02 时不发生二次转换（幂等，不叠加偏移）。
  3. WGS-84 真实终端点转换后与高德底图道路目视对齐；原始坐标在 ext 可查。
  4. simulator/CSV 历史数据导入路径行为不变（回归测试）。

12. F10 地图匹配（设计规划）

本节为设计规划，尚未实现。当前库内无路网数据。

12.1 设计方案

  • 路网准备：导入开源路网（OSM 中国区域抽取或采购商用路网）入 PostGIS，边表含几何、方向、等级、限速、行政区 adcode；建 GIST 索引。
  • 匹配算法：在线增量匹配——以"上一点所在边 + 行驶方向 + 与候选边距离"做隐马尔可夫/权重打分，输出吸附点、road_id、限速、行政区；弱网/稀疏点（间隔 >30s）降级为最近边或不匹配（标 matched=false），不强行吸附。

12.1.1 候选边打分（简化 HMM 权重）

因子权重方向说明
点到候选边距离距离越小分越高（高斯发射概率）>50 米候选直接剔除
行驶方向与边方向夹角夹角越小分越高单行线反向候选降权/剔除
与上一匹配边的可达性沿路网最短路径越短分越高防止吸到平行辅路/高架
道路等级先验高速/主干道按速度先验加权120km/h 点不可能在支路
# 在线匹配伪代码（每点一次）
candidates = road_net.nearby_edges(p.gcj02, radius=50m)
for e in candidates:
    emit   = gauss(distance(p, e), sigma=15m)
    head   = cos_similarity(p.bearing, e.bearing_at(proj))
    trans  = route_reachability(prev_edge, e, dt)
    score  = emit * w1 + head * w2 + trans * w3 + e.prior * w4
best = argmax(score)
if best.score < TAU or p.gap_from_prev > 30s:
    p.matched = False          # 不硬吸附
else:
    p.road_id, p.speed_limit, p.adcode = best.attrs

12.2 下游用法

  • 超速报警：点速度 > 道路限速（容差按规则配置）替代/补充固定阈值，误报可解释。
  • 区划统计：F12 的行政区停留、F55/F56 企业地区维度直接取 adcode。
  • 轨迹回放：可展示"行驶道路"名称与路段里程。

12.3 验收标准

  1. 城市道路 1Hz 仿真轨迹匹配率 ≥95%，高速路段 ≥98%；匹配错误（吸到平行路）率 ≤2%。
  2. 无路网区域/低密度点不产生错误吸附，matched=false 明示。
  3. 单点匹配处理延迟 P95 ≤50ms（在线链路不阻塞）。
  4. 限速取值与路网数据版本可追溯（路网版本号落匹配记录）。

13. F11 轨迹压缩（设计规划）

本节为设计规划，尚未实现。

13.1 双层压缩策略

策略规则目标
死区过滤位移 < 死区半径（规划 15～30 米可调）且速度≈0 的连续点只保留首尾/代表点消除停车点簇，停车场景压缩明显
在线 DP流式维护候选段，点到首尾连线垂距 < ε（规划 10～25 米）判为可抽稀；转弯/变速/报警点强制保留保留轨迹形状，压缩率 50%～80%

13.2 设计约束

  • 原始点全保留：压缩只产生 keypoint 布尔标记或关键点视图，不物理删除点；取证、重算、参数调整都可回到原始层。
  • 报警点、急加减速点、补传段边界点、围栏进出点强制为关键点。
  • 回放与里程：前端回放默认关键点序列；里程统计始终基于原始有效点计算，不用压缩点算里程。

13.2.1 在线 DP + 死区伪代码

# state：anchor=段首关键点，last=上一保留点，pending=待定点
for p in valid_points(car):
    if is_forced_keypoint(p):          # 报警/急加减速/围栏/补传边界
        flush(pending); keep(p); anchor = p; continue
    if in_deadzone(p, anchor, R=20m) and p.speed ~ 0:
        pending.append(p); continue   # 静止点簇：只留代表点
    # DP：若 pending 中存在偏离 anchor→p 连线超过 ε 的点，则该点必须保留
    q = max_deviation_point(pending, line(anchor, p))
    if q.dev >= EPSILON(15m):
        keep(q); anchor = q
    pending.append(p)
flush(pending)

参数 R（死区半径）、ε（垂距阈值）均配置化并按道路等级自适应：高速 ε 可放大到 25 米，城区支路收紧到 10 米。

13.3 验收标准

  1. 城市 + 高速混合轨迹（≥1 万点）压缩率 ≥50%，压缩轨迹与原轨迹 Hausdorff 距离 P95 ≤25 米。
  2. 压缩序列中报警点零丢失。
  3. 停车 30 分钟（约 1800 个静止点）压缩后不超过 5 个代表点。
  4. 前端回放压缩轨迹首屏时间较原始点下降 ≥50%，视觉路线一致。

22. 验收标准

  1. 端到端：模拟点流经 F08～F12 后，原始点、qc 标记、GCJ-02 展示点、道路匹配、keypoint、日统计六层数据齐全且可互相追溯。
  2. 清洗规则链 7 类规则各有可复现样本，分类正确，隔离点可回流。
  3. 坐标转换基准点误差 ≤2 米，且无二次偏移。
  4. 在线匹配城市道路匹配率 ≥95%，单点 P95 ≤50ms。
  5. 压缩率 ≥50% 且形状误差 P95 ≤25 米，报警点零丢失。
  6. 派生里程闭合路线误差 ≤2%，重启/重平衡后统计无重复无丢失。
  7. 补传点正确回补历史日分片。
  8. 全链路 P95 处理延迟满足实时监控目标（目标值在 P0 压测后固化，参考 ≤3 秒事件及时性蓝图指标）。
  9. 影子运行期间，旁路日统计与现网原始点 SQL 重算逐日对账，差异为 0（或全部可解释）后方可切换。
  10. 关闭路网匹配依赖（模拟故障）后，主链路不中断，matched=false 且监控延迟无明显抬升。
  11. 19.1 全部链路指标可按终端、企业维度查询，数据与样本直算偏差为 0。
  12. 同一辆车的实时点与补传点乱序到达时，按 gps_time 归位后统计结果与顺序到达完全一致。
  13. F09 转换幂等：对已入库点重复执行转换不产生二次偏移，raw 原始坐标保留不变。
  14. 下游报表（F42/F52）抽样 50 车 ×7 天与 traj_daily_stat 直算结果一致，误差为 0。

待核实项

事项说明
location 列坐标语义现状 location geometry(4326) 实际存 GCJ-02 数值（非标准 4326 应有 WGS-84）。F09 方案沿用此事实但需在 DDL 注释中明确"列内为 GCJ-02"，避免后续误用 PostGIS 距离函数产生米级偏差——距离计算应使用 ext 中 WGS-84 坐标。
油量字段位置traj_gps_point 现无油量列；F49 油耗依赖该列，18 号迁移是放 ext 还是独立列需与 MOD-017 详设共同确认。
路网数据来源OSM 抽取（免费但限速/限行不全）vs 商用路网（成本）未定，影响 F10 精度与采购。
Flink 引入时点本文按 Python 有状态消费者设计；十万车以上或复杂事件窗口需求出现时需重新评估。
夜间时段/停车/死区阈值蓝图给出方向值（22:00～06:00、3 分钟、15～30 米），需业务确认并配置化。
跨零点里程切分口径按时间比例还是就近切点分配里程，两种实现会造成日里程微小差异，详设需固定并补对账用例。
Kalman 平滑结果是否回放可见当前设计平滑值仅辅助匹配，不回写展示；若监控大屏需要"平滑轨迹"模式，需另增展示列与前端开关。
