MOD-DBD-010 驾驶评分与风险画像

文档编号 MOD-DBD-010|版本 v1.0.0|发布日期 2026-10-05| 状态 已上线|功能编号 F22（驾驶评分）/ F23（风险趋势与画像）

事实基准：2026-10-05 源代码（module-analysis）与 14-driving-score.sql、15-risk-profile.sql

主要代码锚点：ScoreController / ScoreCalcService / ScoreScheduler / ScoreConstants、ProfileController / ProfileCardService / ProfileSupport / ProfileEventMapper / ProfileOrderMapper；前端 analysis/ScoreList.vue、analysis/RiskProfile.vue、api/analysis.ts

1 功能概述

1.1 模块定位

本模块在风险事件与轨迹数据之上提供两类只读分析能力，包名 com.mydbd.analysis[.profile]，菜单挂在"分析决策"目录：

  • F22 驾驶评分（日评）：每日 T+1（次日 01:00）按"当日生效的车-终端-司机绑定"把前一天的风险事件与急加减速折算为 0~100 分与 A~E 五级，写入 mon.driver_score，支持查询、趋势、特征明细与授权人员手动重算。
  • F23 风险趋势与画像：对全网 / 部门 / 司机 / 车辆四类对象，按日 / 周 / 月给出事件趋势、构成、处置漏斗、评分概览、黑点路段网格、司机 / 车辆风险排行。画像模块不建新表，只对 traj 主数据与 mon 风险表做聚合查询。

一句话边界：评分是"每天一行"的离线批计算（可重算、结果落表）；画像是"每次请求实时聚合"的在线查询（不落数据）。两者数据来源相同但口径并不完全一致，最典型的是司机 / 车辆关联口径与漏斗闭环时基，使用前务必读 1.4 与 7.9。

1.3 术语与概念

术语含义
日评 driver_scoremon.driver_score 一行 = 某司机某自然日的评分结果，唯一键 (score_date, driver_id)，无逻辑删除。
当日生效绑定评分归属口径：车辆-终端-司机绑定记录（driver_type=1 主班、valid_mark=1）与评分日时间窗有交集即视为当日驾驶；同日多车合并计评。
当前绑定画像 / 排行的人车归属口径：traj.traj_vehicle_driver 中 status=1 的在效绑定，只反映"现在"，不回溯历史。
扣分白名单ScoreConstants 中 8 个参与评分的事件码：SPEED_GENERAL / SPEED_SEVERE / FATIGUE_DRIVE / DSM_FATIGUE / DSM_DISTRACTION / ADAS_FCW / ADAS_LDW / COMBO_FATIGUE_SPEED。
当日等级 MAX 口径同一车牌 × 同一事件码当天有多条事件时，取 MAX(risk_level) 作为该码当日等级，只扣一次分。
误报排除事件对应工单以 FALSE_ALARM 闭环后，评分聚合 SQL 用 NOT EXISTS 排除该事件，不扣分。
急加减速派生事件不属于 risk_event；由评分任务直接从 GPS 点计算：|a| ≥ 2.5 m/s²，连续同向合并，HARD_ACCEL / HARD_BRAKE 各封顶扣 5 分。
样本门槛当日 GPS 样本点 ≥ 200 且累计驾驶时长 ≥ 30 分钟才出分；不足则删除当日旧行并跳过（视为无评价日）。
空桶补零趋势按日 / 周 / 月补齐时间轴，没有事件的桶返回 0，保证折线连续。
左闭右开画像时间参数统一 [start, end)；按天查询传 end=次日，结束日当天数据需 end 取到下一天。
网格近似黑点ST_SnapToGrid 在 EPSG:3857 米制网格吸附聚类，质心不对应真实路段，VO 标注 approx=true，F10 路网匹配后再升级。

1.4 两套"人 / 车 / 企"口径

同一套系统里存在两套人车关联口径，排查"分数 / 排行对不上"时先确认用的是哪一套：

议题驾驶评分（F22）画像 / 排行（F23）
人车关系"当日生效绑定"：绑定时间窗与评分日有交集即可，主班 driver_type=1"当前 status=1 绑定"：只看查询时刻在效关系
同日多车同一司机当天在多辆车的事件 / 急加减速合并到同一日评分，扣分重新合计并重新封顶车辆榜按车牌独立加权；司机榜再把车牌分经当前绑定映射给人
部门口径dept_id 取司机 / 车辆归属（写入当日快照）dept 维度为本级精确车辆，不含子部门
事件范围仅 8 个白名单码；FALSE_ALARM 排除；同日同码取 MAX 等级全部事件码（含围栏 GEO_*），不排除误报，按 COALESCE(event_time,create_date) 统计
闭环时基不统计闭环，只看事件与工单结果工单漏斗按 create_date，而对象卡 closedTotal 按 close_time（两处时基本就不同）

1.5 本期边界（不做什么）

  • 不做实时 / 行程级评分：只有按自然日的司机日评，不按单次行程、单趟运输任务计分；当日中途入职 / 离职按绑定时间窗自然截断，不做按小时折算。
  • 不做评分规则的页面配置：白名单 8 码、8/4/2 扣分、2.5 m/s² 阈值、200 点 / 30 分钟门槛全部固化在 ScoreConstants，调整需改代码发布，不进系统参数中心。
  • 不做考核处罚动作：模块只产出分数 / 等级 / 排行，不挂钩罚款、派单限制或自动培训单；触发处置仍由工单与人工流程承担。
  • 不做短信 / 推送报表：评分与画像不触发通知中心任何消息，日报 / 周报导出不在本期范围。
  • 不做真实路网黑点：黑点为网格质心近似，不做地图匹配 / 道路绑定 / 历史路段重算（规划见 F10）。
  • 画像不做写操作：四个接口全部 GET，不提供标注、备注、黑名单等回写能力，也不产生任何审计业务数据。

2 典型场景

车队长 · 晨会复盘
查看昨日全队驾驶评分
打开分析决策 → 驾驶评分，默认近 7 天列表按分数升序，D/E 级司机排在最前；点行展开抽屉看 30 天趋势与 Top3 扣分项，晨会直接点名教育。
安全管理员
误报闭环后修正分数
某条超速事件被核实为设备误报并以 FALSE_ALARM 闭环后，管理员对该日发起区间重算，重算结果不再为该事件扣分，等级可回升。
安全管理员 · 态势分析
全网风险趋势与构成
风险趋势与画像页全局时间条选择上月，按周查看事件量空桶补零折线与事件码构成 Top5，判断风险是在走高还是收敛。
调度监控员
一司机 / 一车辆画像
对象画像卡输入司机或车牌，一次看到概览、事件构成、处置漏斗、评分摘要与未闭环 Top5 工单，点工单直接跳工单中心处理。
安全管理员 · 黑点治理
识别事故多发路段
黑点路段 Tab 选 200 米网格与时间范围，地图上按网格质心展示高发位置；页面明确标注为网格近似口径，用于安排路面排查而非执法取证。
企业管理层
月度红黑榜考核
对比排行 Tab 切换司机榜 / 车辆榜，按区间加权风险分排序导出讲评依据；司机排名按当前在聘绑定归属，已离职司机不会因历史绑定入榜。

3 操作流程

两个入口均为分析决策目录（sys_menu parent=300）下的菜单项：驾驶评分菜单 id=301，路由 /analysis/scores，权限 analysis:score:view；风险趋势与画像菜单 id=302，路由 /analysis/profiles，权限 analysis:profile:view（角色授权见种子）。

3.1 驾驶评分列表

进入页面
分析决策 → 驾驶评分（ScoreList.vue）。默认查询近 7 天评分，顶部 4 张 KPI 卡展示平均分、参评司机数、A 级占比、D/E 级人数等汇总。
筛选
按日期区间（默认近 7 天）、车牌 / 司机关键字、等级（useDict('score_level') 渲染 A~E）筛选后查询；size 钳制 1~100。
看排序
后端固定排序 score_date DESC, score ASC：日期新的在前，同一天分数低（风险高）的在前，红榜导向明确。
点开详情
点击任意行打开右侧抽屉，展示该司机 30 天评分趋势、当日特征明细与 Top3 扣分项（见 3.2）。

3.2 评分详情抽屉

  • 趋势图：进抽屉调 GET /api/analysis/score/trend（driverId 必填，默认 30 天，最长 92 天），ECharts 折线展示每日分数，缺失日（未出分）断点。
  • 特征明细 features：driver_score.features jsonb 中固定 10 个键的中文映射（FEATURE_NAMES），含各事件码计数与 HARD_ACCEL（急加速）、HARD_BRAKE（急减速）次数、sample_points、driving_minutes、event_count。
  • Top3 扣分项：前端按 features 中各扣分项折算值排序取前三，让坐席一眼看到"分扣在哪"。
  • 等级标签：level 与 score 双显，A 优秀 / B 良好 / C 合格 / D 较差 / E 危险，中文名来自字典 score_level。

3.3 手动重算

权限可见
重算按钮仅当前用户 roles 含 SUPER_ADMIN 时出现（canRecalc）；后端二次校验 superAdmin 标志或角色码 SUPER_ADMIN / SAFE_ADMIN，不满足返回业务码 40301。
选择日期区间
RecalcRequest 传 start / end（yyyy-MM-dd）：跨度 ≤ 92 天、end ≤ 今天；参数不合法返回 46001；已有重算任务进行中返回 46002。
异步执行
接口立即返回，由单线程 daemon ExecutorService（线程名 score-recalc）逐日串行重算，期间定时日评也会被互斥挡住，避免并发写同日数据。
结果校正
重算为"删除当日旧行后重建"语义（deleteDayExcept + upsert）；误报事件被排除、补录事件被纳入，完成后刷新列表即可看到新分数。

3.4 风险趋势与画像四 Tab

分析决策 → 风险趋势与画像（RiskProfile.vue）。页面顶部为全局时间条（区间 + 粒度 day/week/month），下方 4 个 Tab：

Tab操作与内容主要接口

对象画像类型 vehicle / driver / dept 三选一 + 输入对象，出概览 KPI、事件构成、处置漏斗、评分摘要、未闭环工单 Top5（risk_level DESC, overdue DESC, event_time DESC）GET /profile/object-card
黑点路段半径（网格）100 / 200 / 500 米默认 200、limit 1~50 默认 20；Leaflet 地图展示网格质心圆与计数，弹窗明示"网格聚类近似口径"GET /profile/hotspots
对比排行司机榜 / 车辆榜切换；工单 Top5 行可点击跳转 /risk/orders 处理GET /profile/ranking

时间参数格式统一为 yyyy-MM-dd'T'HH:mm:ss，区间语义 [start, end) 左闭右开；跨度超过 366 天返回 46101，时间格式错误 40001，维度非法 46102，对象不存在或越权 40401。

5 用户价值

无扣分日满分；下限兜底为 0，不为负
5 级
A ≥90 / B ≥75 / C ≥60 / D ≥40 / E <40
T+1
每日 01:00 自动出前一日评分
92 天
手动重算与趋势查询的最大跨度
  • 考核可量化：事件等级、急加减速都折算为统一分数与等级，把"感觉这个司机危险"变成可排名、可追溯的日指标。
  • 口径克制：同日同码只按最高等级扣一次、误报闭环可剔除、样本不足不出分，避免"点多分低、误报冤枉人"。

  • 黑点可定位：即使没有路网匹配，米制网格质心已足够支持"哪片区域高发"的路面排查排序。

6.1 前端实现要点

7 核心实现逻辑

7.1 日评计算总流程

ScoreCalcService.calcDay(date, onlyDriverId) 是定时与手动重算共用的唯一入口，六个步骤顺序执行：

① 查当日绑定 selectBindings
取当日车-终端-司机绑定：主班 driver_type=1、valid_mark=1，绑定 / 解绑时间窗与评分日有交集；ORDER BY bindTime DESC，用 Map.putIfAbsent 保留每车最新一条有效绑定。关联键统一用 plate_no(vehicle_no)。
② 事件聚合 selectEventAgg
一条 SQL 按车牌 × 事件码聚合当天白名单事件：等级取 MAX(risk_level)；NOT EXISTS 排除已被 FALSE_ALARM 闭环的事件。
③ GPS 逐车派生 selectGpsPoints
逐车取当天轨迹点，调 deriveHardEvents 算急加 / 急减并累计驾驶秒数（见 7.4）。
④ 门槛校验
sample_points < 200 或 driving_minutes < 30：删除该车 / 司机当日旧评分行后跳过——该司机当日不出分。
⑤ 计分定级
score = max(100 − 事件扣分 − 急加减速扣分, 0)，保留 1 位小数；按 90/75/60/40 边界定 A~E 级。
⑥ 多车合并 + upsert
mergeDriver 把同司机多辆车的计数累加后重新统一扣分 / 封顶；deleteDayExcept 清扫后 INSERT … ON CONFLICT(score_date,driver_id) DO UPDATE。

7.2 当日生效绑定选择

  • 绑定来源 traj.traj_vehicle_driver（车-终端-司机绑定表），只取 driver_type=1 主班且 valid_mark=1；副班驾驶不计入当日主评分人。
  • 时间窗交集：bind_time ≤ 评分日结束、unbind_time 为空或 ≥ 评分日开始，换班 / 解约会改变次日归属。
  • 同日同车多条绑定：按 bind_time DESC 排序，putIfAbsent 取最新一条。
  • 人车关联键全程使用 plate_no（车辆 vehicle_no），与事件表、GPS 点表的车牌口径一致，不依赖终端号。
  • 只在评分这一天看"当天谁在开"：这与画像排行按"当前 status=1 绑定"的口径刻意区分（见 1.4）。

7.3 事件聚合口径

白名单与扣分在 ScoreConstants 中固化：

事件码含义高 / 中 / 低扣分
SPEED_GENERAL一般超速LEVEL_DEDUCT：高 8 分 / 中 4 分 / 低 2 分（同日同码取 MAX(risk_level) 只扣一次）
SPEED_SEVERE严重超速
FATIGUE_DRIVE疲劳驾驶
DSM_FATIGUE终端疲劳信号
DSM_DISTRACTION分心驾驶
ADAS_FCW前向碰撞风险
ADAS_LDW车道偏离
COMBO_FATIGUE_SPEED疲劳叠加超速组合

旧说法纠正：早期说明曾按"每条事件逐条扣分"描述。代码实际是按车牌 × 事件码一天聚合成一条，等级取当天该码的 MAX(risk_level)；并且 NOT EXISTS 排除工单闭环结果为 FALSE_ALARM 的事件。围栏 GEO_* 事件不在白名单，从不扣分。

7.4 GPS 派生急加减速

  • 对每辆车当天 GPS 点按时间排序，相邻两点计算加速度 a = (v2 − v1)/3.6 / dt；MAX_DT_SECONDS=30：点间隔超过 30 秒不参与（避免掉线期间的虚假大加速度）。
  • 仅当 v1 ≥ MIN_SPEED_KMH=10 且 v2 ≥ 10 时计入，低速挪车不产生急加减速。
  • a ≥ ACCEL_THRESHOLD=2.5 m/s² 计一次急加速（HARD_ACCEL），a ≤ −2.5 计一次急减速（HARD_BRAKE）。
  • 连续同向合并：连续多个点同方向超阈值合并为一次，避免一脚刹车被记多次。
  • 每次扣 HARD_DEDUCT=0.5 分，急加 / 急减各自每日封顶 5 分（HARD_CAP，各 10 次）。
  • drivingSeconds 只在 v1>0 且 v2>0 的相邻点间累计，用于 30 分钟门槛与 features.driving_minutes。

7.5 门槛、扣分与等级

参数（ScoreConstants）值作用
MIN_SAMPLE_POINTS200当日样本点低于此值不出分
MIN_DRIVING_MINUTES30当日驾驶时长低于此值不出分
LEVEL_DEDUCT8 / 4 / 2高 / 中 / 低风险事件单次扣分
HARD_DEDUCT / HARD_CAP0.5 / 5急加减速单次扣分与单日单项封顶
ACCEL_THRESHOLD2.5 m/s²急加减速判定阈值
MAX_DT_SECONDS / MIN_SPEED_KMH30 / 10派生计算的点间隔与速度门槛

等级边界：A ≥90，B ≥75，C ≥60，D ≥40，E <40。该组边界同时出现在 ScoreConstants、14 脚本 score_level 字典注释、ProfileConstants 三处，取值一致但属于多点耦合，调整必须三处同步（见第 13 节）。

7.6 多车合并与 upsert

  • 步骤 ②③ 的中间结果先按车牌归集；mergeDriver 阶段按 driverId 把同一司机当天多辆车的事件计数、急加 / 急减次数、样本点、驾驶秒数全部累加。
  • 累加后重新计算扣分并重新套用封顶：事件按码重新查等级扣分、HARD_ACCEL/HARD_BRAKE 各自再次 cap 到 5 分，而不是把各车扣分值直接相加。
  • 写库前 deleteDayExcept(date, driverIds) 清掉这些司机当天旧行（门槛不足跳过的司机也会清旧行），再批量 upsert：ON CONFLICT (score_date, driver_id) DO UPDATE，保证定时跑、手动重算跑多少遍结果一致。
  • features jsonb 同步写 10 个特征键，score 为 numeric(5,1) 一位小数，最低 0 分。

7.8 画像趋势聚合

GET /api/analysis/profile/trend 的核心约定：

  • dim：global（全网）/ dept / driver / vehicle；granularity：day / week / month。
  • 聚合时间取 COALESCE(event_time, create_date)；区间 [start,end)；plateNos 为 null 表示全网。
  • 用 date_trunc + FILTER (WHERE …) 一条 SQL 出总量与各等级 / 各事件码分量；granularity 通过 MyBatis <choose> 白名单拼接，杜绝任意参数注入。
  • 空桶补零：SQL 返回的稀疏结果在 Java 侧按时间轴补齐；week 桶以周一为起点；因为 [start,end) 不含 end 当天，按"今天"查日趋势时 end 要传明天。
  • 事件构成 Top5 分两步查询（先桶总量、再 Top5 事件码）；非全网用户追加 EXISTS traj_vehicle 部门归属过滤。

7.9 对象画像卡

ProfileCardService.card(type, id, start, end)，type ∈ vehicle / driver / dept：

  • 对象解析（ProfileSupport.resolvePlates）：vehicle 校验 traj_vehicle 存在且部门归属匹配；driver 经 traj.traj_vehicle_driver 当前 status=1 绑定取车牌集合；dept 为本级精确车辆，不含子部门。对象不存在或越权返回 40401。
  • 概览 + composition：区间事件总数、等级构成、事件码构成。
  • 处置漏斗（ProfileOrderMapper）：orderTotal 按 event_time / create_date 区间；interventionTotal 为 distinct 干预工单数；closedTotal 按 close_time 区间。
  • topOrders：未闭环工单按 risk_level DESC, overdue DESC, event_time DESC 取前 5，前端可点跳工单中心。
  • fillScore：dept 取区间日均 AVG(score)，driver 取本人评分，vehicle 取当前绑定司机评分；评分读取独立 try/catch，异常时仅 scoreReady=false，卡片其余内容正常返回。

两处漏斗闭环口径不一致（以代码为准）：工单中心统计漏斗的闭环按 create_date 时基，而画像对象卡 closedTotal 按 close_time 时基。同一区间两个页面的闭环数因此可能不同，跨页对账时必须注明时基；中期应统一为同一 SQL 口径。

7.10 黑点路段（网格近似）

  • GET /profile/hotspots?radius_m=100|200|500&limit=1~50，radius_m 默认 200，limit 默认 20。
  • 事件点先转 EPSG:3857（米制）后用 ST_SnapToGrid(geom, radius_m) 吸附到规则网格，按网格单元 GROUP BY 计数。
  • 每个网格用 ST_Centroid 取质心再 ST_Transform 回 EPSG:4326，坐标保留 6 位小数返回前端打点。
  • 返回 VO 带 approx=true 与 note："网格聚类近似口径，非真实路段；F10 路网匹配后升级"——质心可能落在非道路位置（楼顶、江面），只用于区域级排序。

7.11 风险排行

  • GET /profile/ranking?dim=driver|vehicle。车辆榜：直接按车牌聚合 weightedScore = SUM(COALESCE(risk_level,2))（缺失等级按 2 兜底加权）。
  • 司机榜：先查车牌加权分，再经 当前 status=1 绑定的 allPlateDrivers 映射累加给司机——不是按历史绑定回溯。
  • SQL 层多取 500 行回到 Java 内存排序后截取榜单，避免复杂 SQL 全量映射；评分为 DISTINCT ON 批量取每对象区间最新一条，评分查询异常时该对象评分降级为 null，不影响排行出数。

事件名解析：ProfileSupport.eventName 优先级为 ①字典 risk_event_code → ②ProfileConstants.EVENT_NAME_FALLBACK（含 GEO_ENTER/GEO_EXIT、V_LDW/V_HMW/V_FCW/V_PCW、BEIDOU_SPEED、国标数字码 1~7）→ ③原始事件码，保证未知码也能展示。

12 技术选型依据

  1. 日评落表而非实时算分：评分输入是全天事件与轨迹，实时既无必要又会让列表查询扫全量事件；T+1 落 mon.driver_score 一行，列表 / KPI / 趋势都是窄表查询，并可重算校正。
  2. 一条 SQL 完成事件聚合：按车牌×事件码 GROUP BY + MAX(risk_level) + NOT EXISTS 误报排除，把逐事件循环下沉到数据库，应用层只处理"每车每天一行"的中间结果。
  3. GPS 派生放应用层：急加减速依赖相邻点差分与"连续同向合并"状态机，SQL 窗口函数可读性差；逐车取点在 Java 内推导更易调阈值（2.5 m/s²、30 秒、10 km/h）。
  4. 画像不建表、纯实时聚合：分析维度与时间窗组合太多，物化任一口径都会引入刷新一致性问题；数据量在索引支撑下可接受，换取口径永远新鲜。
  5. 黑点用 ST_SnapToGrid 米制网格而非聚类算法：一条 SQL 即可并行化、参数只有边长；质心口径的局限在 VO 中显式 approx 标注，F10 路网匹配上线后再升级到路段维度。
  6. 跨模块零代码依赖：分析域只读表不 import 业务类，配合独立包与独立菜单，避免"分析需求"反向牵动风控 / 工单代码发布。

15 边界行为与常见问题

某天某司机为什么没有分数？
三种原因：当日无主班绑定（driver_type=1 时间窗无交集）；样本点 <200 或驾驶时长 <30 分钟（系统主动不出分并清旧行）；或当天没有任何车辆绑定到该司机。
同一天开两辆车，分数怎么算？
mergeDriver 把两车事件与急加减速计数全部累加到该司机当日记录，扣分按累加后的计数重新计算，急加 / 急减各自重新封顶 5 分；只有一条 driver_score 记录，plate_no 取其中一辆（以代码装配结果为准）。
误报工单闭环后分数会自动恢复吗？
不会自动。评分是 T+1 快照，闭环发生后需超管 / 安全管理员对该日发起重算（recalc），NOT EXISTS 排除生效后分数才回升。
趋势图为什么最后一天没数据？
区间为 [start,end) 左闭右开，end 当天不包含；日趋势要看今天需把 end 传明天；评分本身也是次日 01:00 才出前一天的分。
周粒度从哪天开始？
周一。空桶补零以周一为桶起点对齐自然周。
部门画像为什么不含下级部门车辆？
dept 维度按本级 dept_id 精确匹配 traj_vehicle.dept_id，不下钻；要看全网用 global，看子部门需单独选择该子部门。
司机换车后历史排行会跟人走吗？
不会。排行司机映射只看当前 status=1 绑定，是"现在谁开这辆车"的口径；历史日评分仍按当日绑定保存在 driver_score 中。
黑点为什么落在江面上？
网格质心是米制网格几何中心，不做路网吸附；VO approx=true 已声明近似。F10 路网匹配上线后按路段聚合可解决。
重算按钮为什么看不到 / 点了 40301？
前端按 roles 含 SUPER_ADMIN 显示按钮；后端同时认 superAdmin 标志与角色码 SUPER_ADMIN/SAFE_ADMIN。账号只有 SAFE_ADMIN 角色但前端按钮不可见时，属于前后端角色集合的细微差异，需管理员核对授权（见待核实项）。
画像页闭环数与工单页对不上？
两处时基不同：画像对象卡 closedTotal 按 close_time 过滤，工单漏斗按 create_date；对账必须统一时基，属已知差异。

17 待核实项

下列条目在本期代码 / 脚本中未能闭环确认，上线前或迭代中需补充核实：

  • 重算按钮角色差：前端 canRecalc 仅判断 SUPER_ADMIN，后端还放行 SAFE_ADMIN；需确认 SAFE_ADMIN 是否应在前端直接看到重算入口，或后端收紧为仅超管。
  • 多车合并后 plate_no 快照取值：mergeDriver 写一行 driver_score 时 plate_no 取哪辆车（最新绑定 / 任一）需与业务确认；查询列表按车牌筛选时可能只命中其中一辆。
  • 漏斗时基统一计划：画像 closedTotal(close_time) 与工单漏斗(create_date) 的口径差异何时统一、以哪个为准，需产品与工单模块共同确认。
  • 黑点升级路线：F10 路网匹配的排期与"网格→路段"历史数据是否重算，尚未见跟踪任务。
  • 长区间画像性能基线：366 天 × 全网 / 月桶的实际响应时间未做压测，当前上限是经验值；上线后需观察慢查询。
  • 等级边界单点化：90/75/60/40 三处复制（含 14 脚本字典注释）暂未做启动一致性校验，调整阈值的发布流程需补充检查清单。
