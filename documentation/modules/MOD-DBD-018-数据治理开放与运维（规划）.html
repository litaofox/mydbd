MOD-DBD-018 数据治理开放与运维（规划）

编号：MOD-DBD-018｜版本：v1.0.0｜日期：2026-10-05｜ 状态：规划中｜覆盖功能项：F36～F40｜ 代码锚点：docker-compose.yml（postgres/platform-app/processing-app/portal-nginx）、AuditFilter、ingest X-Service-Token
产品篇

1. 模块定位与功能范围

本模块是平台面向规模化与合规运营的保障体系，包含五块相互独立又彼此支撑的能力：

功能项名称范围
F36数据质量管理完整性/准确性/一致性/及时性/唯一性五维指标、质量大盘、企业/终端下钻、脏数据隔离区、问题工单、终端合格率画像
F37数据安全与合规敏感字段加密（SM4 方向）、动态脱敏、分类分级、留存销毁与销毁日志、授权审批、等保 2.0 三级方向、KMS/HSM、日志 ≥6 个月
F38开放 API 与监管上报统一 API 网关（鉴权/限流/计量/审计/脱敏）、AppKey/OAuth2、按 JT/T 809 向属地监管平台转发
F39可观测与高可用Prometheus/Grafana、日志聚合、链路追踪、PostgreSQL 主从、多副本、K8s 演进、容灾（RPO/RTO）、按 Kafka Lag 扩缩
F40测试与交付CI/CD、接口自动化回归、808/1078 协议一致性双轨、海量连接压测、流媒体测试、数据迁移双人复核、环境分层、静态扫描
F36～F40 均为设计规划。2026-10-05 平台为四容器单机部署，无主从、无多副本、无 K8s、无监控系统、无链路追踪、无 CI；第 5/7 节如实陈述现状边界。

2. 术语

术语含义
五维质量指标完整性、准确性、一致性、及时性、唯一性（蓝图 §5.3）。
隔离区可疑数据不删除而打标/入隔离表，经人工复核后回流或丢弃（与 F08 共用机制）。
分类分级按《汽车数据安全管理若干规定》区分敏感个人信息与重要数据并施加不同保护策略。
KMS / HSM密钥管理系统 / 硬件安全模块；密钥与数据分离托管。
JT/T 809道路运输车辆卫星定位平台间数据交换标准（2011/2019 版）；企业平台向政府监管平台转发的协议。
RPO / RTO恢复点目标（最多丢多少数据）/ 恢复时间目标（多久恢复服务）。
三驾马车（可观测）Metrics（指标）、Logs（日志）、Traces（链路追踪）。
两地三中心生产中心 + 同城灾备中心 + 异地灾备中心的高可用拓扑（蓝图终态）。

3. 业务场景

数据质量管理员
每天看质量大盘
五维指标按企业/终端下钻，定位丢点率高、异常点多的终端设备，生成问题工单跟踪整改。

数据分级与留痕
人脸/身份证/连续行踪按敏感个人信息管控；视频调阅必须有审批单；日志按 ≥6 个月留存备查。
平台对接方
第三方系统取数
客户 ERP/BI 通过 AppKey/OAuth2 调开放 API，有配额、有限流、调用可计量、出问题可审计。
监管报送岗
属地监管平台联网
按 JT/T 809 通过专线/VPN + 前置机向监管平台转发定位/报警数据，报送状态可监控。
运维值班
故障分钟级发现
Grafana 看板 + 告警，链路追踪一次请求跨 Java/Python/Kafka，日志集中检索不用登机器。
测试/发布经理
自动化回归与协议双轨
CI 跑接口回归与静态扫描；808/1078 用测试工具 + 真实终端双轨验证；压测报告决定能否上线。

5.3 配置与密钥现状

  • 数据库口令、ingest X-Service-Token、高德 key 位于 application*.yml / 环境变量；高德 key 当前为空，逆地理返回 503。
  • 镜像 tag 与 docker-compose 手工维护；无配置中心，环境差异靠不同文件维护。
  • 规划：F38 开放平台密钥加密存储；F37 KMS 托管高密密钥；GATEWAY_MODE 等模式开关纳入环境保护，simulator/mock 禁入生产。

6. 业务价值

  • 敢接真车、敢上规模：质量、可观测、压测体系是 500 车→十万车演进的前提。
  • 合规可过审：等保方向、分类分级、留存销毁、调阅审批满足政企客户与监管入网要求。
  • 平台可开放：统一网关让 API 可对外而不裸奔，809 联网具备监管准入条件。
  • 故障可恢复：备份、主从、容灾把"演示系统"与"生产系统"区分开。

8. F36 数据质量管理（设计规划）

本节为设计规划，尚未实现。

8.1 五维指标体系（蓝图 §5.3）

维度指标与目标值数据来源
完整性丢点率 <0.5%；报警抓拍图片缺失率（附件应到未到）F01 心跳/期望频率推算期望点数 vs 实际；F07 媒体到达回执
准确性异常点率 <0.1%；CAN 信号越界率F08 qc 计数（SPEED_IMPOSSIBLE/TELEPORT/DRIFT 等）；F05 信号范围校验
一致性VIN/车牌纳管率 100%（终端上报标识与平台档案一致）F02 双标识映射结果、gateway_unknown_terminal
及时性事件端到端 ≤3 秒；终端时钟偏差 ≤1 秒（统计/告警阈值 30 秒）gpsTime→入库时间戳差；Kafka 消费 Lag
唯一性重复报文率 <0.01%(车,gpsTime) 幂等冲突计数；source_id 去重计数

8.2 拟新增组件与流程

  • 质量聚合表：按终端×小时、企业×天汇总（traj_qc_stat / gateway_ingest_stat 扩展）。
  • 质量大盘：整体五维 → 企业下钻 → 终端下钻三级；红黄绿阈值配置化。
  • 隔离区与复核：复用 F08 qc_status=REJECT/SUSPECT 数据；复核操作"回流（触发 F12 回补）/丢弃"，操作留痕。
  • 问题工单：质量指标越阈自动建工单（复用 risk_order 或新建质量工单类型），指派运维/设备商处理。
  • 终端画像：按终端型号/批次聚合合格率，反哺采购与淘汰。

8.5 质量聚合表草案（traj_qc_stat）

CREATE TABLE traj.traj_qc_stat (
  stat_time       TIMESTAMP NOT NULL,   -- 小时/日刻度
  stat_grain      VARCHAR(8) NOT NULL,  -- HOUR / DAY
  terminal_no     VARCHAR(32),          -- NULL = 全局汇总行
  dept_id         BIGINT,               -- 企业下钻行
  expected_points BIGINT, actual_points BIGINT, missing_points BIGINT,
  invalid_points  BIGINT, duplicate_points BIGINT, backfill_points BIGINT,
  event_delay_p95_ms  BIGINT,
  clock_skew_p95_ms   BIGINT,
  media_missing   BIGINT,
  score_json      JSONB,                -- 五维得分与红黄绿
  UNIQUE (stat_time, stat_grain, terminal_no, dept_id)
);

8.6 五维指标计算口径

维度公式红黄绿阈值（规划）
完整性丢点率 = missing ÷ expected绿 <0.5%；黄 0.5～2%；红 >2%
准确性异常点率 = qc REJECT 点数 ÷ actual绿 <0.1%；黄 0.1～0.5%；红 >0.5%
一致性纳管率 = 已匹配档案终端 ÷ 上报终端绿 = 100%；黄 99～100%；红 <99%
及时性事件延迟 P95 = 入库 − gpsTime；时钟偏差 P95绿 ≤3s/≤1s；红 >10s/>30s
唯一性重复率 = 幂等冲突计数 ÷ 入库报文绿 <0.01%；红 >0.1%

8.7 隔离区处置设计

F08 清洗标记 qc_status=SUSPECT/REJECT 的点不删除：SUSPECT 留主表打标，REJECT 入隔离表 traj_gps_point_quarantine（结构与主表一致，另加 reject_reason、quarantine_time、review_by、review_result）。

处置动作效果后续
确认回流改标 qc_status=OK 回主表触发 F12 受影响分片回补
确认丢弃隔离表保留 N 天后物理清理计入准确性/唯一性指标
批量误判申诉按规则 + 终端批量复核反向修订 F08 规则阈值

8.8 终端合格率画像

  • 按终端型号/固件版本/批次聚合：五维得分均值、丢点率分布、故障率、在网时长加权。
  • 输出合格率排名与红黑榜，供采购选型与存量淘汰；画像结果支持月报导出。
  • 与 F24 联动：同型号终端视觉误报率进入终端质量画像，作为终端选型输入。

8.9 质量大盘拟新增接口（规划）

接口方法说明
/api/qc/overviewGET全局五维得分与红黄绿（按 deptScope 裁剪）
/api/qc/by-deptGET企业维度下钻（先裁剪后聚合，对齐 MOD-017 口径④）
/api/qc/by-terminalGET终端维度明细，支持型号/固件版本/批次筛选
/api/qc/quarantine/pageGET隔离区分页（原因/时间/终端），默认仅查近 30 天

全部接口遵守 fail-closed：deptScope 为空集合直接返回空页；质量问题工单复用现有 risk_order 派单链路（新增工单类型即可），不另建独立工单系统。

8.3 联动

与 F08 清洗（指标源头）、F59 轨迹完整率（同一套错误/漂移判定与合格率口径，MOD-017）双向联动：F59 是面向业务的单车完整率报告，F36 是面向治理的全域质量大盘，共用底层函数不复制规则。

8.4 风险与验收

主要风险
期望点数估算误差（补传、频率动态变化）→ 期望模型按终端实际上报频率滚动学习；隔离区膨胀 → 保留期与批量处理
  1. 注入已知缺陷数据集（丢点/越界/重复/时钟错），五维指标值与人工核算一致。
  2. 质量大盘企业/终端下钻合计与全局一致（无漏算重算）。
  3. 隔离点回流后 F12 对应分片里程/时长正确变化。
  4. 指标越阈自动生成工单并可闭环；处理全程留痕。
  5. 终端型号合格率排名可导出，支撑采购评审。

9. F37 数据安全与合规（设计规划）

本节为设计规划，尚未实现。现有脱敏仅存在于审计过滤器（AuditFilter 对请求体打码），数据库静态加密/动态脱敏/分级留存均未建设。

9.1 分类分级

级别数据（示例）策略方向
敏感个人信息驾驶员人脸（DSM 画面）、身份证号、连续行踪轨迹、健康/生理信息加密存储、最小可见、调阅审批（F25）、导出严控、明示授权
个人信息手机号、车牌、驾驶证/从业资格证号动态脱敏展示（前 3 后 4 等）、按角色明文授权
重要数据车辆规模运行数据、重点区域（政府/敏感设施周边）轨迹、危化品运输数据出境/外发评估、聚合分析、访问审计、监管口径管理
一般业务数据车辆档案、字典、工单（非敏感部分）常规 RBAC + 审计

9.2 加密与脱敏

  • 存储加密方向：国密 SM4 字段级加密（身份证、人脸样本地址等）；密钥经 KMS 托管，规划 HSM 保护根密钥；数据库透明加密（TDE）作为基础设施层补充。
  • 动态脱敏：在序列化/视图层按角色对手机号、身份证、驾驶证号脱敏；现状 AuditFilter 的打码规则（password/token/secret/phone/idcard 等）是审计专用，不替代业务展示脱敏，需新建统一脱敏组件。
  • 传输：全站 HTTPS（nginx 终结）；服务间令牌升级为可吊销、分权限的凭据（随 F38 网关一并改造）。

9.3 留存与销毁

  • 审计日志（traj.sys_audit_log）≥6 个月留存（蓝图合规基线 §10.2），配合分区/归档；现状只追加但无任何留存策略（见 MOD-013 第 20 节）。
  • 视频证据普通片段 30～90 天到期销毁并写销毁日志（F26）；轨迹数据按合规年限分区归档/销毁，销毁动作本身长期留痕。

9.4 授权审批与等保方向

9.5 验收标准

  1. 敏感字段在库中为密文，应用层按角色解密；KMS 不可用时明文不落地、有降级告警。
  2. 无权限角色通过界面与 API 均只能看到脱敏值；越权尝试有审计记录。
  3. 分级目录覆盖全部个人信息与重要数据表，变更有评审记录。
  4. 审计日志可查询 6 个月以上；到期销毁任务与销毁日志完整可查。
  5. 视频无审批单无法播放（联动 F25 验收）；高危指令无审批不下发。

10.5 签名与报文规范（规划）

请求头：
  X-Access-Key: 应用 AppKey
  X-Timestamp:  毫秒时间戳（与服务端偏差 >5 分钟拒绝，防重放）
  X-Nonce:      随机串（10 分钟内不可重复）
  X-Sign: HMAC-SHA256(AppSecret,
            METHOD + "\n" + PATH + "\n"
            + 排序后的 query 串 + "\n"
            + X-Timestamp + X-Nonce)
响应信封：{code, message, data, requestId}
错误码：40101 未认证 / 40301 越权 / 42901 触发限流 / 50000 服务异常
限流：默认 60 次/分钟/应用，批量/轨迹类接口单独配额

10.8 OAuth2 客户端模式与令牌生命周期（规划）

客户端模式（机器对机器）：
  POST /open/oauth/token?grant_type=client_credentials
  Header: Authorization: Basic base64(AppKey:AppSecret)
  → { access_token, expires_in: 7200, scope: "vehicle:read ..." }

调用：Authorization: Bearer <access_token>
      X-Sign 仍须携带（签名 + 令牌双重校验；令牌可过期、可吊销）
吊销：管理端停用应用或密钥轮转 → 令牌加入黑名单（短过期兜底）
计量：以 AppKey 为准（与令牌解耦），按天写 open_api_meter
  • AppSecret 仅在发放时明文展示一次，库存密文；轮转期支持新旧密钥并行（open_app_secret.rotated_from 链）。
  • 客户端模式不签发 refresh_token（凭密钥自取新令牌）；如未来出现人对人授权场景，授权码模式另行安全评审。

长连接500 终端长连 2 小时 + 30s 心跳无异常断连；指令往返 P95 <3s
流媒体弱网tc/NetEm：丢包 3%、抖动 200ms、限速 2Mbps首屏 <3s、卡顿率 <5%（与 F06 一致）
报表大查询50 并发浏览 + F59 后台任务并行P95 ≤2s，连接池不耗尽

12.6 测试数据与报文样本库

  • 协议样本库：注册/鉴权/心跳/0x0200/苏标 0x64、0x65/9101/1210/1211 等真实脱敏报文（GATEWAY-REF 已整理），纳入回归仓库版本化管理。
  • 缺陷数据集：与 F36/F59 共用，含丢点/越界/重复/时钟错/漂移标注，指标验收以此为标准集。
  • simulator/mock 仅在 dev/联调/预生产可用；生产环境启动自检发现该模式直接拒绝启动。

12.7 生产发布检查清单

  1. 镜像来自 CI 且通过 SCA；配置与密钥经环境注入，无明文入库。
  2. 数据库迁移脚本经双人评审；回滚脚本与备份在执行前就绪。
  3. fat jar 内嵌业务模块时间戳已核对（项目教训：陈旧内嵌 jar 导致改动不生效）。
  4. 重建容器后核对 nginx upstream 解析（必要时重启 portal-nginx）；轮询 POST /api/auth/login 返回 200 为就绪。
  5. 发布后观察 30 分钟核心指标（错误率、Lag、登录成功率、入库延迟），异常按预案回滚。

14.1 阶段准入门控

  • G0 → G1：备份恢复演练完成 ≥1 次；基础监控看板覆盖四容器；静态扫描进入 CI。
  • G1 → G2：F36 五维大盘可用；500 车压测报告通过；脱敏组件与审计日志 6 个月分区上线。
  • G2 → G3：API 网关承载全部对外调用（X-Service-Token 收敛下线）；809 试点地区联调通过；PG 主从切换演练成功。
  • G3 → G4：等保三级测评通过（如客户要求）；K8s 小集群稳定运行 ≥1 个月后再规划多活。

15. 风险与对策

风险对策
早期只做功能不做保障，上量后返工G0/G1 与网关一期绑定交付，监控/备份/压测作为真实终端准入门槛
加密改造影响存量查询性能字段级加密只对高敏字段；索引列用确定性加密/哈希辅助列；压测验证
809 属地平台版本差异大按属地要求版本对接，协议适配层化；先在试点地区联调再推广
监控系统自身成为单点Prometheus 本地短期保留 + 远端持久化；告警多通道；监控与业务资源隔离部署
K8s/多活运维能力不足按阶段引入（compose 加固→3 节点→K8s），每阶段配培训与演练，不跳步
合规改造范围蔓延以等保三级条款与三部法规建立差距清单，按客户准入要求排期，不做无依据的过度设计

16. 验收标准

  1. F36：五维指标在注入缺陷数据集上数值正确；三级下钻与隔离回流闭环可用。
  2. F37：敏感字段密文存储、角色化脱敏、调阅/导出/高危指令审批链贯通；审计日志留存 ≥6 个月可查。
  3. F38：开放 API 鉴权/限流/计量/审计/脱敏五件套生效；809 与测试上级平台联调通过、断链补传无丢失。
  4. F39：监控/日志/链路三支柱上线并通过告警触达、主从切换、备份恢复演练。
  5. F40：CI 质量门、协议双轨、500 车压测、弱网流媒体、迁移双人复核均有当期报告。
  6. 各阶段交付物（备份策略、分级目录、网关文档、容灾预案、测试报告）归档可查。
  7. 生产环境以 GATEWAY_MODE=gateway 启动自检通过；simulator/mock 配置在生产镜像中不可用。
  8. 高危操作（高危终端指令、证据保全解除、审计日志导出）全部有审批与审计成对记录。
