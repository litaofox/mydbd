MOD-DBD-004 轨迹数据接入、查询与回放

文档编号 MOD-DBD-004|版本 v1.0.0|发布日期 2026-10-05| 状态 已上线|功能编号 P04 / P05 / P06 / P08 / P09

事实基准：2026-10-05 源代码（backend-java module-trajectory；processing-service app；frontend src）与初始化 SQL（02-traj-tables.sql）、网关配置（infra/nginx/portal.conf）

主要代码锚点：TrajectoryController / TrajectoryService / GpsPointMapper（Java，module-trajectory）；processing-service/app/routes/ingest.py / routes/simulator.py / routes/dataset.py / services/simulator.py / services/dataset_gen.py / app/db.py / app/security.py（Python）；前端 views/playback/Playback.vue、views/system/ConfigList.vue、api/traj.ts

1 功能概述

1.1 模块定位与边界

本模块覆盖轨迹数据的一进一出：进——把定位点写进 traj.traj_gps_point（PostGIS 点列同步维护）；出——把点查出来支撑实时监控与历史回放。当前有三条接入链路，全部落在 Python 处理服务（processing-service，FastAPI）：

  • 终端 HTTP 实时推送（P05）：面向终端/第三方系统的批量推点接口 POST /api/ingest/traj，以 X-Service-Token 服务令牌鉴权；是真实 JT/T 808 网关就位前的标准接入契约。
  • 样例 CSV 批量导入（P04）：把 samples 目录下的 GPS 轨迹 CSV 幂等导入（重导前按设备+时间窗清旧点），并联动导入当日司机风险事件。
  • 进程内轨迹模拟器（P06）：processing-service 内置 asyncio 模拟器，每 2 秒为 12 辆演示车批量产点，并周期性产出"终端报警 + 风险事件"演示数据；代码注释明确"正式版本将替换为 JT/T 808 终端协议网关"。
  • 标准测试数据集：一键后台生成"4 公司 / 10 车队 / 500 车 / 500 终端 / 500 司机 + 2026-09 全月轨迹"的演示库，standard/dense 两档密度，可清空重灌。

出侧由 Java module-trajectory 提供四个查询接口（P09）：在途车辆、车辆台账、各终端最新位置、历史轨迹（P08 回放页的数据源）。全部查询按登录人数据范围过滤（fail-closed）。

一句话边界：本模块只负责"点怎么进库、怎么查出来"。点入库后的实时判定（超速/围栏 CEP 旁路评估）、实时推送（WebSocket）、报警闭环分别在 MOD-DBD-008、MOD-DBD-005、MOD-DBD-006；轨迹的统计报表（F41 等）属第二波建设内容。

1.3 术语与概念

术语含义
identity_code终端编号，轨迹点的第一关联键；CSV 中的 vehicle_id 列、推送报文的 identityCode 字段都映射到它。
gps_time / receive_time定位时间（终端上报）与平台接收时间（默认入库时刻）；回放与在线判定用 gps_time 口径。
location 列geometry(Point,4326)，入库时由 lng/lat 经 ST_SetSRID(ST_MakePoint) 同步生成，供围栏等空间判定使用；Java 实体不映射该列。
X-Service-Token系统间调用的共享密钥头，processing-service 内部接口（/traj 推送）鉴权方式；与用户 JWT 是两套体系。
幂等重导CSV 重导前按 identity_code + gps_time 窗口 DELETE 旧点再插入，同一文件重复导入不产生重复点。
演示事件模拟器按 12~20 秒随机间隔产出的成对数据：1 条 mon.risk_event（风险事件，自动建工单）+ 1 条 traj.traj_warn_info（终端报警）。
roster模拟器车辆清单：启动时从库里选 10 辆市内车（每个车队第 1 辆）+ 2 辆跨省专线车（DS0353/DS0452）；无数据集时回退北京 5 车。
LATERAL 查询"每终端最新点"的实现方式：终端表驱动 CROSS JOIN LATERAL 逐台索引探测取最新 1 行，避免扫 890 万行轨迹表。
currentPlatesJava 侧范围过滤口径：null=不限（超管），空列表=任何数据不可见（fail-closed），非空=可见车牌集合（由部门范围换得）。

2 典型场景

调度监控员
核查车辆一天行踪
打开历史轨迹回放，选车、选起止时间，地图画出蓝色轨迹线；点播放按 2 倍速看车标沿线移动，拖动滑块跳到任意时点，右上角实时显示该点的定位时间与速度。
坐席/监控页联动
从报警跳到当天回放
报警中心/监控页带参数（plateNo + date）跳入回放页，页面自动选中车辆、把时间窗填为当天 00:00~23:59 并直接查询，省去手工选车选时间。
演示/测试人员
一键灌演示库
系统参数页点"加载标准测试数据集"，后台线程生成 500 辆车 9 月全月轨迹，页面进度条实时更新；想重灌先"清空"再加载，dense 档可压测大数据量查询。
演示/测试人员
模拟实时车流
打开模拟器开关，12 辆车开始 2 秒一批上报点位，监控页车标动起来；同时每隔十几秒自动产生一条终端报警和风险事件，报警中心、工单、大屏数字全部"活"起来。
第三方系统对接方
按契约推送轨迹
外部网关/终端按 identityCode + points[] 报文向 /api/ingest/traj 批量推点，请求头带 X-Service-Token；平台返回插入条数，CEP 评估失败不影响入库。
数据治理
样例轨迹重复导入
同一份 9 月 1 日 CSV 导入两次，库中不增重：接口先删该设备当天旧点再插入；当日的司机风险事件也不会重复出现。

3 操作流程

相关菜单：实时监控 → 历史轨迹回放（sys_menu id=12，路由 /playback，权限点 playback:view；调度监控员可见，企业车队长种子授权不含回放）。数据装载与模拟器控制在 系统参数 页（id=921，/system/config，权限点 system:config:view）顶部的"测试数据与模拟器"面板。

3.1 历史轨迹回放

选择车辆
下拉列出在途车辆（"车牌（终端编号）"），来源 /api/traj/vehicles，按数据范围过滤。
设时间窗
起止时间均可空：不填时间 = 查询该车全部轨迹（页面既有语义）。
查询与绘制
"查询轨迹"后地图绘制蓝色轨迹线（#2563eb，宽 4），视野自适应；提示"共 N 个轨迹点"。
播放控制
播放/暂停；1x/2x/4x/8x 倍速（基准 600ms 一点）；滑块拖动定位；右侧显示当前点定位时间与速度；车头方向随 direction 旋转。

3.2 加载标准测试数据集

进入面板
系统参数页顶部"测试数据与模拟器"→ 标准测试数据集区（4 公司 / 10 车队 / 500 车，鲁苏沪皖 9 月全月）。
选择档位
"加载标准数据集"（30 秒一点，约 700~900 万点）或"加载稠密数据集"（15 秒一点，约 1500~1800 万点）；已有任务运行时接口返回 409。
跟踪进度
页面轮询 /api/ingest/dataset/status 展示阶段与百分比；可切走别的菜单，回来自动接续。
清空重灌
"清空"删除全部业务数据（保留 IAM/菜单/字典/配置/审计）；任务运行中禁止清空（409）。

3.3 启停实时轨迹模拟器

  • 开关在同一面板"实时轨迹模拟器"区：启动后显示运行状态、车辆数、ticks、演示事件计数；周期同步后端真实状态，多标签页一致。
  • 未加载标准数据集时给出提示"模拟器使用内置 5 辆演示车，建议先在左侧加载测试集"（回退清单）。
  • 停止有确认框："停止后将不再产生实时轨迹、终端报警与风险事件（已产生的数据保留）"。

3.4 样例 CSV 导入

  • 接口 POST /api/ingest/load-sample，body {"file": "vehicle_gps_20260901.csv"}；文件须位于容器内 {storage_root}/samples（默认 /data/samples），文件名取 basename 防目录穿越。
  • CSV 列：vehicle_id, plate_no, gps_time, longitude, latitude, speed, direction, altitude, alarm_flag, driver_phone, driver_idcard, mileage（driver_* 两列不入库）。
  • 返回导入文件名、设备号、时间范围、插入点数与联动事件数；当前界面无独立入口，以接口直调/脚本方式使用（api/traj.ts 已封装 loadSample）。

3.5 终端 HTTP 实时推送（系统间）

  • POST /api/ingest/traj，请求头 X-Service-Token: <服务令牌>（配置项 service_token，环境变量注入）。
  • 报文：{"identityCode":"...", "plateNo":"...", "points":[{"gpsTime":"yyyy-MM-dd HH:mm:ss","lng":..,"lat":..,"speed":..,"direction":..,"altitude":..,"alarmFlag":0,"mileage":..}]}；identityCode 与 points 必填，缺失返回 400。
  • 响应 {"inserted": N}；单批超过 5000 点自动分片。

7 核心实现逻辑

7.1 三条接入链路的共同落库管道

无论来源是外部推送、CSV 还是模拟器，最终都汇入 db.insert_gps_points(rows)：行 dict 统一为 identity_code / plate_no / gps_time / lng / lat / speed / direction / altitude / alarm_flag / mileage 十一个键，execute_values 单 SQL 批量插入，模板尾部 ST_SetSRID(ST_MakePoint(%s, %s), 4326) 用 lng/lat 同步生成 PostGIS location 列——围栏等空间判定（MOD-DBD-007）依赖该列，任何新接入链路只要复用此函数即自动具备空间能力。连接管理 get_conn() 上下文：正常 commit、异常 rollback、始终关闭。推送与模拟器链路在入库后都会旁路调用 cep_engine.evaluate_points(rows)，并用 try 包裹保证"评估挂了不影响入库"。

7.2 终端 HTTP 推送与服务令牌

鉴权
FastAPI Depends(verify_service_token)：X-Service-Token 头不等于配置 service_token（默认 change-me-service-token，环境变量覆盖）即 401。该链路不走用户 JWT。
报文校验
identityCode 与 points 必填（400"identityCode 与 points 不能为空"）；plateNo 可选但应给，回放按车牌过滤依赖它。
分片入库
点列表按 5000 行切片循环 insert_gps_points，累计 inserted 返回。
CEP 旁路
整批（未分片的原始 rows）交 cep_engine.evaluate_points 做规则/围栏评估；异常仅打印 [cep] 日志。

7.3 样例 CSV 幂等导入与事件联动

定位文件
默认 vehicle_gps_20260901.csv；os.path.basename 防目录穿越；不存在返回 404。
解析
csv.DictReader 逐行读取，vehicle_id → identity_code，经纬度/速度等转型；空文件 400。
幂等清理
取全文件最小/最大 gps_time，先 DELETE 该设备该时间窗旧点，再分片插入——重复导入不重复。
事件联动
导入日的 driver_events.json 中当日事件同步写入 mon.risk_event（dsm_level → risk_level）；count_risk_events_on(日期)==0 才导，同一天只导一次。

7.4 进程内模拟器：车辆清单与运动模型

roster 选取（启动时一次）：市内车——按车队（dept_type=2）每队取第 1 辆已绑终端的车（DISTINCT ON d.id 配 ORDER BY d.id, v.id）；跨省车——按终端编号 DS0353/DS0452 精确选取；查询失败或结果为空回退到北京 5 车（SIM_001~005 京牌）。

每 2 秒 tick：

模式运动模型参数
local 市内车平滑随机游走：航向 ±0.35 弧度抖动、速度 8~78 km/h 波动、按速度折算经纬度步长；出城区边界（lng ±0.12 / lat ±0.09）航向反转反弹中心 = 车队所属城市中心（9 城坐标表）
cross 跨省车沿"上海→苏州→芜湖→合肥"走廊 haversine 插值往返，到头掉头；车头方向取前方 0.2km 方位角速度 60~108 km/h；里程 3~15 万公里初始
fallback北京城区（116.404, 39.912 附近）随机游走速度 20~80 km/h

每 tick 全部车辆成一批 rows：mileage 按速度×2 秒累计，alarm_flag 在速度 ≥95 时置 1；随后 insert_gps_points → CEP 旁路 → _maybe_demo_event。演示事件按 12~20 秒随机间隔产出，5 类按权重抽取（一般超速 0.30 / 严重超速 0.50 / 疲劳 0.72 / DSM 疲劳 0.88 / 设备故障 1.00 累计权重），超速类只落在跨省高速车上；选车时刻意避开上一次的车辆；严重超速要求当前速度 ≥95，否则自动降级为一般超速。每次产出 1 条 risk_event（自动建工单，见 MOD-DBD-009）+ 1 条 traj_warn_info（报警，见 MOD-DBD-006）。

7.5 轨迹查询的数据范围过滤

TrajectoryService.currentPlates() 是全部查询的统一闸口：超管/数据范围=全部 → 返回 null（SQL 不加车牌条件）；范围为空 → 返回空列表，各方法直接返回空结果（fail-closed，SQL 都不执行）；否则按 deptScope 查有效车辆换得去重车牌集合，轨迹查询以 plate_no IN (...) 过滤。即使用户只传 identityCode 不传车牌，点位的车牌也必须在可见集合内——终端编号无法成为越权通道。WebSocket 推送链路是例外：listLatestPointsForPush() 全量查（调度线程无 UserContext），由发送环节按各会话范围逐会话过滤（见 MOD-DBD-005）。

7.6 最新位置查询的 LATERAL 优化

"每个终端最新一点"若用 DISTINCT ON 或窗口函数，需要扫/排 890 万行轨迹表（注释实测 DISTINCT ON 约 53s、全量 DISTINCT 约 19s）。现实现以终端表驱动：traj_terminal（500 行级）CROSS JOIN LATERAL，逐终端用 (identity_code, gps_time DESC) 索引做 ORDER BY ... LIMIT 1 探测，500 次索引查找换来整体亚秒级（注释实测约 0.5s）。可见车牌集合作为可选条件拼在 LATERAL 外层。该 SQL 同时服务 /api/traj/latest（HTTP 数据源）与 WebSocket 推送。

7.7 前端回放页实现

  • 地图：Leaflet + 高德瓦片（webrd0{s}.is.autonavi.com，style=8），初始视野北京；查询成功 fitBounds 自适应轨迹。
  • 绘制：整条轨迹一根 L.polyline（#2563eb/4px/0.8）；移动车标是 divIcon 内嵌 SVG（vehicleIconSvg），方向角经 rotate 变换，方向变化超过 15° 才重建图标避免高频 DOM 重建。
  • 播放：setInterval 600/speed 毫秒步进索引；到末尾自动停；切倍速时重启定时器；滑块与索引双向联动。
  • 路由联动：identityCode 精确匹配优先、车牌兜底；date=YYYY-MM-DD 自动填当天 00:00:00~23:59:59；带参即自动查询；watch route.query 支持同标签换车（多标签模式下 path 不变仅 query 变）。
  • 时间展示：dayjs 兼容 ISO 串，统一显示 yyyy-MM-dd HH:mm:ss。

12 技术选型依据

  1. 写库放 Python、查询放 Java：接入侧是 IO 密集批量写（execute_values 单 SQL 多行 + 分片），Python 脚本化迭代快；查询侧要与平台统一的认证/数据范围体系集成，Java 复用 UserContext 零成本。共享同库是两侧唯一耦合。
  2. 服务令牌而非用户 JWT 做系统间鉴权：终端/网关没有"登录人"，共享密钥头是最简方案；与用户体系隔离，泄露面可独立轮换。
  3. 幂等导入用"按窗删除再插"而非唯一约束：轨迹点天然允许同时刻多点（不同来源），加唯一约束会误伤真实数据；按设备+时间窗先清后插达到同等幂等效果且不扭曲模型。
  4. 模拟器进程内 asyncio 而非独立服务：演示用途下与 processing-service 同生命周期最省心；roster 从库中动态选取，灌了数据集自动升级车队规模，没灌也有北京 5 车兜底。
  5. LATERAL 逐终端探测而非 DISTINCT ON 全扫：把"N 个终端各取最新 1 点"从全表排序转化为 N 次索引点查，注释留存了 53s→0.5s 的实测依据。
  6. 轨迹查询全量返回而非分页：回放需要完整点序绘制折线，分页会破坏连续性；大窗口查询的数据量风险在 13 节登记。
  7. 数据集后台线程 + 状态轮询：百万级生成是分钟级任务，同步 HTTP 会超时（nginx 对 ingest 给 300s 仍不够）；异步任务 + status 接口让前端可断续跟踪。

15 边界行为与常见问题

同一个 CSV 导两遍会重复吗？
不会。导入前先按"设备 + 文件最小/最大 gps_time"删除旧点再插入；当日的司机事件也因 count_risk_events_on=0 检查只导一次。
推送接口报 401 是什么原因？
X-Service-Token 头缺失或与 processing-service 的 service_token 配置不一致；注意该令牌与用户登录 JWT 是两套体系。
单批最多能推多少点？
报文不限长，服务端按 5000 行分片入库；nginx client_max_body_size 220m 与 300s 超时是实际上限。
为什么受限用户在回放页选不到某辆车？
/api/traj/vehicles 已按数据范围过滤；即使手工构造 identityCode 调 /track，点位车牌不在可见集合内也会被过滤为空。
超管查得到但回放没数据的车是什么情况？
该车（终端）还没有任何轨迹点，或轨迹点的 plate_no 为空/与档案车牌不一致——回放页车辆清单来自"有轨迹的终端"，台账车无点不会出现。
模拟器停了，监控页的车还动吗？
不动。已产生的数据保留（轨迹/报警/事件不删），但不再新增点位；监控页最新点停留在最后上报时刻，按 refTime 口径会逐渐显示离线。
数据集加载中可以清空吗？
不可以，接口返回 409"数据集任务运行中，禁止清空"；同理运行中重复加载也 409。
清空数据集会删掉我的账号吗？
不会。clear_business_data 只清业务数据，IAM 用户/角色/菜单、字典、系统配置、审计日志保留。
不选时间查询会怎样？
按页面语义查询该车全部轨迹（无时间条件）；注意大历史量车可能返回非常多点（见 13 节风险）。
倍速切换为什么要先停再播？
实现上切换倍速时重启定时器（playing false→true）使新间隔立即生效，表现为一瞬间的重启，属正常行为。
