MOD-DBD-001 平台基础与通用能力

文档编号 MOD-DBD-001|版本 v1.1.0|发布日期 2026-10-06| 状态 已上线|功能编号 P01 / P02 / P03

事实基准：2026-10-05 源代码（backend-java platform-boot、platform-common、module-iam；frontend src）

主要代码锚点：PlatformApplication / HealthController（platform-boot）；JwtUtil / JwtAuthFilter / Result / ErrorCode / GlobalExceptionHandler / WebConfig / MybatisPlusConfig / MybatisMetaObjectHandler（platform-common）；AuthController / AuthService（module-iam）；前端 views/Login.vue、layout/MainLayout.vue、store/tabs.ts、store/auth.ts、router/index.ts、api/http.ts

1 功能概述

1.1 模块定位与边界

本模块是平台的地基，包含四组贯穿全系统的基础能力，本身不对应某个业务菜单，但每一个业务页面都建立在它之上：

  • 登录与 JWT（P01）：账号密码登录、失败计数与锁定、JWT 访问令牌签发与校验、登录态在前后端的维持；MFA 二次验证仅在此描述令牌链路，TOTP 绑定与策略详见 MOD-DBD-002。
  • 统一响应与全局异常（P02）：所有 Java REST 接口返回 {code, message, data} 统一结构；业务异常、参数校验异常、唯一约束冲突、未知异常被全局异常处理器翻译为标准错误码，前端请求库统一解包。
  • 容器基座（P03）：Spring Boot 启动类、模块装配（scanBasePackages + MapperScan）、定时任务开关、CORS、JWT 过滤器注册、MyBatis-Plus 分页插件、公共审计字段自动填充、健康检查端点。
  • 前端布局与标签页框架（P03）：登录后的主框架——左侧可折叠导航菜单（按登录人权限渲染）、顶部多标签页（固定标签 / 右键菜单 / 溢出滚动箭头）、通知铃铛、用户下拉（个人中心 / 退出登录）、keep-alive 视图缓存。

一句话边界：业务规则（谁能看哪些菜单、数据范围多大）在 MOD-DBD-002（IAM）；本模块只负责"令牌怎么签发与校验、响应怎么包装、应用怎么装配、页面框架怎么组织"。

1.3 术语与概念

术语含义
access 令牌登录成功签发的业务访问令牌，HS256 签名（2026-10-06 起由 JwtUtil 显式钉死），claims 含 sub=username、uid、purpose=access，有效期 8 小时。此前 signWith 未指定算法时 JJWT 按密钥长度自选，50 字节密钥实际签发 HS384；解析侧与 processing 侧均兼容 HS384/HS512 存量令牌，过渡期无需重新登录。
mfa 令牌开通 TOTP 的账号密码校验通过后签发的中间令牌（purpose=mfa，5 分钟），只能调 /api/auth/mfa/verify，不能访问任何业务接口（过滤器按 purpose 拒绝）。
UserContext请求线程内的登录主体 ThreadLocal，由 JwtAuthFilter 写入、finally 清理；Service 层据此取当前用户。
Result / ErrorCode统一响应体与错误码枚举（40001/40101/42301/40301/40401/40901/50000），成功恒为 code=0。
固定标签 affix多标签页中不可关闭的标签，当前仅 /monitor（实时导航监控），始终置于首位。
viewKey / refreshSeq"刷新当前标签"的实现机制：path + 自增序号作为 router-view 的 key，序号变化触发组件重建。
valid_mark全平台软删标记约定（1 有效 / 0 已删），用户、角色、围栏等均沿用。
雪花 ID 按 string 处理前端约定：后端 bigint 主键（雪花 ID）超出 JS 安全整数，接口层一律以 string 承载（见 iam.ts、mdm.ts 的 id: string 声明）。

3 操作流程

本模块无独立业务菜单，入口是登录页（/login）与登录后的主框架（任何菜单页都在其中）。

3.1 登录与进入工作台

打开登录页
访问 /login（未登录访问任何页面会被路由守卫重定向到此，并带 redirect 参数）。
输入账号密码
演示环境登录页提供测试账号快捷填充（admin/admin123、四省调度员与车队长 test123456，与 16/17 号种子一致）。
（可选）动态口令
账号已开通 TOTP 时进入第二步，输入身份验证器 6 位验证码；可"返回上一步"。
进入工作台
登录成功跳 redirect 参数指向页，否则跳该账号菜单树中第一个可访问菜单（firstMenuPath，兜底 /monitor）。

3.2 多标签页工作方式

打开功能页即开标签
从左侧菜单进入任一功能页，顶部 44px 顶栏内出现一个标签；同一路径重复进入只更新原标签（一功能一标签，按 route.path 去重）。
切换与关闭
点击标签切换；点标签上的 × 关闭；关闭当前激活标签自动跳到相邻标签，没有相邻标签时回 /monitor。
右键菜单
标签上右键弹出：刷新当前（组件重建）、关闭其他（保留本标签与固定标签）、关闭全部（仅留固定标签 /monitor）。
溢出滚动
标签过多时顶栏左右出现 ‹ › 箭头平滑滚动；切换标签后激活标签自动滚入可视区。
刷新恢复
标签清单存 sessionStorage（键 mydbd-tabs），F5 刷新后恢复；退出登录时清空，避免下个账号看到上个账号的标签。

3.3 侧栏折叠与顶栏工具

  • 折叠导航：侧栏底部"收起菜单"按钮切换 210px / 64px；状态存 localStorage（mydbd-aside-collapsed），下次进入保持。
  • 监控大屏入口：顶栏 DataBoard 图标直达 /dashboard（脱离主布局的全屏大屏，详见 MOD-DBD-005）。
  • 通知铃铛：未读角标（99 封顶）、最近消息弹层、"全部已读"、点工单类消息跳 处置工单 页（详见 MOD-DBD-011）。
  • 用户下拉：显示姓名/登录名，开通 MFA 的账号带"动态口令"标记；菜单含 个人中心（ProfileDialog，改资料/密码/绑定口令）与 退出登录。

3.4 退出登录

发起退出
右上角用户名 → 退出登录 → 确认框"确认退出登录？"。
服务端留痕
前端调 POST /api/auth/logout，服务端只写审计日志（AUTH/LOGOUT）；JWT 无状态，不做令牌拉黑。
本地清理
清空会话标签（tabs.reset）、清空 auth store 与 localStorage token，window.location.assign('/login') 硬跳转彻底重置内存态。

3.5 会话失效后的表现

  • access 令牌有效期 8 小时，到期或无效后任意接口返回 40101；前端 http.ts 拦截 401：提示"登录已失效，请重新登录"、清 token、跳 /login。
  • 令牌被篡改、purpose 不是 access、账号被停用/删除，同样按 401 处理（过滤器分别返回"令牌类型无效""账号不存在或已停用"等文案）。
  • 登录页表单校验失败（密码错误）直接展示后端 message，含剩余尝试次数；锁定时提示解锁时间。

7 核心实现逻辑

7.1 登录认证与 JWT 双用途令牌

AuthService.login 的完整判定顺序（每一步失败都抛 BizException，前端按 message 原样提示）：

① 查用户
按 username + valid_mark=1 查 traj.sys_user；不存在返回"用户名或密码错误"（不区分账号不存在与密码错，防枚举）。
② 状态与锁定
status!=1 → "账号已停用"；locked_until 在未来 → 42301"账号已锁定，请于 {时刻} 后重试"。
③ 校验密码
PasswordCodec.matches（PBKDF2-HMAC-SHA256，每用户 16 字节盐，120000 迭代，存储格式 pbkdf2$120000$base64(salt)$base64(hash)，比对用 MessageDigest.isEqual 防时序攻击）。失败则 fail_count+1；达 5 次置 locked_until=now+15min 并提示"剩余尝试次数"。
④ 成功处理
清零 fail_count/locked_until，回写 last_login_time 与 last_login_ip（取自 X-Forwarded-For 首段 / X-Real-IP / remoteAddr），evict 权限缓存。
⑤ 分支签发
mfa_enabled=1 且有密钥 → 返回 LoginVO.mfaStep（5 分钟 mfa 令牌）；否则返回 LoginVO.access（8 小时 access 令牌 + 姓名）。

为什么 login 不能加 @Transactional：代码注释明确——密码错误会抛异常，若存在事务，失败计数/锁定时间的 UPDATE 将被一并回滚，"连续失败 N 次锁定"策略失效。此处仅有单表单行写入，无需事务。

令牌结构（JwtUtil.build）：HS256（jjwt Keys.hmacShaKeyFor 建钥、signWith(key, Jwts.SIG.HS256) 显式指定算法；2026-10-06 前仅传 key 时 JJWT 按密钥长度自选算法），claims 为 sub=username、uid=userId、purpose=access|mfa、iat、exp。密钥配置链 ${mydbd.jwt.secret} → ${JWT_HMAC_SECRET} → 开发兜底值。

跨服务算法契约（2026-10-06 修复，详见 修复方案存档）：processing-service 的 app/security.py 用 PyJWT 验签浏览器 JWT，白名单为 HS256/HS384/HS512；Java 签发侧固定 HS256、解析侧接受同族 HMAC。令牌算法必须两侧同时认可，否则 processing 接口 401，前端拦截器收到 401 会清 token 并硬跳 /login。

7.3 统一响应 Result 与错误码

所有 Controller 返回 Result.ok(data) 或经异常处理器返回 Result.fail(code, message)，结构固定 {code, message, data}，成功恒为 code=0, message="success"。错误码枚举：

错误码常量默认文案典型场景
40001BAD_REQUEST请求参数错误参数校验失败（带字段名）、取值非法
40101UNAUTHORIZED未认证或登录已失效无令牌/令牌过期/密码错误/未登录
42301LOCKED账号已锁定连续失败锁定窗口内登录
40301FORBIDDEN无访问权限@RequiresPerm 校验失败
40401NOT_FOUND资源不存在按 id 查无有效记录
40901CONFLICT资源状态冲突唯一约束冲突、保护规则（如内置角色禁删）
50000INTERNAL_ERROR服务器内部错误未捕获异常兜底（HTTP 500）

7.4 全局异常翻译

GlobalExceptionHandler（@RestControllerAdvice）四类处理器：

  • BizException：透传 code 与 message（warn 级日志）；业务代码只负责 throw new BizException(ErrorCode.CONFLICT, "登录名已存在")。
  • MethodArgumentNotValidException / BindException：取第一个字段错误，拼成"字段名 + 校验提示"，返回 40001。
  • DuplicateKeyException：数据库唯一约束冲突统一翻译为 40901"数据已存在或绑定冲突，请检查唯一性规则"，避免把 SQL 细节透给前端。
  • Exception 兜底：HTTP 500 + 50000，error 级日志带完整堆栈。

7.5 容器基座（platform-boot / platform-common）

  • 装配：单一启动类扫 com.mydbd 全部包，MapperScan 匹配所有模块的 mapper 包；@EnableScheduling 使各模块 @Scheduled 生效（如工单超时扫描）。
  • CORS：/api/** 放开所有来源（allowedOriginPatterns *）、允许凭证，适配前端 Vite 开发服务器跨域；生产由网关收敛（见部署手册）。
  • 分页：MybatisPlusInterceptor 挂 PaginationInnerInterceptor（POSTGRE_SQL 方言），Service 统一 new Page<>(page, size) 并各自钳制 size 上限。
  • 审计字段：实体继承 BaseEntity（creator/create_date/updater/update_date），insert/update 由 MetaObjectHandler 自动填充当前登录名，无登录上下文（如 DataInitializer）落 "system"。
  • 健康检查：GET /health 返回 {"status":"UP"}，因路径不在 /api/* 下，过滤器不拦截，探针免令牌。

7.6 前端布局与多标签页框架

  • 菜单渲染：MainLayout 遍历 auth.menus（来自 /api/auth/profile 的菜单树）：menuType=1 渲染为可展开目录（支持目录内再嵌一层二级分组目录，仅当其下有可见菜单时显示）；menuType=2 且 visible!=0 且有 path 渲染为菜单项；visible=0 的隐藏项不渲染。
  • 标签模型：TabItem{path, title, fullPath, affix}，以 route.path 为唯一键；visit() 已存在则只更新 fullPath/标题；/dashboard 与 /login 不登记标签。
  • 固定标签：ensureAffix('/monitor','实时导航监控') 保证存在且置首；关闭动作对 affix 一律无效；关闭全部后仅剩它。
  • 刷新机制：viewKey = route.path + '#' + refreshSeq；"刷新当前"自增 refreshSeq 触发 router-view 重建，不重载整页。
  • 视图缓存：keep-alive include=['Monitor'] :max="6"，监控页切走保留地图与连接状态。
  • 持久化：标签存 sessionStorage（mydbd-tabs，按浏览器会话隔离）；侧栏折叠态存 localStorage（mydbd-aside-collapsed）；token 存 localStorage（mydbd-token）。
  • 退出时序：先 ElMessageBox.close() 显式收起确认框遮罩（注释说明曾与跳转存在时序竞争残留遮罩），再 tabs.reset()、auth.logout()、window.location.assign('/login')。

7.7 前端请求封装与路由守卫

api/http.ts（axios 实例，timeout 120 秒）：

  • 请求拦截：localStorage 有 token 即附 Authorization: Bearer。
  • 响应拦截：body 含 code 字段时，code===0 直接返回 data（业务代码拿到的已是解包结果）；否则 ElMessage.error(message) 并 reject。调用方设 skipErrorMessage 可跳过全局弹窗（预留能力接口降级用，如终端指令/逆地理）。
  • HTTP 401：提示"登录已失效"、清 token、跳 /login。

router/index.ts 守卫链：meta.public（仅 /login）直接放行；无 token → 跳登录带 redirect；首入 await auth.loadProfile()（失败则 reset 跳登录）；meta.perm 存在且 auth.has() 为假 → 回落 firstMenuPath（菜单树第一个可访问叶子，兜底 /monitor）。

8 数据流程

一次"登录 → 打开业务页 → 调接口"的端到端链路：

登录
POST /api/auth/login（白名单免认证）→ 校验密码/锁定 → 签发 access（或 mfa 步进）。
装载档案
前端存 token → GET /api/auth/profile 取用户/角色/权限/菜单树，渲染侧栏。
业务请求
axios 附 Bearer → JwtAuthFilter 解析 → UserContext 装载 → Controller @RequiresPerm 校验 → Service 业务。
统一返回
Result.ok(data)；异常经 GlobalExceptionHandler 翻译为 fail(code,message)。
前端解包
code=0 返回 data；非 0 弹 message；401 清会话回登录页。

与业务模块的分工：数据范围过滤（deptScope）在主体装载时已算好存进 UserInfo，由 MOD-002 与各业务模块消费；权限点在 PermAspect 判定，本模块只提供 UserContext 载体。

12 技术选型依据

  1. 无状态 JWT 而非服务端 Session：单页 + 多实例友好，免会话同步；代价是无法即时吊销，用 8 小时较短有效期 + 停用账号在主体装载时拦截（DbAuthRealm 返回 null 即 401）折中。
  2. 双用途令牌（purpose 声明）而非另起通道：MFA 中间态复用同一 JWT 设施，过滤器一行 purpose 判断即可隔离，避免引入临时会话存储。
  3. PBKDF2-HMAC-SHA256 自实现而非引 BCrypt 依赖：JDK 原生 SecretKeyFactory 即可，12 万迭代 + 每用户盐 + isEqual 常数比较，满足口令存储基线且不增依赖。
  4. 自研 JwtAuthFilter + UserContext 而非引入安全框架：平台权限模型（@RequiresPerm + deptScope）较轻，OncePerRequestFilter + ThreadLocal 足够，避免框架学习成本与过度配置。
  5. @RestControllerAdvice 集中翻译异常：Controller/Service 不 try-catch，错误文案只在抛出处维护，前端拿到的永远是可直读的业务文案。
  6. 多标签页自研（tabs store）而非路由级缓存方案：一功能一标签 + 固定标签 + 右键菜单是监控类系统的操作习惯；sessionStorage 按会话隔离，天然支持多账号分窗口使用。
  7. MyBatis-Plus 分页插件：PostgreSQL 方言 LIMIT/OFFSET 自动生成，业务代码不手写分页 SQL。

15 边界行为与常见问题

密码输错几次会锁？锁多久？
连续 5 次（IamConstants.MAX_FAIL_COUNT）锁定 15 分钟（LOCK_MINUTES），提示剩余尝试次数与解锁时刻；登录成功自动清零。
退出登录后旧令牌还能用吗？
能，直到 8 小时过期。JWT 无状态，logout 只写审计日志；这是选型时的已知取舍（见 13 节）。
为什么 mfa 令牌调业务接口会 401？
JwtAuthFilter 强制 purpose=access；mfa 令牌（purpose=mfa，5 分钟）只允许换发正式令牌，防止未完成二次验证的会话访问业务。
停用账号后已签发的令牌还有效吗？
无效。每次请求主体装载时 DbAuthRealm 检查 valid_mark/status，停用即返回 null，过滤器按 401"账号不存在或已停用"处理。
刷新浏览器标签会丢吗？
不会。标签清单在 sessionStorage（mydbd-tabs），F5 恢复；但关掉浏览器标签页/窗口后按会话隔离策略不再保留。
为什么退出登录要"硬跳转"？
window.location.assign('/login') 彻底重置前端内存态（store、keep-alive、弹层），注释说明曾与确认框遮罩关闭动画存在时序竞争，硬跳转是最稳妥的清理方式。
接口返回 40901 是什么意思？
资源状态冲突：重名、重复绑定（唯一约束）或保护规则触发（如内置角色禁删、超管不可停用）。文案由后端给出具体原因，或统一约束翻译"数据已存在或绑定冲突"。
/health 为什么不需要令牌？
JwtAuthFilter 只注册在 /api/* 上，/health 不在拦截范围，探针可直接访问。
审计字段谁写入的？
MybatisMetaObjectHandler 在 insert/update 时自动填充 creator/updater 为当前登录名；定时任务、初始化等无登录上下文场景落 "system"。
前端接口拿到的为什么不是 Result 包装？
http.ts 响应拦截器已统一解包：code===0 时直接把 data 返回给业务代码，非 0 统一弹错；业务代码不需要再判 code。
