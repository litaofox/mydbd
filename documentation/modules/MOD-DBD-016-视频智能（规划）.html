MOD-DBD-016 视频智能（规划）

编号：MOD-DBD-016｜版本：v1.0.0｜日期：2026-10-05｜ 状态：规划中｜覆盖功能项：F24～F27（另有 P12 页面占位）｜ 代码锚点：processing-service/app（routes/analysis.py、services/risk_engine.py、cep_engine）、03-mon-tables.sql、VideoAnalysis.java
产品篇

1. 模块定位与功能范围

视频智能模块覆盖主动安全事件的产生、取证、调阅治理与模型迭代全链路。总体策略是"边缘触发 + 按需调阅"：识别在车载终端 NPU 上完成，平台不做全量视频分析、不存全量视频；平台负责事件汇聚、证据管理、调阅审批、留痕审计与模型生命周期。

功能项名称范围
F24终端边缘智能DSM（疲劳/分心/抽烟/接打电话）、ADAS（FCW/LDW）终端侧识别；信号 + 1～3 张水印抓拍图上报；平台仅做事件接入与分级
F25调阅审批与水印实时/历史视频调阅须有审批单；单次限时（规划 ≤10 分钟）；播放与下载水印=调阅人账号+时间；全程审计；无单不可调
F26证据保全事故相关片段 WORM 长期保全；普通片段 30～90 天自动到期清理并写销毁日志；哈希存证；MinIO 对象存储
F27MLOps模型注册/版本/灰度、OTA 升级下发（808 0x8108）、效果漂移监控、标注（Label Studio）与再训练闭环
F24～F27 均为设计规划，尚未实现。当前平台只有一个"视频分析"占位任务链路（确定性行为，无真实视觉模型），详见第 8 节。

2. 术语

术语含义
DSMDriver State Monitoring，驾驶员状态监测：疲劳驾驶、接打手机、抽烟、分心、未检测到驾驶员等。
ADASAdvanced Driver Assistance System，高级驾驶辅助：前向碰撞预警 FCW、车道偏离预警 LDW、车距监测、行人碰撞等。
边缘触发识别与抓拍在终端本地完成，仅把结构化事件与少量图片上传平台，区别于"全量视频回传 + 云端识别"。
调阅单一次视频访问的授权凭证：申请人、车辆、通道、起止时刻、用途、时长、审批人；无单不签发播放地址。
WORMWrite Once Read Many，一次写入多次读取的不可篡改存储，用于事故证据长期保全。
证据片段与风险事件关联的短视频（任务书口径：报警前后约 10 秒）或抓拍图集。
OTAOver-The-Air，终端算法包/固件远程升级；808 消息 0x8108 为下发升级包通知。
漂移（模型）真实场景分布变化导致模型指标（误报/漏报）偏离上线基线，需要再训练。

3. 业务场景

驾驶员 · 实时干预
终端本地声光提醒
疲劳/抽烟/前向碰撞风险在终端毫秒级报警并语音提醒司机；事件与抓拍图异步上报平台，不依赖网络通畅。
安全员 · 事件核查
看图判断报警真假
风险事件详情直接展示 1～3 张水印抓拍图，无需调视频即可完成大部分误报/实报确认。
安全主管 · 视频调阅
申请-审批-限时调阅
对争议事件提交调阅申请，审批通过后在浏览器限时查看片段，画面带本人账号与时间水印，全程留痕。
事故处理 · 证据管理
事故片段封存
重大事故关联片段一键转 WORM 保全，超出普通保留期也不销毁，哈希可校验、调取需授权。
算法工程师 · 模型迭代
误报样本闭环
安全员标记的误报图片进入标注集，再训练后新版本灰度下发部分车辆，指标对比后全量。
合规管理员
留存与销毁可审计
普通片段到期自动清理且写销毁日志；人脸等敏感个人信息的调阅、导出全部有记录，满足汽车数据合规要求。

4. 目标业务流程

4.1 主动安全事件闭环（F24）

终端识别
DSM/ADAS 模型在 NPU 推理命中，本地声光提醒驾驶员
边缘抓拍
抓拍 1～3 张 JPEG（叠加车牌/时间/事件类型水印），经苏标 0x64/0x65 附加项或 vps warn 通道上报
平台接入
MOD-014 网关映射 typeId→event_code、级别转换，落 mon.risk_event + traj_warn_media（F07）
分级冷却
复用现有 cep_engine.evaluate_signal 的规则启用/分级/冷却机制，避免同类报警风暴
核查处置
安全员看图确认实报/误报；实报按现有工单链路处置，误报样本回流 F27

4.2 视频调阅闭环（F25/F06）

申请
选择车辆、通道（DSM/ADAS/其他摄像头）、时间范围（实时或历史）、用途、期望时长（≤10 分钟）
审批
按用途分级审批（班长/安全主管）；调阅司机人脸画面按敏感个人信息从严
签发
审批通过后后端向流媒体（F06 ZLMediaKit）签发限时播放凭证，含调阅人水印参数
播放/下载
浏览器 flv.js 播放或片段下载；画面叠账号+时间水印；开始/结束/下载写审计（VIDEO_VIEW/EXPORT）
到期失效
凭证到期即失效，继续观看需重新申请；调阅单归档

6. 业务价值

  • 实时性与成本兼得：边缘识别毫秒级提醒司机，平台只收事件与图片，避免全量视频上云的带宽/存储成本。
  • 隐私合规：无单不调阅、限时、水印、审计四件套，满足《个人信息保护法》《汽车数据安全管理若干规定》对车内人脸/行踪数据的要求。
  • 证据可信：WORM 保全 + 哈希存证 + 销毁日志，事故证据可质证。
  • 模型越用越准：误报样本→标注→再训练→灰度 OTA 的闭环，使误报率、漏报率持续下降。
  • 复用现有风控：平台不重建报警引擎，边缘事件直接进入已上线 CEP 分级/冷却/工单链路。

8. 现状架构（代码实证）

8.1 占位任务链路（processing-service）

POST /api/analysis/video            # X-Service-Token 鉴权，外部服务调用
  └─ db.upsert_video_analysis(RUNNING)
       └─ services/risk_engine.recognize(task)   # ★ 占位实现，非视觉模型
            ├─ channel=DSM → DSM_FATIGUE(0.91) / DSM_DISTRACTION(0.84)
            ├─ channel=ADAS → ADAS_FCW(0.88) / ADAS_LDW(0.82)
            └─ 无 event_code 时：按 taskId 字符和确定性选择（可重复，无随机）
       └─ cep_engine.evaluate_signal(...)         # 复用真实规则引擎：启用判断/分级/冷却/落库
  └─ db.update_video_analysis(SUCCESS, event_count=0|1)
  • 该链路不读取任何视频/图片，无推理、无截图、无片段调阅；它的实际价值是打通了"外部分析任务 → 真实 CEP 风险事件"的通道。
  • 失败路径：识别/评估异常时任务置 FAILED（按代码实际结构，update 终态）。

8.3 Java 侧现状

  • VideoAnalysis 实体 + VideoAnalysisMapper（纯 BaseMapper，无自定义方法）。
  • MonitorController 提供 video-analyses 只读列表（P11 能力），供监控模块查看分析任务记录。
  • 前端无视频播放器、无调阅入口；Monitor.vue 的视频/对讲/拍照按钮为 reservedCommand 预留态。

8.4 前端与交互现状

  • 监控页 Monitor.vue 的"视频 / 对讲 / 拍照"三个按钮当前均为 reservedCommand 预留态：点击仅提示功能建设中，不发任何指令。
  • 视频分析任务仅 P11 只读列表（MonitorController video-analyses），列字段为任务号/车牌/通道/状态/结果摘要，无播放器、无缩略图。
  • P12"视频智能"菜单为占位入口；前端工程未引入 flv.js/hls.js 等播放依赖，也无水印组件。
  • 风险事件/工单详情中的 media_url 为裸链展示（OrderDetailDrawer 等），无鉴权、无水印、无失效控制。

8.5 全量视频为什么不上云（容量基线算例）

以 500 车规模、单车 4 路摄像头（DSM/ADAS/前向/车厢）1080P、平均码率 2Mbps 估算：

方案单车单日数据量500 车单日90 天累计
全量视频持续上传（4 路 ×2Mbps）≈86.4 GB≈43 TB≈3.9 PB
边缘触发图片（20 事件/车/日 ×3 张 ×300KB）≈18 MB≈8.8 GB≈0.8 TB
按需片段（5 次/车/日 ×20 秒 ×512kbps，30 天保留）≈6.4 MB≈3.2 GB（累计 ≈96 GB）—

两条路线相差约四个数量级，叠加 4G 弱网上行与隐私合规，"边缘触发 + 按需调阅"是唯一可持续路线；码率与事件频次为规划估算，需在试点车队实测修正。

9. 目标架构：边缘 + 平台分工

车载终端（DSM/ADAS 摄像头 + NPU）
  │ 终端侧：推理（F24）→ 本地提醒 → 抓拍 1~3 张水印图
  │ 上传：苏标 0x64/0x65 附加项 / jt808_warn_topic + warn_media（经 MOD-014）
  ▼
平台接入层（app/gateway：字典映射/级别转换/附件转存）
  ├─► mon.risk_event（source_id 幂等、规则分级冷却）
  ├─► traj_warn_media → MinIO（F26 桶策略：普通 30~90 天 / WORM 事故桶）
  └─► 样本回流（误报标记 → Label Studio → 训练集）（F27）
平台服务层
  ├─ 调阅服务（F25）：调阅单/审批/限时凭证/水印 → F06 ZLMediaKit → flv.js
  ├─ 证据服务（F26）：保全/哈希/保留策略/销毁日志
  └─ 模型服务（F27）：注册中心/版本/灰度/OTA 0x8108/漂移监控
横切：@AuditLog VIDEO_VIEW/EXPORT（F34）、权限 IAM、合规策略（F37）
职责边缘（终端）平台
视频原始流本地采集、本地循环覆盖缓存（约数十秒～数分钟）不常态接收、不常态存储；仅经 F06 实时播放或 F07 按需取片段
智能识别F24 模型推理、本地告警不做全量视频分析；仅规则分级、去重、冷却、工单
图片/片段事件触发抓拍、片段编码鉴权转存、保全、到期清理、调阅审批
模型按 OTA 包更新本地模型注册、评测、灰度、下发、漂移监控（F27）

9.1 端到端时序（边缘事件 → 平台落库 → 坐席提示）

终端 NPU 命中事件
  ├─ 本地声光提醒（不依赖网络）
  ├─ 抓拍 1~3 张 JPEG（终端侧叠水印）
  └─ 上报：808 苏标附加项(0x64/0x65) + 0x1210/0x1211 文件上传  OR  vps jt808_warn_topic
        ▼
MOD-014 网关接入（近期 app/gateway，终态 module-gateway）
  ├─ typeId → event_code 字典映射；苏标级别反转（见 10.5）
  ├─ 附件下载转存 MinIO（普通桶），计算 SHA-256
  ├─ source_id 幂等去重（终端事件 ID）
  └─ 投递平台事件通道
        ▼
cep_engine.evaluate_signal（复用现状）
  ├─ 规则启用 / 分级 / 冷却判定
  ├─ 落 mon.risk_event + traj_warn_media
  └─ WebSocket 按 deptScope 过滤推送坐席（端到端 ≤3 秒）
        ▼
坐席弹窗 → 看图核查 → 实报派单 / 误报标记（样本回流 F27）

9.2 边缘事件接入契约（平台侧要求，规划）

字段必填说明
event_id是终端生成的事件唯一 ID，作为平台 source_id 幂等键；重投不产生重复事件
terminal_no / plate_no是终端标识与车牌，须与平台档案一致（F36 一致性维度）
event_code是DSM/ADAS 事件码（10.1 目录）；平台不再像占位实现那样"造"事件
level是终端级别；网关按字典反转映射为平台 1/2/3 级
event_start / event_end是开闭环时刻；持续型事件必须配对（10.7）
gps_time / lng / lat / speed / coord_sys是事件时刻位置；coord_sys 标明 WGS-84 或 GCJ-02，由 F09 统一转换
confidence是0～1 置信度；低于阈值仅入样本库，不触发坐席告警（10.6）
images[]是1～3 张，含转存后对象 key、拍摄时刻、图片水印摘要
model_code / model_version否终端模型版本，用于 F27 漂移统计分桶

10.2 事件载荷要求（平台接入契约）

  • 结构化字段：终端标识、车牌、事件 code、开始/结束（开闭环）、级别、gpsTime、位置、速度、置信度。
  • 媒体：每事件 1～3 张 JPEG，分辨率与体积在终端侧限制（规划 ≤1080p、单张 ≤500KB）；图片水印含车牌、时间、事件名。
  • 指标目标：误报率 <5%、漏报率 <3%（以标注集评测为准），指标按车型/光线/天气分桶统计。

10.3 平台侧改造

10.4 验收标准

  1. 仿真/台架注入疲劳、手机、抽烟、FCW、LDW 五类事件，平台 3 秒内出现对应 code 的风险事件且附图可打开。

  3. 事件图片水印信息完整（车牌/时间/事件名），过期 URL 不可访问。
  4. 规则关闭/冷却配置对边缘事件同样生效（复用 CEP，不另建开关）。
  5. 终端模型在标准测试集上误报 <5%、漏报 <3%（评测报告归档）。

10.7 开闭环事件合并规则

  • 持续型事件（疲劳、接打电话等）终端上报 START 与 END；平台按 (车 + code + START 时刻) 匹配，END 更新 risk_event 结束时刻与持续秒数。
  • END 先到 / START 丢失：END 作为孤立点单独落事件并标记 unmatched_end，由网关补偿任务处理。
  • START 后 300 秒无 END：平台超时关闭，事件标记 timeout_closed，不参与持续时长排名。
  • 冷却窗内同类 START 视为同一持续事件刷新，不新建 risk_event。

19. 验收标准

  1. 五类 DSM/ADAS 事件端到端到达风险事件并附图，3 秒及时性、幂等不重复。
  2. 终端侧评测误报 <5%、漏报 <3%，评测报告与线上灰度数据可对照。
  3. 调阅无单 403、限时失效、水印可见、全程有审计（VIDEO_VIEW/EXPORT）。
  4. 普通证据到期删除有销毁日志；WORM 证据管理员不可删改且哈希可校验。
  5. 模型灰度/全量/回滚经 0x8108 全流程可操作，失败终端自动恢复。
  6. 漂移监控可对指定版本告警，并能一键创建标注/再训练任务。
  7. 全量视频不落地：对象存储中仅存在事件图与经审批调阅产生的片段文件（存储审计抽查）。
  8. 现状 /api/analysis/video 占位行为在改造后不再产生"按 taskId 字符造事件"的记录，历史任务可查。
  9. 断网 10 分钟内终端缓存事件与图片，恢复后自动续传，平台无重复、无丢失。
  10. 对象存储容量水位 80%/90% 两级告警；到期清理任务失败自动重试并告警，不残留过期对象超 24 小时。

20.1 播放凭证签名规则（规划）

  • 凭证 = Base64(orderId、vehicleId、channel、exp、nonce) + HMAC-SHA256 签名；签名密钥按环境托管（F37 KMS）。
  • ZLMediaKit on_play 鉴权 hook 回调平台校验，校验失败拒绝出流；nonce 一次性使用，防 URL 转发扩散。
  • 历史回放凭证绑定起止时刻，超出申请时段的 seek 请求拒绝；回放倍率（如支持）不绕过水印渲染。
