MOD-DBD-002 用户与权限（IAM）

文档编号 MOD-DBD-002|版本 v1.0.0|发布日期 2026-10-05| 状态 已上线|功能编号 F33

事实基准：2026-10-05 源代码（backend-java module-iam、platform-common）与初始化 SQL（06-iam-tables.sql）

主要代码锚点：IamUserController / IamRoleController / IamMenuController / AuthController；UserService / RoleService / MenuService / AuthService / DataScopeService / TotpService / PasswordCodec / DbAuthRealm（module-iam）；RequiresPerm / PermAspect / PermissionCache / UserInfo（platform-common）；前端 views/system/UserList.vue、views/system/RoleList.vue、components/ProfileDialog.vue、api/iam.ts

1 功能概述

1.1 模块定位与边界

IAM 模块回答三个问题：你是谁（用户档案与登录策略）、你能点哪些功能（角色 → 菜单/按钮权限点，RBAC）、你能看哪些部门的数据（角色 → 五级数据范围 deptScope，属 ABAC 维度的属性授权）。此外提供登录的 TOTP 二次验证（F33）。

  • 用户管理：用户 CRUD、启停、重置密码、分配角色、解锁、管理员代关 MFA；用户名部分唯一（valid_mark=1），软删。
  • 角色管理：角色 CRUD、菜单/按钮授权（树）、数据范围五选一、自定义范围勾选部门；内置角色受保护。
  • 菜单/权限点：traj.sys_menu 三级模型（1 目录 / 2 菜单 / 3 按钮），种子化维护、不开放界面维护，权限点编码唯一。
  • 登录 MFA（F33）：TOTP（RFC 6238）动态口令，绑定/开关在个人中心，登录时强制二步；管理员可代关闭。

一句话边界：登录动作与令牌签发机制见 MOD-DBD-001；本模块负责"登录策略（锁定/MFA）、用户角色档案、权限点与数据范围"。数据范围算出的部门集合由监控、报警、主数据等业务模块消费，消费方式见各模块文档。

1.3 术语与概念

术语含义
权限点 perm_codesys_menu 上的权限编码（如 iam:user:edit），按钮级权限的载体；uk_sys_menu_perm 部分唯一索引约束。
data_scope角色上的数据范围档位：1 全部 / 2 本企业及以下 / 3 本部门及以下 / 4 仅本部门 / 5 自定义。
deptScope登录主体（UserInfo）上算好的可见部门 ID 集合；null=不限制，空集=不可见任何部门数据。
企业节点 dept_type=1组织树中标记为"企业"的节点；data_scope=2 时沿父链向上找最近的企业节点再取其整棵子树。
内置角色 built_in=1种子角色（SUPER_ADMIN/SAFE_ADMIN/DISPATCHER/FLEET_CAPTAIN），禁删、禁改编码与数据范围。
SUPER_ADMIN超管角色码，后端硬编码绕过一切权限点与数据范围判定（PermAspect、DbAuthRealm）。
UserInfo请求级登录主体：userId/username/realName/deptId/superAdmin/perms/deptScope，由 DbAuthRealm 装载。
TOTPRFC 6238 时间型动态口令，HMAC-SHA1、30 秒步长、6 位数字；密钥 Base32 存储（20 字节随机）。
mfa_pending_secret绑定流程中已生成但未验证确认的密钥；确认后才迁入 mfa_secret 生效。

2 典型场景

安全管理员
新员工开号
在 系统管理 → 用户管理 新增用户：设登录名、初始密码、归属部门、勾角色（如"调度监控员"）。新员工登录后只看到监控与主数据只读菜单，且只看得到本部门数据。
安全管理员
定制角色授权
为"省公司风控专员"建自定义角色：菜单树勾选风险预警分析、处置工单、报警中心（不含主数据维护按钮），数据范围选"自定义部门"并勾选该省组织节点。
高权限用户
绑动态口令加固
在 个人中心 → 动态口令 页获取密钥，用手机身份验证器（扫码 otpauth 二维码）绑定，此后登录必须在密码后再输 6 位动态码。
安全管理员
手机丢失应急
用户手机丢失无法提供动态码，管理员在 用户管理 列表点该用户"关口令"（代关 MFA），用户用密码登录后可重新绑定新手机。

3 操作流程

3.1 用户管理

菜单路径：系统管理 → 用户管理（sys_menu id=901，路由 /system/users，权限点 iam:user:view；维护按钮 id=911，权限点 iam:user:edit）。

筛选查询
顶部按用户名、姓名、状态、部门、角色组合筛选；列表含"锁定"标记（locked_until 未到期即显示）。
新增用户
「新增用户」（v-perm iam:user:edit）→ 抽屉填登录名/初始密码/姓名/部门/角色/状态 → 保存（密码 8~20 位含字母数字）。
行内操作
编辑、分配角色、重置密码、解锁（仅锁定时出现）、启停、关口令（仅已开 MFA 且非 admin）、删除；admin 行隐藏大部分操作。
生效时间
用户/角色变更立即 evict 权限缓存，该用户下一次请求即按新权限判定（无 120 秒等待）。

3.2 角色管理与授权

菜单路径：系统管理 → 角色管理（sys_menu id=902，路由 /system/roles，权限点 iam:role:view；维护按钮 id=912，权限点 iam:role:edit）。

列表与筛选
按角色码/名称关键字、状态筛选；列显示角色码、名称、数据范围 tag、内置标记、用户数。
新建/编辑角色
抽屉填角色码（大写开头 2~40 位）、名称、数据范围单选（内置角色禁用编码与数据范围）、状态、备注。
勾选菜单权限树
el-tree 按 sys_menu 三级展示（目录→菜单→按钮），勾选即授权；目录勾选会级联子节点。
删除限制
内置角色禁删；有用户关联的角色提示"已分配给 N 个用户，请先解除"；删除弹窗注明用户数与自动解除关联。

3.3 自定义数据范围配置

选择"自定义部门"
角色编辑抽屉中数据范围选 5（自定义部门），下方出现部门勾选区。
勾选部门
组织树（traj.traj_dept）勾选可见部门；后端强制至少勾一个，且部门必须存在；关系存 sys_role_dept。
效果
该角色用户的主体 deptScope=勾选部门的并集（不再自动含下级，勾什么看什么）；多角色时与其他角色范围取并集。

3.4 个人开启动态口令（MFA）

打开个人中心
右上角用户名 → 个人中心 → "动态口令"页签（未绑定时显示空态与"获取绑定密钥"）。
获取密钥与二维码
调 GET /api/auth/mfa/setup，后端生成 Base32 密钥存 mfa_pending_secret，返回 otpauth:// URI；前端用 qrcode 库渲染 170px 二维码。
验证器扫码并确认
手机身份验证器扫码（或手输密钥），输入当前 6 位动态码提交 POST /api/auth/mfa/enable；验证通过密钥迁入 mfa_secret、mfa_enabled=1。
此后登录二步
登录页密码通过后进入第二步输 6 位码；顶栏用户名旁出现"动态口令"标记。
关闭
已开启状态下需同时验证登录密码 + 当前动态码才可关闭（POST /api/auth/mfa/disable），密钥一并清除。

3.5 管理员代关闭 MFA / 解锁

  • 代关 MFA：用户管理列表对已开启 MFA 的用户点"关口令"→ PUT /api/iam/users/{id}/mfa/disable，清空 mfa_enabled/secret/pending，无需用户提供任何凭证（属高权操作，带审计）。
  • 解锁：锁定用户行出现"解锁"按钮 → PUT /api/iam/users/{id}/unlock，清零 fail_count 与 locked_until；启用一个停用账号时同样自动清零锁定。

7 核心实现逻辑

7.1 RBAC 模型与权限点判定

模型：用户 → sys_user_role → 角色 → sys_role_menu → 菜单/按钮(perm_code)。判定链：

① 主体装载
DbAuthRealm：超管 perms 给空集（判定端直接放行，不浪费一次权限查询）；非超管 selectPermsByUserId 取全部有效角色的 perm_code 并集。
② AOP 拦截
PermAspect 两个切点：@annotation（方法级优先）与 @within 且方法无注解（类级兜底）。
③ 判定
superAdmin 直接通过；否则按 Logical.OR（任一命中即过）/ AND（全部命中）匹配 perms；失败抛 40301"无操作权限：码1 / 码2"。
④ 前端一致渲染
v-perm 指令与 auth.has() 按 profile 返回的 perms 判定；SUPER_ADMIN 角色前端同样硬编码放行（store/auth.ts）。

7.2 五级数据范围 deptScope 计算

DataScopeService.compute(user, roles) 的语义（多角色取并集；返回 null 表示不限制；返回空集表示什么部门都不可见）：

档位常量计算规则组织树操作
1 全部数据SCOPE_ALL直接 return null（任一角色为全部即整体不限制）—
2 本企业及以下SCOPE_ENTERPRISE沿用户 dept_id 父链向上找最近 dept_type=1 的企业节点，取其整棵子树；链上无企业节点时退化为本部门resolveEnterpriseId（100 步防环）+ subtree BFS
3 本部门及以下SCOPE_DEPT_TREE用户 dept_id 的整棵子树（含自身）subtree BFS
4 仅本部门SCOPE_DEPT_ONLY只含用户 dept_id 本身—
5 自定义SCOPE_CUSTOMsys_role_dept 中该角色勾选的部门 ID 原样并入（不含下级）selectDeptIds(roleId)
  • 组织树一次性 DataScopeDeptMapper.selectAllNodes() 全量加载为内存 Map（id → parentId/deptType/children），子树计算在内存 BFS，不做递归 SQL。
  • 用户无部门（dept_id 为空）时，2/3/4 档贡献为空；5 档只看角色勾选，与用户部门无关。
  • 内置角色范围：DISPATCHER=3（本部门及以下）、FLEET_CAPTAIN=2（本企业及以下）、SAFE_ADMIN/SUPER_ADMIN=1。

7.3 主体装载与权限缓存

每个 /api/* 请求由 JwtAuthFilter 调 PermissionCache.getOrLoad(userId, DbAuthRealm::loadByUserId)：

  • 缓存命中且未过 120 秒 TTL：直接用缓存主体，不查库。
  • 未命中/过期：DbAuthRealm 重查用户 + 角色 + 权限 + deptScope，回写缓存。
  • 账号被停用/删除：loadByUserId 返回 null，缓存清除该键，过滤器按 401 处理。
  • 写操作联动失效：UserService 各写方法 evict(userId)；RoleService 更新/删除 evictAll()（影响所有持有该角色的用户）；AuthService 登录/改密/MFA 操作 evict 自身。

7.5 角色管理与保护规则

  • 内置角色保护：built_in=1 时禁删；更新时不允许修改 roleCode 与 dataScope（前端表单同步禁用这两项）。
  • 删除前置：countActiveUsers(roleId) > 0 拒绝删除（"该角色已分配给 N 个用户，请先解除"）；删除成功后清 role_menu/role_dept/user_role 三类关系并 evictAll。
  • 关系维护：更新采用"全删全建"（deleteByRole 后按请求体重插）；仅 data_scope=5 写 sys_role_dept，其他档位保持空表避免脏数据（代码注释明确）。
  • 校验：dataScope ∈ [1,5]；dataScope=5 必须至少勾一个部门且全部有效；menuIds 必须全部存在于 sys_menu。

7.6 TOTP 二次验证（F33）

实现：TotpService 自实现 RFC 6238（HMAC-SHA1、30 秒步长、6 位、验证时容忍 ±1 个时间步）；密钥为 SecureRandom 20 字节，Base32 编码（32 字符）存储。流程状态机：

setup（未开通）
GET /api/auth/mfa/setup：生成密钥写 mfa_pending_secret（不动正式密钥）；已开通者拒绝"如需更换请先关闭"。返回 secret + otpauth://totp/mydbd:{username}?secret=...&issuer=mydbd。
enable 确认
POST /api/auth/mfa/enable：验证 pending 密钥的动态码 → mfa_enabled=1、mfa_secret=pending、清 pending。无 pending 时报"请先获取绑定密钥"。
登录二步
login 密码通过且 mfa_enabled=1：返回 mfaRequired + 5 分钟 mfa 令牌；/api/auth/mfa/verify 校验 purpose=mfa、账号有效、动态码正确后签发 access。
disable 关闭
本人关闭需密码 + 当前动态码双验证；管理员代关（adminDisableMfa）无凭证要求，用于手机丢失兜底。两者都清空 secret 与 pending。

前端 ProfileDialog 用 qrcode 库把 otpauth URI 渲染为 170px 二维码；Login.vue 第二步仅接受 6 位数字正则。

7.7 前端权限渲染与页面实现

  • 路由级：/system/users、/system/roles 在 router meta.perm 配 iam:user:view / iam:role:view，守卫无权回落。
  • 按钮级：所有维护按钮 v-perm="'iam:user:edit'" / 'iam:role:edit'；UserList 对 admin 行额外隐藏敏感操作。
  • ID 按 string：iam.ts 中 UserListRow.id、UserDetail.id 等雪花 ID 字段全部声明为 string，避免 JS 精度丢失；roleIds: string[]。
  • 角色抽屉：菜单树 el-tree（props label=menuName），数据范围 5 时才展示部门树（label=deptName），保存时 getCheckedKeys() 收集；重置时 dataScope 默认 3。
  • 锁定展示：后端在 UserListVO 上算好 locked（locked_until > now），前端仅锁定时显示"解锁"按钮。

12 技术选型依据

  1. RBAC + 数据范围双维模型：菜单/按钮解决"能不能用"，deptScope 解决"能看哪些"，二者正交；多角色并集是行业通行语义，用户排障时可逐角色还原。
  2. 权限判定 AOP 化、不查库：权限集在请求主体上，PermAspect 纯内存匹配；鉴权 SQL 只在主体装载（且被 120 秒缓存覆盖）时发生，接口热路径零权限查询。
  3. 菜单种子化而非界面维护：权限点与代码强耦合（注解、v-perm、meta.perm 都引用编码），界面可改只会制造失配；SQL 种子幂等随版本演进。
  4. 组织树内存计算：部门量级小，selectAllNodes 一次加载 + BFS 子树，比递归 CTE 简单且躲开数据库方言差异。
  5. TOTP 自实现：RFC 6238 算法简短（HMAC-SHA1 + 动态截断），自实现免引依赖；±1 时间步是标准容差。
  6. pending 密钥两段式绑定：未确认密钥与生效密钥分列（mfa_pending_secret / mfa_secret），绑定中途退出不会破坏既有可用状态。
  7. 写操作主动 evict + 120s TTL 兜底：兼顾"权限变更立即生效"与"防代码漏 evict"两个目标。

15 边界行为与常见问题

改了角色权限，用户多久生效？
立即。RoleService 更新/删除后 evictAll 清空权限缓存，用户下一次请求即按新权限判定；前端菜单需重新进入或刷新后收敛。
多角色时数据范围怎么算？
取并集；任一角色为"全部数据"则整体不限制（deptScope=null）。没有任何角色贡献部门时为空集，即看不到任何部门数据。
"本企业及以下"的企业怎么认定？
沿用户部门的父链向上找最近 dept_type=1 的节点；找不到时退化为本部门。防循环做了 100 步上限。
自定义范围勾选上级部门会含下级吗？
不会。自定义档位只看勾选 ID 本身，不含下级；要含下级请改用"本部门及以下"或把下级也勾上。
为什么内置角色不能改编码和数据范围？
内置角色的编码（如 SUPER_ADMIN）被后端硬编码引用，数据范围是其业务语义的一部分（如 DISPATCHER=3），改动会破坏内置约定，故 RoleService 强制保护。
超管为什么没有 perms 也能过所有接口？
DbAuthRealm 给超管空权限集但置 superAdmin=true，PermAspect 第一行就放行；这是刻意的性能取舍（超管不需要加载权限集）。
绑 MFA 中途关闭页面会怎样？
无影响。密钥还在 pending 列，正式密钥未动；再次进入 setup 会重新生成 pending 密钥覆盖。
mfa 令牌能当登录令牌用吗？
不能。purpose=mfa，过滤器只允许其调 /api/auth/mfa/verify，5 分钟过期。
用户被删除后还能登录吗？
不能。软删后 valid_mark=0，登录查不到该用户（按 valid_mark=1 过滤），已有令牌在主体装载时也会被 401。
菜单能在界面上维护吗？
不能。sys_menu 由 SQL 种子维护（版本化），/api/iam/menus/tree 只读；这是权限点与代码强耦合下的有意设计。
新建用户能立刻登录吗？
能。create 即写库且 valid_mark=1；若给了初始密码符合强度，即可登录（未分配角色则无菜单可见，落入 /monitor 兜底但接口权限仍按空 perms 判定）。
